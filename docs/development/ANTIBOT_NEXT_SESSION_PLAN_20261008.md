## 1. 用户目标与本次范围变更

目标是减少网站能够观察到的 B-A-T 自动化特征，让用户自己的浏览器任务更可靠地运行；保留 browser-use 和现有主业务能力。

- **矛充分调查、依据证据改造**：公开资料暴露出的潜在问题也要审计；当前盾测不到时，补测量或采用独立验证，不能直接跳过。具体产品修改仍要求可定位的问题、最小兼容差异和回归证据。
- **优先不写、少写代码**：不复制成熟组件已有的检测引擎、挑战协议、行为窗口、浏览器控制器、Agent loop 或调度器。允许经复用评估证明必要的薄适配、组件规则/局部扩展、B-A-T 独有契约与产品路径修复、合成场景及脱敏结果关联。少写代码不能作为不修复真实软件缺口的理由。
- **不以“商业系统做不到”为免责理由**：本地可以实现许多相同机制。全球信誉数据、真实账号历史、非公开模型、受信设备证明等外部条件与可实现的软件机制分开结算。

## 4. 检测覆盖与完成状态

[覆盖矩阵](ANTIBOT_COVERAGE_BACKLOG_20261008.md) 是逐项待办事实源，沿用 N/E/B/S/V 的 30 个 ID，可添加子项。该目录不是“30 项全都实现了”，也不是永远不增项的上限。

每项分别记录三个轴，不合成一个模糊“完成”字段：

| 轴 | 允许的状态 |
| --- | --- |
| 盾实现 | 未核实 / 未接入 / 已配置 / 已采集 / 已有判定 / 校准通过 / 部分覆盖 |
| 矛结果 | 未审计 / 待测 / 有差异待修 / 已改待验 / 改善通过 / 无需修改且有证据 / 失败 |
| 范围处置 | 必做待办 / 外部条件待核验 / 具体子项受限 / 用户明确接受的例外 |

“缺少 SDK”“没有现成库”“还未找到数据”“接入麻烦”不能直接归为硬性限制。先记录检索和候选证据，检查配置、公开算法和成熟组件的适配方式；未能闭合的仍是未完成。用户不要求复制大厂规模，但也没有批准把所有难项删除。

涉及非公开训练集、全球信誉、真实平台历史、受信硬件或不可取得的权利时，必须拆开**可实现机制**与**缺少的现实数据/证明**。本地合成历史可以验证规则，不能证明对真实平台的识别效果。例外记录要写缺什么、尝试过什么、可做到哪一步、剩余影响及恢复条件；需要缩小已承诺软件范围时，必须由用户明确决定，不能由开发 agent 默认为豁免。

每项实施前登记目标输入、预期可观察差异、规则版本、异常/正常样本、测量有效性、接受标准和回退标准；不得看到 B-A-T 结果后改标准。确定性规则需要预期样本判定正确；统计模型需要独立数据、样本量、误报/漏报和事先确定的阈值，三轮样本不足以宣称总体准确率。

行为模型须定义样本单位，按用户、会话、设备或时间批次隔离训练、调参与留出验证；同一轨迹、同一会话及其派生片段不能跨组泄漏。分别报告各组人数/设备数/会话数及样本分母、不确定性。单人单设备的多轮只支持该用户和环境；不能把数百个鼠标事件当成数百名独立用户，也不能宣称对一般真人的准确率。

## 5. 盾的分层补齐与复用方向

### 5.1 运行基线及浏览器环境（E、N04、V01/V06）

审计固定 CrowdSec 内置检测、fpscanner 和现有 Brotector 适配；按缺口核验 BotD、CreepJS。保留独立文档或轮次，避免探针相互改变原生对象。明确信号缺失、权限拒绝、异常、超时的状态；不能将库的 `detected=false` 自动视为有效阴性。

### 5.2 网络与协议（N01–N06）

增加受控 HTTPS 入口，在**客户端到第一个 TLS 终止点**观测握手。优先复用 JA4/抓包或边缘组件；HTTP/2、HTTP/3、原始头顺序分别核验能力，不能从规范化后的应用 headers 恢复已丢失数据，也不能测到网关回源连接后当作 Chrome 指纹。

对人工 Chrome、B-A-T 的真实浏览器请求、必要的后台 HTTP 分别测量；保留缓存、连接复用和重定向的影响。浏览器 UA/Cookie 相同不保证网络栈相同；网络指纹不同也不自动等于恶意。不得把通过修改 JA4 字符串当作改变真实握手。

每类网络特征必须映射到有公开依据的判据或关联规则，并验证已知异常、合理正常变化和缺失输入。仅得到 JA4/协议字段属于“已采集”；不能独立判别的特征要引用实际消费它的关联子项及校准证据，不要求把每个不同指纹一票判为 bot。

### 5.3 行为、输入与访问时间窗口（B01–B06）

先复用既有事件和服务端日志；使用 CrowdSec parser/scenario 等成熟窗口与规则机制。采集鼠标/键盘/滚动/焦点/可见性、动作与导航关系；只保留必要摘要，不记录真实输入内容。明确事件序列不变量与统计行为模型的不同证明强度。

对行为模型继续调查公开算法、实现、数据集、许可和跨设备适用性。没有可校准模型时，诚实保留该子项未完成，继续完成可验证规则；不得自造“真人分数”或把采集器说成分类器。

频率覆盖实际请求、并发、重复和失败重试，关联准备、试跑、运行、恢复、账号检查等阶段。小时/天级统计、跨任务连续性和服务重启后的保留分别验收；缩短时间或回放时间戳只证明规则逻辑，不能替代真实时间运行的证据。

计数口径在实验前冻结：动作/命令数、可观测的客户端请求尝试数、网关收到数、源站收到数分别记录；失败在到达网关前的尝试不能从源站日志反推。业务、挑战、探针遥测、静态资源、预加载、重定向和重试分别归类，规则是否计入各类写明，基线与候选保持一致。报告采集覆盖与未知部分，区分产品能主动控制的请求和浏览器自主产生、当前只能观察的流量。源站请求减少若来自前置拒绝，不算访问预算改善；命令数不能代替网络请求数。

### 5.4 会话、关联、挑战与业务（S、V02–V05）

复用 CrowdSec 挑战、签名、PoW 和公开规则接口，验证过期、重复提交、状态丢失、存储隔离以及上游确实承诺的绑定语义。不能由“加密 Cookie”推导任意设备/IP 绑定。

合成账号的跨会话、设备、IP 关联和公开流程规则都纳入范围；不把 S04/S05 整类简单标为“外部”。未知平台模型和真实历史另列限制，不建立新的自研风控平台。蜜罐/隐藏链接复用已有公开实现前先检查无障碍、预加载和普通扫描器的正常反例。

真实账号登录、验证码、访问限制继续走已有人工接管；盾侧可以验证自有挑战和处置协议，但这不授权伪造第三方证明或恢复已停止的平台测试。

### 5.5 组件选择约束

CrowdSec/Hub 和当前 Traefik/bouncer 是已运行基础；BotD、CreepJS、FoxIO JA4、Anubis、BunkerWeb 是按具体缺口评估的候选，不能为了凑组件数量全部安装。Anubis/BunkerWeb 不能仅因名称带反爬就被算作鼠标行为模型。

候选历史固定提交与许可证见 [原选型第 2 节](ANTIBOT_OPEN_SOURCE_ASSESSMENT_20261007.md#2-调研证据与冻结对象)。新选型需重新核对源码和最小样本，不自动升级旧版本；JA4 TLS 与其他 JA4+ 许可分别处理；当前 Bot Detection/bouncer Alpha 风险保留。

## 6. 盾自身验收，先证明题目有效

必须区分三种实验用途并分别记录配置摘要、启用模块、处置方式和实际可达路径：

| 用途 | 前置拦截如何处理 | 能支持的结论 |
| --- | --- | --- |
| 定位/观察 | 优先用固定上游版本已验证的观察/模拟机制；若不支持，则使用明确登记的独立测试入口，仅启用被测模块的原生规则，保留其他层的测量 | 定位单项差异；不算整体放行或反爬通过 |
| 单层强制校准 | 被测模块的真实拒绝/挑战/限流必须生效；其他会遮蔽样本的模块在该独立配置中明确标记为未参与处置 | 证明该层规则与正常反例有效；不能外推到全栈 |
| 最终组合验收 | 所有已纳入组合的模块同时按冻结配置处置，验证正常与异常场景；不加 B-A-T 白名单或放宽规则 | 组合检测与 B-A-T 实际可达业务结果 |

当前网关是 live 且故障默认阻断，不能默认拥有观察模式。若指纹先拒绝，后续行为/会话采集不足必须记“未到达/未测”，不能记“未命中”；先做分层校准、解决前置问题，再补最终组合证据。调查原生配置能力属于 R2，不允许为穿过前置层伪造通行证明、删除历史拒绝，或将不同处置配置下的结果并成一组成功率。

1. 每项至少覆盖已知异常、合理正常反例、输入缺失和错误路径；根据机制另加边界值、组合和版本条件。规则单测、模拟日志、真实浏览器样本分别记账。
2. 人工与自动化的浏览器版本、Profile 模式、网络、页面、检测配置尽量同条件；差异不能消除时说明影响。既有人工数据可用则复用；新环境或新信号缺乏人工样本时不能把自动化样本冒充人工。
3. 只在确认人工样本不能复用且验收确实依赖时，集中安排一次明确操作；不反复开关窗口或临时改测试页。无人时推进独立工作，人工门保留待完成。
4. Cookie 域隔离不等于 IP 桶、账号历史和封禁状态隔离。用上游明确支持的隔离/重置方式处理实验状态，记录重置和暖启动两类实验；不清除个人状态，不用白名单跳过检测。
5. 探针、网关或日志异常不能计为“B-A-T 未被识别”；需要区分引擎判定、实际返回、业务结果和资源结算。分组标签和预期答案不得成为检测依据。
6. 保留上游默认规则基线与新增规则版本；为修正误报而调规则需要独立正常样本和变更理由，双侧按相同配置重测，不能为候选过关删除判据。

## 7. 矛的审计与实施边界

| 产品路径 | 需要查明和处理 | 当前入口（相对仓库根目录） |
| --- | --- | --- |
| 浏览器连接与采集 | 会话归属、额外 attach/订阅、注入、跨 frame/worker、导航后状态 | `apps/api/python/browser_use_runner/task_browser.py`；`vendor/workflow-use/workflows/workflow_use/hybrid/native_event_capture.py`；`vendor/daily-chrome-extension/browserModel.ts` |
| 浏览器/后台网络 | 每种 transport 的来源、UA/Client Hints、Cookie、连接和代理连续性 | `apps/api/python/browser_use_runner/account_http.py`；以 CodeGraph 查清调用范围，不能只见一个文件就全局替换 |
| 会话与身份 | 日常/专属模式、Profile 所有权、登录和挑战状态、恢复 | 已有 browser owner/account/session 模块；先用 CodeGraph 取实际路径 |
| 输入执行 | 坐标、原生输入事件、焦点、键盘/IME/粘贴、滚动、时序与轨迹 | B-U 当前动作与既有事件桥；成熟输入实现优先，不先造随机曲线生成器 |
| 全阶段访问 | 实际网络请求和动作预算、长窗口、取消、去重、重试 | `apps/api/src/task-chain/execution-pacing.ts` 仅为现有固定节点延时入口；不得误作完整流量治理 |
| 响应与挑战 | 200 挑战页、重定向、429、登录/验证、实际任务输出 | 既有结果读取、访问状态和人工接管路径；必要时补局部适配 |

保留 browser-use、现有任务架构与每运行单控制会话；不通过删除记录/验证来降低暴露，不增加普通节点的隐式模型调用，不把 website 名称或实验标签写入公共 runtime。需要改宿主或关键库时先证明公开接口/小补丁无法满足不变量，再重新完成复用评估，不能仅凭“stealth”宣传替换。

每项整改链：公开依据或现场现象 → 有效测量 → 实际源码路径 → 最小差异 → 同规则复核 → 主业务回归 → 回退条件。无差异时结算“该范围无需修改且有证据”；测量不足时结算“待测”，两者不得混用。

## 8. 业务回归与最终完成门

主业务是约束和必要回归范围，重点开发仍在底层控制。保护原生探索和事件采集、读取/点击/输入/导航、动态任务结果、已有准备/发布/普通执行/恢复、人工接管、模型调用审计、单会话归属与 finally 清理。根据实际改动选择最小代表场景；不能重新铺开 UI、编译器或任务链平台建设。

独立复核采用未参与调优的探针或场景；同源库不能伪装成独立检测器。记录首次失败和修正后的结果；不能以“HTTP 200”“动作成功”“总分降低”替代有效检测和业务结果。一般开发授权不允许全量/根级测试；扩大验证先按 AGENTS 说明范围、必要性和成本。

最终交付必须同时包含：可独立启动的盾、B-A-T 底层改造及回退、逐项覆盖/前后对照报告、首败与剩余问题、资源状态和文档更新。RESEARCH 记录复用与证据，ROADMAP 记录阶段与未完成项，PROGRESS 记录实际结果。某行只有采集、某项正常样本缺失或长窗口未跑完，不能在整体报告中隐藏。

整体完成仅在所有可实现的范围内子项通过上述门、应修问题闭合、无新业务回归，且剩余客观限制已明确处理后成立。保留例外和“未知”是报告诚实的要求，不是把未完成自动转换为通过的办法。
