# 专家引导式需求访谈要求

日期：2026-09-11

状态：访谈 Skill 的长期产品要求与维护依据

适用范围：浏览器自动化任务的需求访谈；运行协议与产品阶段边界仍以 [需求对话机制](INTERVIEW_UI.md) 和 [产品流程](PRODUCT_FLOW.md) 为准。

## 1. 目标

本要求面向不熟悉专业术语、不擅长完整表达、只知道大致想做什么的用户。访谈 Agent 应像了解业务的专家一样，先理解用户真正想得到的结果，再按用户当前能回答的程度提供解释、例子、少量有后果差异的方案或暂定建议，逐步形成可审阅、可纠正并足以交给下一阶段的需求。

“相对圆满”不等于穷尽所有问题，也不等于填满固定字段。一次访谈相对圆满，需要同时满足：

1. 用户能从当前表述中认出自己的目标，理解关键建议与未决项，并有明确纠正入口。
2. 会改变最终结果、证据标准、停止点或风险边界的取舍，已经由用户明确表达、明确委托，或以仍待决的形式保留。
3. 草稿中的目标、范围、字段语义、完成标准和建议能够追溯到用户事实、明确决策或标记清楚的暂定假设。
4. 可由抓取计划按需调查取得的入口、页面结构、字段可得性和访问状态没有转嫁给用户，也没有被伪装成已知事实。
5. 信息不完美时，系统可以形成边界明确的探索目标；该目标只用于取得后续决策所需证据，不冒充完整采集许可或正式外部行动授权。

## 2. 非目标

- 不建立市场、币种、用途、来源平台等固定必问清单，也不要求每轮依次经历同一套阶段。
- 不替用户发明用途、偏好、业务范围或风险承诺；专家建议必须说明理由和影响，并允许拒绝或纠正。
- 不在访谈中搜索、打开网页、验证页面事实、设计选择器或生成执行链路；来源取证由抓取计划按需完成。
- 本方法论不另行定义 AI Connect Authoring XML、Question、草稿结构、数据库、UI、抓取计划或执行协议。
- 不把需求草稿确认解释为浏览器操作、支付、提交、发布、删除或其他正式行动授权。
- 不以某个商品、网站或历史案例定义通用规则，也不宣称本文采用的研究已直接证明本产品效果。

## 3. 当前证据与问题界定

### 3.1 真实自然输入的观察

观察来源：2026-09-11 对当前本地正式 Workbench 持久化 `/api/interview` 快照的只读核验。用户任务标识和原始模型事件因隐私边界不写入本文；承载该现场的本地 SQLite 属于 Git 忽略数据，因此本文保留匿名的问答与语义结论，不将其表述为可由仓库独立复跑的 fixture。

一次真实商品采集访谈从宽泛目标开始，用户依次点击了“家用台式”“尽可能完整”“基础信息”。最终草稿在协议、结构和字段层面合法，也保留了型号、品牌、价格、容量、功率及来源关联；但地域市场、来源选择政策、在售范围和“价格”的具体含义仍未形成共同理解。“尽可能完整”被改写为“后续确认来源范围内可发现的全部”，来源总体本身没有可审阅边界。

该观察说明：Question 可回答、草稿结构完整和用户点击推荐项，不足以单独证明需求语义已经充分。每次点击只确认当前问题轴，不能推断用户也确认了未展示的市场、时间、来源或字段口径。

### 3.2 十四案验收的证据边界

现有[十四案验收报告](interview-acceptance-report.md)真实覆盖了模型访谈、Question、可确认草稿、确认和刷新恢复，并逐案进行了人工可接受性审阅。它证明 Skill 能在多种任务中保留用户已经表达的信息、区分部分调查事实和业务要求，并生成可持久化草稿。

其中[案例 1–7 附录](interview-acceptance-cases-01-07.md)的含糊商品案例在第二轮由合成用户主动补充了地域市场、时间范围、来源类型、字段和缺失处理，因此主要证明“已明确语义的保留和成稿”，没有独立证明面对只会点击推荐项的用户时，Agent 能发现所有会改变结果的关键歧义。自动检查也主要覆盖协议、关键用户词、调用次数和持久化；关键歧义、问题覆盖和过早成稿仍依赖人工判断。

因此后续验证应补充语义反例和独立评价指标，而不是改写旧报告或用与 Skill 文案同构的字符串断言制造通过。

## 4. 概念与信息归属

### 4.1 任务模型与用户模型

Agent 每轮同时维护两个工作模型：

- **任务模型**：用户想改变什么或得到什么、结果对象、边界、判断标准、依赖和风险。
- **用户模型**：用户已经知道什么、能否理解当前术语、能否给出具体值、是否希望系统建议、以及对当前结论是否已经形成共同理解。

用户模型只用于调整支持方式，不能变成对能力、身份或意图的臆测。支持强度应随反馈变化：用户表达充分时直接成稿；表达困难时先用具体经验、例子、解释或少量方案降低回答成本。同一必要输入没有取得时，继续换一种问法不等于获得进展；应调整支架、降低表达粒度，或提供延期、显式有限探索等真实处理策略。

### 4.2 四类访谈信息

| 类型 | 定义 | 处理方式 |
| --- | --- | --- |
| 疑问 | 缺失答案会改变结果、证据、停止点或风险，且当前不能安全后置 | 一轮只问当前价值最高的一项；给出 2–3 个有真实后果差异的方向，并允许同面板自由补充 |
| 建议 | 专家基于已知目标提出的可解释方向，尚未被用户接受 | 说明理由、影响和可纠正性；不记为用户事实 |
| 暂定默认 | 可逆、低风险且不改变用户目标的处理方式 | 在草稿中显式标记并随版本审阅；用户纠正后立即替换 |
| 待调查事实 | 需要实际来源或页面才能知道的外部事实 | 写入 discoveryTasks 或现场核验项，由抓取计划按需取证，不要求用户代查 |

若某个“默认”会改变纳入集合、字段真值、证据权威层级、时间或地域边界、正式行动风险，它就是需要共同确认的业务取舍，而不是可静默采用的默认。

### 4.3 来源业务取舍与调查事实

用户需要决定或明确委托的是来源政策，例如适用市场、证据权威层级、是否只接受官方来源、零售信息是否属于结果，以及覆盖目标。系统后续调查的是具体 URL、候选品牌或站点、分类入口、分页方法、访问限制、页面字段可得性和实际枚举终点。

“由系统发现来源”表示把具体候选发现交给系统，不自动表示系统可以替用户决定会改变结果的来源政策。用户明确委托这类取舍时，Agent 应给出有理由、可纠正、边界明确的建议口径，而不是编造实际来源名单。

## 5. 功能要求

### EGI-FR-001 目标优先理解

当输入只有名词、动作或大致愿望时，先帮助用户说明想得到的结果、想解决的问题、一个具体例子或希望改变的状态。不得把“为什么/用途”变成所有任务必问，也不得在用户不知道时替其发明目的。

### EGI-FR-002 自适应引导

每轮根据当前任务和用户模型选择最合适的动作：实质回答、解释术语、复述确认、提出一个疑问、给少量方案、提出暂定建议或直接成稿。不得为了形式固定走完一套阶段或维度；同一必要输入持续未取得时，应调整支架、降低粒度，或转为延期、显式有限探索等真实处理策略，不反复询问信息是否已准备好或已填写。

### EGI-FR-003 高价值疑问排序

对候选缺口做反事实判断：设想 2–3 个合理答案，如果答案不同会改变纳入集合、字段含义、证据标准、完成判断或风险动作，该疑问才具有较高决策价值。优先级通常为：不可逆风险与停止点；结果对象和集合边界；会改变结果的来源与证据政策；字段语义和完成标准。该顺序是比较维度，不是固定问卷。

### EGI-FR-004 可回答的问题

优先询问用户能够依据自身目标、经验或具体例子回答的问题。用户不理解术语时先用普通语言解释差异。每个需要用户回答的 Question 提供 2–3 个彼此有真实后果差异的方向，并保留同面板自由补充。互斥方向使用单选；同一决策轴内可并存的条件使用复选，不得借复选合并不同维度。未知名称、事实或具体值不得被编造成选项，而应由用户在选定方向后补充。用户可以补充、拒绝、选择“不确定”或纠正建议。

### EGI-FR-005 建议与共同确认

推荐项必须说明推荐理由和对结果的实际影响，并先核对它的可行前提；不能以用户掌握或愿意提供尚未表达的信息为推荐前提。未点击的推荐不构成用户决策；点击只确认当前问题明确展示的内容。高影响假设不得藏入全局草稿确认。对用户明确委托的取舍，Agent 可以提出专业建议，但必须保留依据、适用边界和纠正方式。

### EGI-FR-006 模糊语义收窄

遇到“全部”“尽可能完整”“当前”“最新”“价格”等词，不按字面复述即视为完成。只在与当前结果相关时核对其可观察含义，例如目标总体、适用时间、生命周期、数值类型、单位、观察时间或多来源差异。若这些差异会改变结果且用户尚未委托，继续询问；若只是实际页面事实，则交由抓取计划按需调查。

### EGI-FR-007 跨轮继承与矛盾消解

最新明确纠正取代旧值。成稿前应同时核对目标、范围、来源、交付字段、完成标准和默认建议，避免旧对象、旧数量、被拒绝来源或相互矛盾的缺失规则残留。不能只修改用户最后提到的段落。

### EGI-FR-008 成稿停止条件

只有以下条件满足时才输出最终需求草稿：

- 最终结果和对象可辨认；
- 会改变结果的关键业务取舍已明确、已明确委托或被明确保留为探索后回访决策；
- 关键量词、字段和完成条件具有可观察含义；
- 每项重要范围与假设可追溯，跨段落无冲突；
- 剩余外部事实可由抓取计划按需调查取得，不要求用户替系统调查；仍需用户取舍的事项已经明确回访条件，且回访前不执行依赖该取舍的正式行动；
- 权限与正式行动停止点明确。

信息足够时可以首轮成稿。仍有一个高价值疑问时继续提问，不以轮数、字段数或用户连续点击推荐项作为结束依据。

### EGI-FR-009 非完美信息下的探索交接

用户确实不知道、拒绝回答或需要证据后才能决定关键取舍时，不强迫其虚构答案。纯数据采集目标中的入口、页面和字段可得性等外部事实，可以保留在既有结构化 brief 的 `discoveryTasks` 中，由抓取计划按需取证；这不改变最终采集目标。用户若明确接受一个有限对象、字段和终止条件的探索性采集结果，它仍是真正的数据采集任务，可以输出结构化 brief，不因使用“探索”一词而改变类别。只有在尚无可审阅的采集目标、需要先取得信息再决定采集范围且用户未委托该业务取舍时，产物才属于信息检索或混合探索需求：形成当前可保存的通用 Markdown 草稿并明确回访条件，不能伪装成可进入抓取计划的采集 brief。若连安全探索边界也无法确定，则继续保留待决事项，不生成误导性的完成草稿。草稿文字本身不创建新的机器阶段、资格或授权门。

### EGI-FR-010 授权边界

需求确认只确认需求版本。抓取计划启动及其按需来源取证、浏览器访问和任何外部副作用仍使用各自的产品授权门。信息不足时可以提出建议或探索草稿，但不得擅自搜索、操作网页、提交事务或执行正式采集。

## 6. 原则、依据、行为与验收映射

| 原则 | 理论启发 | Skill 行为 | 可观察验收 |
| --- | --- | --- | --- |
| 以目标判断充分性 | T1 目标导向需求工程 | 从用户想得到或改变的结果反推当前缺口；不按字段清单填表 | 同一表面动作、不同目标会得到不同澄清；完整输入可首轮成稿 |
| 引导发现而非代替回答 | T2 苏格拉底式提问 | 获取信息、倾听、复述、综合；给出专业方向并允许补充具体经验和例子 | 不懂术语者得到解释；Agent 不把建议或未知值写成用户事实 |
| 按用户反馈调整支持 | T3 脚手架式辅导 | 同时建模任务与用户；必要输入未取得时调整支架、降低粒度或转换处理策略 | 表达充分者不被重复盘问；表达困难者获得更具体但不诱导的帮助 |
| 权衡询问成本与行动损失 | T4 混合主动界面 | 低价值未知后置，高损失未知阻塞；反复索取无果时提供延期或有限探索 | 不要求用户提供可调查 URL；高风险停止点不被默认化；同一输入不被换措辞重复索取 |
| 优先问会改变后续决策的问题 | T5 基于信息价值的澄清问题排序 | 用答案反事实差异排序，不虚构精确分数 | 关键歧义召回率提升，问题数量不因固定清单膨胀 |
| 建立当前目的所需的共同理解 | T6 沟通 Grounding | 推荐需显式接受且可纠正；每次确认只覆盖已展示内容 | 只点某一推荐项不会让未展示假设进入用户事实 |
| 可追溯、可验证、不过度规定 | T7 技术需求定义 | 标记假设和待调查事实，定义可观察完成条件，不提前写页面实现 | 草稿重要陈述可追溯；未知页面事实由抓取计划按需调查；没有选择器级规定 |

## 7. 典型场景要求

| 用户状态 | 合适行为 |
| --- | --- |
| 不理解术语 | 先用普通语言和结果差异解释，再询问；不考用户术语 |
| 不太能表达 | 给出少量有后果差异的方向，并允许在同一面板补充一个例子、当前困扰或想看到的结果 |
| 不知道用途 | 允许“不确定”；用不同结果的后果帮助识别，不替其编造业务目的 |
| 明确委托系统决定 | 提出有依据、有限定、可纠正的建议政策；具体事实留给调查 |
| 拒绝回答 | 尊重拒绝；说明对结果的影响，可转为安全探索目标或保留待决 |
| 只点击推荐项 | 仅记录该问题轴的选择；推荐不依赖用户尚未表达的掌握或提供意愿；继续检查其他会改变结果的未知 |
| 表达已经充分 | 总结关键边界后直接成稿，不为展示访谈能力多问 |
| 纠正先前选择 | 最新纠正优先，重算整份草稿并清除所有相关旧表述 |
| 多个条件可兼容 | 同一决策轴内用复选允许组合；不同维度分别确认，不包装成一个复选问卷 |

## 8. 访谈与抓取计划的交接

访谈交付业务上可审阅的目标、边界、字段语义、证据政策、完成条件、调查任务和权限边界。抓取计划判断哪些来源事实必须先取得，在同一计划过程中按需产出实际 URL、观察时间、字段可得性、枚举依据、访问状态、覆盖证据和缺口；不需要来源取证的任务直接形成计划，不伪造调查已完成状态。

EGI-FR-008 是 Skill 决定是否生成结构化采集 brief 的行为要求，不是新增的机器级资格门。目标、有限对象、字段和终止条件已可审阅的真实采集任务，可以在 `discoveryTasks` 中保留外部事实核验并正常进入抓取计划，由计划按需取证，即使用户称其为探索。尚无可审阅采集目标、需要先取证再由用户决定业务范围且未明确委托时，输出 `brief=null` 的通用 Markdown 探索需求；当前只能保存和确认，不能进入抓取计划或执行链。文档描述不会创建新的机器能力或授权。计划按需取证若发现需要改变已经确认的业务目标，仍带证据回到访谈形成新版本。

## 9. 验证计划

### 9.1 行为评价

- **关键歧义召回率**：隐藏一个会改变结果的轴，检查 Agent 是否在成稿前识别；不要求固定问句。
- **无关提问率**：统计被问但不同答案不会改变需求或风险的事项。
- **过早成稿率**：关键结果取舍仍未确认或明确委托时生成最终草稿的比例。
- **调查事实转嫁率**：要求用户提供本应由系统调查的 URL、分页、页面字段等情况。
- **共同理解准确性**：推荐未选、仅选择单一问题轴或拒绝回答时，草稿是否只记录实际确认内容。
- **跨轮一致性**：纠正后旧事实残留、跨章节冲突和默认建议冲突的数量。
- **可追溯与可验证性**：重要需求能否归因到用户事实、明确决策或标记假设，完成标准能否由后续证据判断。

评价应使用语义等价和反事实任务，不以固定词、标题、XML 片段或与 Skill 同构的正则命中代替行为判断。建议由不了解预期问题路径的独立评审者审阅结果，并分别记录协议通过、需求质量和下游执行边界。

### 9.2 本次实际验证范围

本次仅更新需求文档与私有访谈 Skill，并执行 Skill 结构校验、相对链接检查、核心协议约束静态核对和 `git diff --check`。不调用真实模型，不重跑十四案，不启动抓取计划、BrowserSkill 或执行，也不把文档评审或独立离线演绎视为生产行为效果已验证。

待后续独立验证的内容包括：弱表达用户的真实多轮体验、单选/复选专业方向与同面板补充的连续使用、关键歧义召回和过早成稿、拒答/不确定时的计划取证与回访、复杂纠正的一致性，以及不同模型与任务类别的稳定性。
