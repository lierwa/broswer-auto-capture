# 开发路线

唯一执行顺序是 A → B → C → D → 组合验收。当前停在 A；不得以 mock、测试数量或受控页面结果跳过实际任务页门。

| 阶段 | 交付 | 进入条件 | 退出条件 |
| --- | --- | --- | --- |
| [A 动作记录](replay-repair/A_ACTION_CONTEXT.md) | 可保存、加载并关联真实动作、命中上下文和结果 | 固定来源校验通过 | 受控场景、实际任务页、变化输入/状态均由正式入口通过 |
| [B 定位与读取](replay-repair/B_DOM_TARGET_READ.md) | 可重新解析的唯一目标及有来源的字段值 | A 通过 | 重建、重排、集合、shadow/frame 与变化数据通过 |
| [C 交互执行](replay-repair/C_INTERACTION_ORDER.md) | 定位、滚动、操作、条件等待和读取按真实后态推进 | B 通过 | 慢响应、分页、遮挡、取消与恢复无重复副作用 |
| [D 显式 b-u 节点](replay-repair/D_EXPLICIT_BU_NODE.md) | 在当前 Browser 会话执行有界局部模型任务 | 会话借用和审计边界核验 | 未进入时零模型；进入时动作、调用、结果及退出状态完整 |
| [组合验收](replay-repair/E_INTEGRATION_ACCEPTANCE.md) | 保存加载、同链换输入和干扰差异下的完整业务结果 | A–D 各自通过 | 代表任务及第二类任务均完成，普通复跑只在显式节点调用模型 |

当前动作：

1. 执行无浏览器 provider 传输门。
2. 传输通过后重跑实际任务页 A。
3. 使用变化输入或页面状态复验 A。
4. A 完成后进入 B。

任何阶段失败都停在所属模块修复；不重新探索整项任务来掩盖局部合同缺口。
