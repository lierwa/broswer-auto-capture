## 1. 这次替换什么

此前整改仍围绕“最终字段 → DOM 字段方法 → 拼装最终结果”补缺口，未解决采集和加工职责混合。继续补 required、selector 或提示不能作为本轮主方案。

本轮目标：需求对话确认业务任务及最终交付；准备期由 B-U 探索实际页面、动作、区域、分支和重复方法；需要采集时整体保存指定页面/区域内容；B-A-T 持续在线编译并以正式执行器验证和复跑。数据清洗本身可以是另一项自动化任务，具体清洗功能、处理节点及其验收不在本轮实施范围。先打通业务主流程，再处理展示。

直接复用成熟开源能力是实施约束：优先使用已锁定的 B-U 内容取得与转换接口；局部缺口通过 Crawl4AI 等成熟组件的公开 API 补齐。B-A-T 只写任务范围、值绑定、来源事实、产物持久化和复跑适配，不手写另一套抓取器、DOM 解析器、Markdown 转换器、下载引擎或 Agent loop。存在局部缺口时先适配/扩展成熟组件，不以“接入麻烦”转向自研。

最高边界仍遵循 [TASK_CHAIN_ARCHITECTURE.md](TASK_CHAIN_ARCHITECTURE.md)。准备期允许模型探索；正式复跑的模型调用只来自已确认计划中的显式 llm 节点。LangGraph 继续承担图推进、循环、取消，不新增 Agent loop 或第二套调度器。

## 3. 最终输出怎样确认

业务交付必须区分下列需求；它们可以组合，不为每一种文件格式创建一套运行引擎。

| 交付需求 | 对话必须确认 | 完成依据 |
| --- | --- | --- |
| 操作完成 | 要完成的动作、目标状态、风险及授权点 | 合法控制流完成；必要的目标状态来自真实动作/观察 |
| 结构数据 | 单项/集合、用户明确字段、顺序数量、缺失与不足处理 | 实际结果符合已确认合同；不能用最终字段反推范围采集策略 |
| 页面/区域原始内容 | 哪些页面或区域、文字/表格/图片范围、数量及交付形式 | 目标范围内容与要求的附件实际保存，来源和覆盖事实可查 |
| 内容或报告 | 保留原内容还是明确要求总结/比较/整理，来源引用要求 | 原内容产物实际存在；报告生成按已有显式能力另行表达，不给普通采集暗加加工 |
| 文件资产 | 获取已有文件还是生成文件，内容、格式和交付位置 | 文件确实保存且可读取，不用下载按钮点击代替文件取得 |
| 可继续操作页面 | 用户结束后要继续做什么、是否保留实际页面 | 本次 owner 的活页面交接已确认，失效不能报为仍可用 |

界面呈现、文件格式和活页面约定与业务数据形状分别表达。底层优先复用 ResultSpec.execution/data、TaskOutput.value/artifact 和 browserHandoff；扩展交付元数据只补它们无法表达的真实不变量，先验证再冻结协议。

用户只要操作完成时，不强迫提供字段；要原始内容时，确认范围及原始内容交付；要报告/文件时，不强迫伪装成一行数据；要页面与数据时，分别核验后组合交付。这里记录交付意图边界，不要求本轮新增所有报告/文件生成能力。已实现范围如实交接；尚未支持的交付在确认/准备入口明确说明，不能悄悄改成字段表或追加清洗来假装支持。

## 4. 字段从哪里来

- 用户明确要求的字段：保存其原话、语义和确认事实，禁止宿主按网站名加字段。
- 模型建议的字段：只是候选，需要业务依据；凡改变结果的重要取舍，进入 Question Panel 确认，不能因为模型写进草案就当成已知事实。
- 用户说“抓商品配置/页面中的全部属性”时：确认这些内容所在的页面/区域以及图文范围，整体保存区域内容。不能解释为逐个找到某些配置字段，也不要求访谈 LLM 猜字段或采集 LLM 为每个参数填写 selector。
- 领域模板或搜索资料：只能提供有来源的建议，不能证明现场页面具有这些字段。领域字段是版本化任务数据，不写入公共平台类型。
- 现场发现的新业务歧义：带证据回需求对话。区域定位、加载方式和字段实际标签属于准备调查，不逐项要求用户填写技术参数。

只有任务确实要求具体字段时才讨论字段来源和缺失规则。导航、筛选、分支所需的链接/身份/状态，仍使用现有真实读取能力；不能因解除最终字段门禁而删掉必要运行输入。区域采集的合同是范围及内容，不是配置参数清单。缺失、无法读取、不适用分别保留事实，不新增通用语义 judge。

需求对话交接的是目标、步骤和依赖、输入、来源、采集范围、最终交付与业务边界；不交接 selector、DOM 路径、节点 ID、执行预算。会改变用户结果的业务歧义必须关闭；定位、加载和页面实际内容留给准备研究。

## 5. 一条主流程与各阶段责任

```text
需求确认：业务任务 + 最终交付 + 来源/范围/风险
    → 首次生成前显示本任务实际浏览器模式，可直接更换
    → 同一确认草案的准备投影：业务步骤及数据/控制依赖
    → B-U 代表探索与在线编译：真实动作、观察、条件和重复方法
      若需要采集：进入目标 → 打开/加载目标范围 → 整体采集 → 保存产物
      若为纯操作：沿动作、必要读取、分支及循环完成目标
    → 真实 sample/verification：按候选任务图执行
    → 发布
    → 普通执行器复跑 → 业务结果与资源清理分别落库
```

准备计划不得仅凭最终结果是数组就决定真实流程。重复 N 个输入应调用同一参数化链路 N 次；第一次调查原生 Agent 可以观察循环及必要转移，正式执行由已发布图处理。未观察到的业务分支不能猜测为已验证，明确保留未覆盖路径与准入缺口。

B-U 得到自然语言业务目标、当前步骤上下文、真实输入和原生页面观察；它决定导航、点击、展开、滚动和任务相关区域。它不负责逐个填写最终业务字段选择器，也不编写 IR、清洗规则、样例或节点编号。捕获与编译继续在线发生，不能通过取消在线节点生成来规避问题。

普通编译缺口记录并阻止发布，继续原生探索；来源无法可靠保存、文档/会话身份失配、越权等硬边界才停止并保留原因。登录、验证码由用户处理，不能绕过。已有页面访问和敏感数据边界继续保留。

纯编译修复只消费已保存的原来源，不自动重开浏览器或重派已观察动作；不能把编译错误变成再次浏览器操作来凑齐证据。

## 6. 整页/区域内容采集的最小实现

业务范围可以是整页、一个或多个内容区域。首次探索的模型根据业务目标和真实页面决定进入哪个页面、切换哪个 tab、展开或滚动到哪里，并选择区域；宿主用已有定位能力形成可复跑的范围绑定。模型不负责枚举配置字段、返回完整 DOM、填写节点 ID 或生成另一份业务计划。

一个范围采集动作整体处理选定内容；采集多个条目时，导航入口来自本次运行的真实集合，普通执行器复用同一条参数化详情链路。分支和循环复用现有 IR、证据适配和 LangGraph，不手写调度，不为每个条目重新开 Agent。

| 保存内容 | 复用及完成依据 |
| --- | --- |
| 原页面/条目身份与采集范围 | 复用当前 owner、文档/目标身份、来源证据与 ValueBinding；关联本次运行输入 |
| 区域 HTML、文本及表格 | 复用成熟内容序列化/采集 API；原始区域内容作为来源，Markdown 只作阅读副本 |
| 要求保留的图像/资源 | 复用成熟下载/浏览器资源接口，写现有受控 Artifact 存储；记录实际文件、原 URL 和来源区域 |
| 加载与覆盖 | 复用原生展开、滚动、分页动作及停止条件；记录实际覆盖、未加载、未支持和预算不足 |

采集前通过既有 B-U 观察/DOM API 取得最后一次导航、tab 切换、展开或加载之后的当前内容，并核验 owner、target/document 与范围对应。不能把非空缓存当成当前观察，尤其正式执行没有原生 Agent 每步观察循环保障。方法新鲜度无法证明时保留缺口并阻止发布；来源身份失配或当前来源不能可靠保存按硬边界停止，不新增缓存框架。

精确区域定位失败必须留下定位缺口，不能自动改抓整页或相邻推荐区冒充命中。库的 cleaned_html、fit_markdown、图片评分和长度过滤是派生策略，不能成为丢弃原始正文、短参数、表格或目标图片的依据。不能仅保存 HTML 中的 img 链接就宣布图文已落盘；要求原图时核验实际字节。图片里是什么参数不在采集阶段做字段解释或 OCR 清洗。

只采集授权范围。使用当前 execution 的实际浏览器会话，不另开抓取浏览器重访已登录页面；已有会话取得的内容可交给 Crawl4AI 的纯 HTML 输入接口处理。登录、验证码、受限访问由用户处理；Cookie、Profile 和敏感原文不进入 Git、测试快照或普通日志。公开 API 暂不能覆盖要求的附件或页面形态时，记录具体缺口并阻止该方法发布，先适配成熟能力，不静默缩小交付。

采集节点成功以范围绑定成立、规定内容保存及产物可读为依据；正式链路仍按合法控制流和节点/合同/运行时错误结束，不追加全局 LLM judge。动作失败、来源取得失败、编译缺口、模型协议错误与资源清理失败分别归因，保留首次失败及结束原因，不能用一个“生成未完成”覆盖事实。

## 7. 旧逻辑退出清单

| 旧逻辑 | 处理 | 必须保留的有效能力 |
| --- | --- | --- |
| 草案仅接受两种交付、两种数据形状并强制字段 | 替换新任务生成入口的限制；旧草案保留读取兼容 | 已确认业务意图、类型边界、来源引用校验 |
| recordSteps 按数组 schema 固定拆成发现/补字段 | 移除其作为通用规划策略的调用；让确认的业务计划及真实调查决定步骤 | each、稳定来源身份、参数化单项执行 |
| 最终业务 schema 直接限制范围采集字段和转换 | 从页面/区域采集路径解除，以范围及原始产物交付；不追加清洗填字段 | 必要导航/控制流读取、用户明确字段读取及边界 Zod/JSON schema 校验 |
| 数据任务一律禁用原生 extract | 首次探索确需 extract 时保留原生语义和调用审计；完整工具不直接物化为复跑 llm | 只恢复 extract 不构成原始采集闭环；正式语义步骤先取得普通观察输入，再调用既有显式 llm |
| done 成功必须拼装最终字段 readRefs | 退出这个通用完成前置条件，按当前业务步骤交付完成事实/产物 | 原生结束与成功事实、来源准入、真实结果关联 |
| 点击前以缺少编译集合证据拒绝动作 | 将普通编译准入检查移回编译；不把目标绑定缺口当原生业务错误 | 授权、文档/会话身份、真实选择规则、错误来源保存 |
| 同名字段按代表项存在性猜继承或强迫每份详情提供全部后备 | 采集内容绑定本次输入和产物；必要运行字段按真实合同传递 | 不从第一条样本推断所有条目必有；逐项运行身份一致，必要输入缺失如实失败 |
| 只返回第一个失败动作、原异常仅有引用 | 补齐安全且可归因的阶段诊断，分别保留首次失败和结束原因 | 敏感数据不得进入日志；清理错误不覆盖业务错误 |
| 围绕旧强制字段路径的 prompts、死调用、示例和测试 | 在新路径通过后按调用范围删除/改写，逐项登记退出状态 | 保留保护真实协议、身份、控制流与历史读取的不变量测试 |

清理顺序：先列调用及历史消费者 → 提供同一入口的新实现 → 定点验证 → 移除旧生成分支、旧指令和死逻辑 → 删除仅支撑旧假设的测试/文档声明。不得为了过旧测试保留新任务的隐式旧后备，不新增“旧/新模式”让用户选择。

旧 Requirement、Source、Release、TaskRun、执行事实不改写；已发布合法节点继续由相同公共运行器消费。历史读取/有效低层能力不是待删除的错误方案，不把“清干净”解释成删除用户历史或另建双运行引擎。旧整改报告保留首败证据，但其逐字段继承方向不再作为本轮主实施依据。

## 8. 本任务浏览器、并行与清理

全局提供默认浏览器模式，任务可单独覆盖。首次生成前直接显示解析后的实际模式，用户可选择日常 Chrome、专属浏览器显示窗口、专属浏览器后台运行；不增加“跟随全局”第四个选项，不让用户理解继承状态。仅显示默认值不自动写入任务覆盖；用户选择真实模式后保存任务选择。每次准备/试跑/正式运行解析一次并冻结本次模式，运行途中全局或任务设置变化不改变现有会话。

一个 execution 一个实际控制会话，各任务拥有独立 owner、lease、target/session 或专属 Profile，允许并行。共享日常 Chrome 进程不等于共享受控 tab；不能并发控制同一个目标，也不能因为一个旧任务清理未确认就阻塞所有新任务。只对实际资源冲突给出具体原因。

成功、失败、取消在 finally 释放本次控制资源；手动/自动关窗、目标消失、连接断开、进程退出和上次 OS 启动变化沿现有生命周期核验该 owner。确定已关闭时结束占用；仅断连而关闭未证实时保留待核验事实，不误关其它任务或用户窗口。关机后重启必须核验并使过期占用失效，不能要求用户先清理旧任务才能创建新任务。

页面交付只有用户明确要继续使用且现场活页面存在时成立；保留窗口不等于仍保留自动化控制占用。业务 TaskRun 结果与 execution 清理状态独立，cleanup_required 不触发模型修复或覆盖原失败。复用 [PARALLEL_BROWSER_LIFECYCLE_20261005.md](PARALLEL_BROWSER_LIFECYCLE_20261005.md) 的现有 owner/lease/关闭核验；已通过及尚未完成的真实场景沿原记录保留，本轮不重写清理框架。

## 9. Product Alignment 与复用门

Product Alignment:
- natural-language task: 采集任务相关页面/区域内容；也覆盖文档页面采集及无数据输出的页面/表单操作。
- reusable chain boundary: 参数化浏览器动作、必要读取、条件/循环及按需范围采集组成同一任务图；重复调用一条链。
- runtime inputs: 用户输入、动态来源集合、单项身份、采集产物引用。
- dynamic task outputs: 状态、结构数据、内容/文件、原页面交接及组合。
- generic platform capability used: 既有 Browser/Tools、成熟内容采集 API、定位和 Artifact、ValueBinding/ResultBinding、LangGraph。
- replay model calls: 普通采集/动作节点 0；仅已确认的显式 llm 节点允许调用并审计，本轮不新增清洗步骤。
- site/task-specific code added: no。

Reuse Assessment:
- capability: 浏览器探索、整页/区域内容取得、附件持久化、控制流和交付。
- existing implementation in repository: browser-use 0.13.8、markdownify 1.2.2、受管 workflow-use 适配、Artifact 引用、Pi AgentSession、LangGraph StateGraph。
- mature candidates and pinned versions: 优先现有 browser-use 0.13.8/markdownify 1.2.2；候选补充 Crawl4AI v0.9.4，源码已核验，未安装/冻结其接入。
- selected implementation: 原生 B-U 和现有运行器；先直接调用已有内容 API，明确局部缺口后使用 Crawl4AI 公开 API 补足，不同时部署两套浏览器控制链。
- reused public surface: B-U HTMLSerializer.serialize、extract_clean_markdown/convert_html_to_markdown、原生 Tools 注册/回调及历史结果；Crawl4AI LXMLWebScrapingStrategy.scrap(url, html) 和 DefaultMarkdownGenerator.generate_markdown(input_html) 为已核验的无浏览器输入接口。
- B-A-T-owned adapter and remaining gap: 任务范围/动态输入到现有定位和公开采集 API 的绑定、来源与产物持久化、正式复跑和旧生成路径退出；真实原图/加载覆盖尚待最小样本证明。
- license/runtime/platform fit: B-U 为 MIT，现有 Python 桥及依赖已在 Windows 使用；候选 Crawl4AI 要求 Python >=3.10，其许可证含 Apache-2.0 与额外署名要求。区域/附件接入的 Windows 行为尚未验收。
- browser/runtime/state ownership conflicts: 单次 execution 一个实际控制会话；并行任务 owner 独立，复用现有 lease 清理。
- replay model calls: 内容序列化/格式转换无需 LLM；完整原生 extract 仅用于首次探索并审计，不直接物化为复跑 llm 节点。已确认语义步骤先由普通观察/采集形成一个输入，再调用既有显式 llm；prompt 随版本冻结，最多调用一次并返回类型化结果，不拥有 Browser/Tools/文件系统。本轮不为采集新增此类步骤。
- rejected candidates and evidence: 尚未否决任一成熟候选；不得因局部不适配就自研等价采集、解析或下载能力，先记录 API/运行证据并适配/扩展。
- focused validation: P0 只核验一份包含文本、表格和图片的真实范围，包含一次展开/内容变更后取得当前内容，并以另一运行输入证明绑定复用；以源码和最小行为证据冻结具体接法，记录 RESEARCH。

源码、候选行为与接入缺口详见 RESEARCH 的“2026-10-05 页面/区域采集直接复用”记录。a-d 的 captureEvent 保存完整响应 HTML 或原始附件字节、ZOL Provider 下载图片的做法可参考；其站点路由与内容信号不是 B-A-T 公共能力，不搬入平台。源码能力存在不表示本项目范围采集或原任务已经通过。

## 10. 最小阶段与验收

| 阶段 | 范围和产物 | 最小验收 / 退出条件 |
| --- | --- | --- |
| P0 契约与直接复用 | 固定业务范围与原始产物边界，核对公开 API 及旧调用清单 | 文档对抗审查；一份真实区域/附件样本包含展开或内容变更后的当前观察，证实接法，记录 RESEARCH 后冻结，不先写自研采集器 |
| P1 原生探索与采集 | 接入原生能力，任务相关区域产物，普通缺口继续探索，安全诊断 | B-U 可推进真实代表任务；图文和来源取得；普通编译缺口不拦业务，身份/越权错误仍停止 |
| P2 访谈及计划交接 | 业务依赖、交付意图、范围与必要输入，替换固定数组拆分；直显实际浏览器模式 | 已实现的执行/原始内容交付同一入口可用；不猜配置字段，不显示第四个浏览器选项，不强制每个任务采集 |
| P3 正式闭环 | 动态条目/范围绑定、循环/分支、产物持久化、正式验证/发布/复跑 | 原京东范围图文采集及非采集操作分别有真实证据；换输入复用，普通节点 0 模型；不开发清洗框架 |
| P4 清理及审查 | 删除旧生成路径、旧指令/死代码，更新引用和当前证据；开发验证后对抗 review | 同一正式入口的新任务可运行；旧合法版本可读/运行；旧错误路径没有隐式后备；审查发现闭合 |

最小业务样本：①原京东任务按确认规则选条目、进入详情、整体保存目标配置区域图文，不预设参数字段；②一个不要求采集或数据字段的浏览器操作。对所改不变量定点覆盖动态单项变化、空/不足集合、实际分支路由、原图落盘/加载不足和会话失效；不能用固定 SKU 或站点特例通过。浏览器选择和清理优先沿用已有验证，仅新增改动/未闭合场景扩大范围，不重复跑整组测试。

验收通过必须来自生产入口生成并持久化的链路，随后由正式执行器执行，不能注入最终 source/chain，也不能边跑边加站点特例。控制样本用于核验不变量，原京东结果单独记录。相同版本普通节点模型调用为 0；首次探索及已确认显式 llm 的调用用途单列。本轮文档同步后启动一个对抗 subagent 审查文档；后续开发验证完成再做代码审查，重点是成熟能力复用、字段门禁退出、动态身份、循环/分支和资源归属。

只运行所属范围最小现有验证；阶段内不重复无变化验证，不跑根级/全量。第一失败、修复后结果、未覆盖路径和剩余阻断分别写入 PROGRESS。普通测试通过不得换算成主业务完成。

审查补充边界：逐项执行必须按原值传递根参数，来源读取不得让模型为参数找页面字段；当前内容与资源必须同一文档（同 URL 重载也要拒绝混合产物）。CSS 背景及伪元素原图沿成熟解析器和现有 CDP 保存。一个内容交付步骤应选择一个共同区域；多个不同范围不得隐式只交最后一处。未支持的多区域聚合必须暴露合同缺口而非静默成功。
来源调查补充：入口选择是准备任务的一部分，不能预设所有可点击任务项都有 a[href] 或禁止研究代表条目的导航。先保留原生调查能力，再证明实际 URL 的读取/绑定来源；无法证明的普通编译缺口不得由猜造入口填补。来源只是参数化入口，不能把最终配置字段反灌来源步骤。
