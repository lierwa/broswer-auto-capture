# 平台账号管理重建：复用、交互和跨浏览器会话

2026-10-03。本文件取代旧方案的产品入口和默认模型方法生产路线。文档对抗审查修订后通过，D1–D4 已实施并完成所属受控验证；D5 修订/最终证据以 [交付记录](BROWSER_ACCOUNT_MANAGEMENT_DELIVERY_20261003.md) 为准。旧完成结论被用户真实复验否定，历史失败与证据保留。

## 1. 用户实际要什么

用户要管理主流网站账号，直接利用日常 Chrome 已有登录，或在专属浏览器登录；两边统一显示，必要时把指定网站的登录态迁移到另一边。平台、网址由平台目录或当前页自动取得，不要求填写技术资料。检查不能默认启动模型探索。

复用两个参考项目的现有检查能力：MediaCrawler 7个平台，social-auto-upload 11个平台，重合5个，共13个平台。复用来源代码，B-A-T 仅适配原浏览器/Profile/owner、结果、持久化和产品操作。用户已说明为学习用途；保留各自许可证和原作者声明。

现状失败已证实：私人 B站尝试2次模型调用后 click 失败，检查链未形成，账号身份未取得；界面隐藏错误，焦点操作又覆盖了维护原因。目录条目已软删除，维护窗口仍指向原条目。不能以受控样本站通过替代实际平台可用，也不能以打开成功代替登录成功。

Product Alignment:
- natural-language task: 使用网站已有账号查询资料、维护后台内容，并在日常/专属浏览器之间复用指定网站会话。
- reusable chain boundary: 固定平台检查策略在指定稳定浏览器身份上运行；指定站点认证状态从源身份传到目标身份后独立核验。
- runtime inputs: BrowserIdentity、版本化平台/策略、原 owner/lease、源/目标身份及目标覆盖确认。
- dynamic task outputs: 当前登录状态、可取得的身份、每次检查和迁移结果、目标核验与资源清理结论。
- generic platform capability used: 原浏览器连接、Playwright/CDP公开接口、TaskChain/LangGraph、ProductStore/SQLite、Radix。
- replay model calls: 0；账号入口删除默认研究与自动模型后备。
- site/task-specific code added: no（站点事实属于导入的版本化平台数据和保留来源的参考模块，不写公共runtime分支）。

## 2. 通用性的具体含义

一份平台目录、一套账号结果合同、一套检查/维护/迁移命令、一份持久事实库，日常和专属共用。平台目录可扩展，不在公共Zod合同增加平台枚举；域名、检查函数、接口、页面判据和读取字段归固定版本的平台数据。使用原组件执行，不另造驱动、图调度器或检查DSL。

平台账号与浏览器会话分别展示。只有经平台实际确认的稳定UID才能把两边归为同一账号；姓名相同、Cookie存在、同一个目录标签都不能合并。没有稳定UID的条目按会话分别展示，保留人工绑定来源但不宣称身份相同。

日常 Chrome 与专属 Profile 分开；专属 visible/headless 共用。统一列表不修改任何认证状态。检查/登录继续在对应原Profile上；用户选择“用此浏览器”明确保存现有全局下一次运行浏览器偏好，当前任务继续原绑定，不暗中迁移。运行设置摘要显示选中的浏览器，不能显示账号已选却仍使用另一Profile。

### 2.1 登录与身份不是同一个结果

固定结果应表达 `authenticated / unauthenticated / inconclusive`，另有 `identityConfirmed` 和可空的脱敏身份。平台给出有效登录但未返回用户名时，可以显示“已登录 · 未取得账号名”；不能为了缺用户名把登录检查判失败。仅Cookie/本地标记属于线索，显示“有登录线索 · 尚未核验”，不是authenticated。

明确未登录响应与网络/挑战/页面变化分别建模。依赖的boolean不直接等于产品事实：必须同时保存实际依据类型、响应/页面确认、错误和来源版本，异常返回true、只有未发现登录按钮、只有Cookie存在均降为inconclusive。保留上次身份与时间，不用旧成功覆盖当前未知。

## 4. 跨浏览器打通

产品提供两个方向：日常→专属、专属→日常。用户选定平台和源/目标后才取得该网站认证材料；不自动扫描私人所有Cookie。不复制Chrome Profile，不操作全局Chrome账号同步。

迁移步骤：
1. 确认源绑定和平台检查结果；明确未登录则拒绝，网络/挑战/未知则提示处理，不能按旧成功迁移。
2. 核验目标当前平台账号。若相同UID可提示已可用；不同账号或无法确认，必须展示“替换目标网站会话”的明确确认。未知不当作空白。
3. 顺序借用源、释放控制连接、借用目标，一个产品操作只有一个实际控制会话；窗口保留不等于并发控制。
4. 使用成熟认证状态接口，按平台目录精确域名/origin/存储范围捕获Cookie、localStorage及必要IndexedDB；不得捕获全Profile再把无关秘密发到host。自定义平台不默认允许父域所有站点。
5. 源材料仅在内存传递并按批准 key 增量装载到目标；原 Context 禁止 `set_storage_state`、无范围 `storage_state`、全量 `clear_cookies`。Cookie key 包括 domain/path/name/partition 与原属性；只删除/写入获准 key，localStorage 只操作获准 origin/key。IndexedDB 必须由已有成熟公开 API 证明能够增量处理；桥接不支持则明确阻止该平台迁移，不全量替换兜底。普通DB与日志只存引用、版本、阶段与投影结论。
6. 当前版本只有 B站、微博、知乎范围允许迁移；源必须本次登录且有稳定UID，目标未知则拒绝准备。目标独立检查且UID匹配才显示“已共享”。无稳定身份的平台只支持检查/选择源浏览器/在目标登录，不尝试同账号迁移。
7. 安装或验证失败时，用该站点迁移前快照恢复目标受影响范围并独立核验恢复；恢复不确定则保存“目标会话待处理”，不能把失败覆盖成成功。

迁移不是持续双向同步。平台可能绑定设备或要求验证；这时给用户去目标网站登录的入口，并保存真实迁移失败。来源账号与源标签保留，取消在写入前直接停止；写入后取消必须结束验证或回滚并记录不确定性。服务重启时未完成迁移保留待核验，不自动重试写Cookie。

迁移按钮在没有目标写入能力/源授权/实际所有权时给出具体原因，不自动授权个人扩展。个人Profile的授权、覆盖确认和验证码由本人完成；隔离测试Profile可自动验收。

### 4.1 范围与一次性确认

目录的每个版本必须声明 Cookie 域、必要认证 origin、允许存储 key、共享认证域组、关联影响和迁移能力。网址匹配不自动批准父域 Cookie。百度/Google/支付宝等共享认证的实际依赖需样本核验；不能明确完整范围的版本只允许检查/使用源浏览器/在目标登录，拒绝迁移。确认视图逐项显示实际认证域和已知关联服务，不声称共享父域 Cookie 仍只影响一个网站。受控验收同时含独立域与共享父域两类样本，批准范围外 key 不读取也不写入。

准备迁移生成持久 requestId 和一次性确认引用，绑定源/目标稳定 Profile、授权 binding、平台及范围版本、新鲜源/目标检查结果、原窗口ID和目标认证状态摘要，2分钟过期。摘要由随机秘密 HMAC 产生，不向客户端返回认证材料；secret仅内存，重启后旧确认失效。写入前重新核验源和目标摘要、Profile及授权；任一变化必须重新展示确认。源没有稳定UID或目标本次未知时拒绝准备；不靠额外确认绕过身份缺口。

准备检查取得原产品操作门，源/目标读取后释放控制连接，保存pending确认。等待确认没有控制器，但两边保留的账号维护 owner 继续阻止正式运行，以免抢用现场。确认提交再取得整操作门并重核验，源断开/目标连接之间不释放。正式运行、维护、检查、删除沿原占用判断，不增加调度器。重复 requestId 返回原事实，取消后迟到结果不能覆盖已结束运行。

### 4.2 目标回滚与重启

已有 ProviderCredentialStore 经固定包源码核验仅 JSON/文件锁，不是加密存储，不能用于认证回滚材料。Windows 采用操作系统 DPAPI `CryptProtectData/CryptUnprotectData` 的薄适配，禁止自造加密。写入前先存目标获准范围的最小快照至 data 下忽略目录：DPAPI 当前用户加密、当前用户文件ACL、格式/范围版本及校验摘要、原requestId，以及独立恢复HMAC key。恢复key仅存在加密快照，不依赖重启后丢失的确认secret。源材料不持久化。DB先持久保存 rollback_ready，再保存 write_started，确认快照存在且能解密后才写入；每次目标写入后的摘要以恢复key生成，用于防止恢复覆盖用户后续改号。

重启作废所有内存确认；凡持久 rollbackRef 未终结（包括写前）统一保留目标待处理，不自动写入或删除备份。用户明确选择恢复/放弃；missing snapshot 只能幂等放弃，不能报已恢复。恢复使用快照内的完整原范围、独立恢复key与原owner，不受新目录升级影响。写前核验 expected，逐项写后 actual 必须等于 intended 才能登记允许恢复摘要；变化拒绝覆盖。安全恢复/共享核验成功后删除快照，删除与DB终结间崩溃仍保留显式放弃出口。解密/ACL/损坏保持待处理。

## 5. 自定义登录绑定

平台目录之外提供“绑定其他网站”。默认从本次受管窗口当前页面取origin/显示名称，用户无需填写网址/selector/JSON。保存网站与Profile绑定即完成收录；未建立检查依据时显示“已绑定 · 尚未核验”，不启动模型。

检查依据复用已有可版本化TaskChain：选择已发布只读零模型链，或用 Chrome 原生 DOM/Overlay inspect 选取可见账号名/未登录入口。仅接受唯一稳定 id/data-testid；没有稳定定位就提示改用已有链，不自造选择器引擎。确认预览保留2分钟，确认即存不可变方法版本（即使尚未检查），原 navigate/read-fields/QuickJS/terminal 经 TaskChainRuntime/LangGraph 复跑。账号名出现只确认登录与展示，identityConfirmed=false，不能共享；标识消失为未知。取消退出原生选取，保留窗口/旧绑定；用户不填selector/JSON。

当前自定义绑定只支持原origin内只读检查，不提供认证迁移按钮。新增可迁移版本必须先核验完整认证key/共享域/目标身份，默认不批准父域或任意子域。

自定义链选择/发布前递归使用原 TaskChain 校验：固定不可变版本、只读能力/scope、子链递归，无 llm、无不受限外部调用、无写入动作；含模型的只读链也拒绝，进入浏览器前反馈。旧API `establish` 确定性返回已退役/不调用模型；`refresh/check/capture` 只映射新固定检查或当前页绑定，缺策略保持未核验；历史method只读。不得仅删UI保留默认producer后门。

## 7. 持久化和现有代码处置

复用原SQLite表/迁移，不删除历史。新的检查事实保存平台策略版本、身份引用、三态、身份摘要、依据等级、开始/结束、0模型和独立运行引用；旧AccountCheck/Method/TaskChain仍能读取为历史。平台目录固定数据与自定义绑定分别投影，不为了省代码把旧schema原地改成不能读旧数据。

迁移事实独立记录源/目标身份、平台版本、覆盖授权、写入阶段、目标核验、回滚与清理，不能保存在一个可漂移的“synced=true”。需要原运行调度时沿TaskChain/LangGraph；不新建调度器。

删除前先查调用/影响：旧 `account-method.ts`、`account-classifier.ts` 的默认模型方法生产与相关仅镜像实现的测试应退役；旧 `account-runtime.ts` 如仍服务历史检查/自定义链，保留必要执行适配。保留Profile身份、同源路由、revision、并发/取消/重启/owner、真实失败证据、业务无关已有dirty工作。不得删除通用W-U/B-U只读或编译能力，仅移除账号默认调用。

原交付文档/PROGRESS/ROADMAP注明失效结论和新方案，不改写历史首败。新的实现不能继续用旧“completed”证明新需求已满足。

事实兼容采用独立版本reader：现有 kind=check/method/result 原schema原样保留；新平台检查 kind=platformCheck、schemaVersion=1，不伪造旧method/chain字段；新迁移 kind=transfer、schemaVersion=1。历史verified只投影为历史身份已确认，不改写为本次authenticated。历史failed与modelCalls原样显示。新的固定检查若经TaskChain运行则引用实际不可变链/独立TaskRun，未运行链不能填虚假ID。

旧active maintenance即使entry已软删，也必须通过BrowserIdentity/owner/lease投影为“此前登录窗口”维护行，保留平台历史名称及原错误；用户可核验/返回/按原所有权结束。不能自动恢复用户删掉的目录，也不能忽略或强关旧窗口。新库/自有旧库副本与真实软删条目门均需验证。
