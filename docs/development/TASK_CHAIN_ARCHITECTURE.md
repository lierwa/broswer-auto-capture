## 已确认的目标层级与当前实现差距（2026-09-25）

```text
interview Skill + 按需只读搜索 + 用户确认 → 唯一准备计划草案
    → 同一草案版本的受校验内部投影与 B-U 指令
    → browser-use Agent + capture → immutable source artifact
    → workflow-use compiler + host materializer → candidate TaskChain
    → formal sample / verification → release + preset
    → LangGraph / TaskChainRuntime → TaskRun + execution cleanup → Workbench
```

| 层级 / 当前入口 | 单一责任 | 交接内容与退出条件 |
| --- | --- | --- |
| 对话与成稿：`apps/api/src/interview/`、访谈 Skill | 根据完整对话按需只读搜索、澄清业务歧义并形成唯一准备计划草案 | 来源身份、入口与引用、目标、动态规则、停止点和试做要求由用户审阅确认；待决事项未结算时不能交给 B-U。 |
| 准备：`task-chain/preparation.ts`、`authoring.ts` | 消费同一已确认草案，调用一次代表探索，协调编译与正式验证 | 内部合同仅受校验地投影草案，不得另生成业务计划或新 URL；来源、候选、验证和发布分阶段保存。 |
| 探索与采集：`hybrid/author.py`、`capture.py` | B-U 拥有 Agent loop 和浏览器能力；B-A-T 记录实际操作与必要来源 | 动作/参数/结果、相关前后观察、被后续决策或输出消费的数据、结束结果。来源关闭后不可变，不能把只读观察失败变成动作重派。 |
| 编译：`hybrid/natural_compile.py`、`hybrid-materializer.ts` | 从固定来源构造读取、函数、动作及控制连接，校验值绑定 | 完整动作覆盖的候选链或明确缺口。编译修复先离线消费原来源；纯编译缺口不得自动重新开浏览器。 |
| 运行：`plan-executor.ts`、`packages/runtime/src/task-chain/` | LangGraph 调度单一 Chain IR；B-A-T 处理输入、预算、恢复和审计 | 独立 TaskRun、输出与事件。普通节点零模型；只允许显式 llm 节点调用模型。 |
| 产品：`product.ts`、`execution-result.ts`、Workbench | 投影精确版本和单次运行，承接清理、修订及用户验收 | 合法终点与资源清理分别保留；用户验收是独立事实，修订发布新版本。 |

字段准入：每个持久公共字段必须有真实生产者和消费者；能从已存事实推导的内容不再增加第二份权威状态。诊断只描述定位所需的阶段和安全错误信息，不进入业务输出合同。已保存历史版本不因精简新实现被原地重写。

2026-09-27 方法边界补充：代表探索提炼 DOM 读取、操作和重复方法，代表样本用于证明方法，集合全部数据由生成链路在运行时获取。代表样本数量、单次读取预算与最终业务总量是不同事实；局部查询完整或双读稳定均不能证明业务全集。当前最终值倒推 DOM、读取上限耦合及自然循环编译断点见[主线方法编译差距](MAINLINE_METHOD_COMPILATION_GAPS.md)，必须先补能力再启动新的产品测试任务。此段明确目标，不表示这些断点已经修复。

2026-09-22 链路阶段与异常处理修正：阶段表达业务推进，展开子链显示同一执行图中的动作、节点类型与本次运行状态。`stable/v2` 的正常推进和业务分支端口必须接线；通用错误结果没有显式处理边时，由现有运行器在原节点保留失败、受阻、取消或人工等待事实。显式恢复边优先，缺少正常/业务路由仍是合同错误。新自然链仅删除可证明为受管编译器生成且无业务内容的重复异常边与孤立终态，不添加公共字段；历史版本保留。阶段卡不展示底层出口数量，不同业务终态不得合并成绿色“结束”。

Function 的代码属于版本化任务数据：编译阶段根据确认规则及读取样本形成纯 JavaScript，复用 QuickJS 验证并绑定已有节点输出。函数不读取浏览器、网络或文件；后续浏览器动作消费函数结果。当前候选选择适配只覆盖完整候选读取后的原始 ordinal 选择，不能宣称所有纯数据变换的自然编译都已经接通。

当前 B-U 预执行实际注册的能力为 `navigate / go_back / click / input / send_keys / scroll / dropdown_options / select_dropdown / wait / find_elements / search_page / done`；数据任务另有 `extract`。这是当前适配完成范围，不是 B-U 全部能力。工具说明与参数由其原生注册机制提供给 Agent，任务只提供已确认语义、输入及授权来源；宿主不要求 Agent 编写整张 IR。`find_elements` 的完整候选读取连同原始 ordinal 供后续 Function 使用，截断结果不能充当完整集合。完成记录明确区分成功与失败；准备注解的模型调用单独审计，普通复跑不再执行该注解。

预执行到编译的最小数据交接以消费者为依据，不以“以后可能有用”增加字段：

| 保存的事实 | 生产者 | 后续消费者 / 缺少时如何处理 |
| --- | --- | --- |
| 同一已确认准备计划草案、来源引用和代表输入 | 需求确认、准备协调器 | 动态规则及输入绑定；有业务歧义则回对话，不让计划模型或编译器猜。 |
| 实际动作、参数、结果与顺序 | 原生 Tools 派发和 capture | 编译的完整动作覆盖；失败或未派发不能伪装为成功动作。 |
| 动作相关的页面、文档、目标及必要前后观察 | 现有 Browser/DOM 能力适配 | 稳定目标、导航和后置条件；不能沿用探索时的临时元素编号作为复跑身份。 |
| 后续选择所需的完整候选、属性和原始 ordinal | `find_elements` 及读取采集 | Function 的运行输入与后续 click 绑定；读取截断或缺少消费字段时产生明确编译缺口。 |
| 由已确认规则生成的纯 JS 及变化输入样例 | 准备期语义注解，独立记录模型调用 | QuickJS 校验后物化 Function；复跑仅执行固定源码，错误不触发模型后备。 |
| 代表执行结束结果和来源关闭事实 | 原生 done 与 finally 关闭 | 候选准入和来源保留；不替代正式 sample/verification，也不替代 execution 清理事实。 |

最常见的值流只有一条：`当前页面读取 → main({ candidates }) → ordinal → 浏览器点击`。读取负责数据完整，Function 负责纯数据计算，浏览器能力负责动作；三个责任不能互相代做。Function 不需要 shell、Agent loop 或一套新的规则语言。

## 1. 最高产品目标

B-A-T 将自然语言描述的浏览器任务编译为参数化、版本化、可验证、可复跑的任务链路。首次运行可以由模型借助浏览器能力探索实际路径；链路形成并验证后，普通执行器直接复跑，只有到达显式 LLM 节点时才允许调用模型。

B-A-T 不以任何网站、业务实体或任务类别作为平台边界。数据采集、内容播放、表单填写、后台配置、文件上传下载和跨页面操作都由同一套任务链路表达。具体网站名称、页面文案、业务字段和任务数量是版本化任务数据，不是平台源码中的固定规则。

## 2. 产品闭环

```text
自然语言任务
  -> 需求访谈：Skill 按完整对话决定何时只读搜索、调查和追问；重要歧义由用户决定
  -> 准备计划草案：同一对话中写明目标、来源依据与试做入口、动态规则、步骤依赖和完成标准，用户确认唯一版本
  -> 内部投影：只校验并转换已确认草案，不能再次生成业务语义或添加 URL
  -> 代表探索：browser-use Agent 在一个 Browser 会话内探索每个步骤的一条代表路径
  -> 证据编译：结合已确认草案、内部合同和真实来源，把完整动作覆盖编译成参数化混合候选链路
  -> 自动样本复跑：正式执行器立即验证候选
  -> 修复—验证：本地失败复用原证据生成新版本并再次验证
  -> 换输入验证：证明输入绑定和复用边界
  -> 复跑运行：用户从已发布链路画布直接启动；画布绑定本次 execution 展示实时运行流；无节点、合同或运行时错误即完成
  -> 用户验收：接受结果、在自由画布修订局部节点，或携带运行记录返回需求访谈
  -> 漂移修复：受影响链路暂停，经用户授权形成并验证新版本
```

准备计划草案是需求对话的唯一用户确认产物，描述业务目标、来源和需要试做的可组合步骤。链路描述“一个步骤如何执行”；运行记录“本次使用哪些输入实际发生了什么”。内部 `TaskRequirement`/`TaskPlan` 如仍用于合同和编排，必须引用同一草案版本，不拥有独立业务决定；具体决定见 [ADR 0011](../adr/0011-interview-produces-preparation-draft.md)。

## 3. 单一事实源

| 事实 | 权威归属 |
| --- | --- |
| 用户目标、来源决定及引用、试做入口、参数、步骤依赖、约束和完成标准 | 已确认准备计划草案版本 |
| 来源候选和待决事项 | 需求对话事实；确认后引用进入同一草案版本 |
| 内部计划合同、绑定和技术预算 | 已确认草案与编译证据的受校验投影，不是第二份业务事实源 |
| 参数化节点、连接、输入输出契约、复用边界和推导出的技术预算 | 任务链路版本 |
| 当前输入、节点游标、变量、检查点、结果和审计 | 独立任务运行 |
| runner、浏览器会话和临时资源是否确认释放 | 执行资源清理事实 |
| 链路阶段分组和已发布坐标 | 不可变链路展示/修订版本 |
| 用户对运行结果的接受、节点调整或需求重聊意见 | 用户验收记录 |
| 当前页面、标签页及人工等待现场 | 浏览器会话 |

模型消息、UI 临时状态、任务样例和测试夹具都不是上述事实的替代来源。

链路画布中的标题、折叠出口、节点坐标、边路由和选中关系是由 TaskChain、版本化布局及运行事实派生的展示投影，不是新的执行事实源。
自动布局不得进入 executable digest；修订草稿的手动布局可以进入草稿 checksum，并在发布后作为该链版本的不可变展示布局继续使用。

一条链路只拥有一套可执行节点和连线。为满足用户阅读与局部修订，版本化展示事实可以把相连的动作节点归入**链路阶段**：阶段声明用户可读目的、实际节点引用、一个逻辑入口和具名出口，但自身不参与调度。阶段外连线只能穿过已声明边界；分支、循环和异常路径仍由真实节点与边表达。阶段或布局变更进入修订 checksum；只有可执行节点、边或绑定改变才改变 executable digest。

该版本化展示事实统一称为 `ChainPresentation`，按精确 chain id/version 关联并随发布版本不可变。它拥有阶段分组、总览布局、阶段聚焦布局、descriptor registry reference 和独立 presentation digest；不得被塞进 `TaskChainRuntime`，也不得由 Workbench 临时猜测。修订 checksum 同时覆盖 executable snapshot 与 presentation，二者 digest 分离。

动作节点的产品标题、摘要、类型化编辑字段、目标要求、端口、兼容替换和验证范围统一来自精确 capability name/version 的 `CapabilityDescriptor`。descriptor 是通用平台合同，不保存网站或任务知识；缺少 exact descriptor 的历史节点只读，不回退到 JSON 编辑。

Workbench 对同一层级投影提供三种阅读状态，而不是三份图：总览只绘制阶段及阶段间路径；选中阶段可在其下方临时附着非布局的动作摘要；进入阶段后，同一画布用面包屑聚焦该阶段的真实动作子图。任一时刻只允许一个临时摘要；技术路径不得常驻或塞进会撑大主图的容器。线性摘要可用时间线，含分支、循环或异常出口的路径必须进入聚焦图审阅和编辑。

## 4. 通用 Chain IR

任务链路是平台级中间表示，不是浏览器录像，也不是某次模型工具调用的原始转录。每个链路版本至少声明：

- 动态输入契约与动态输出契约；
- 入口节点和有向连接；
- 节点读取与写入的值绑定；
- 成功、缺失、超时、阻断、人工等待和失败等明确出口；
- 明确终点、执行预算和复用边界；
- 版本、验证证据和实现摘要。

任务输入和节点结果使用通用结构化值或产物引用。平台不得为网站、商品、评论、剧集、表单或其他任务实例新增固定公共类型。任务需要的字段结构由需求与计划动态生成，随链路版本保存并由运行时校验。

## 5. 节点族

| 节点族 | 职责 | 必要语义 |
| --- | --- | --- |
| `capability` | 调用版本化通用能力 | 能力引用、输入绑定、配置、效果等级、结果合同及明确失败出口 |
| `function` | 在隔离沙箱执行随链路保存的纯数据函数 | 固定源码、输入绑定、单一结果合同、时间/内存限制及失败出口 |
| `branch` | 根据已有值选择有序多路分支 | N 个有序类型化 case、必需 default、稳定 port 及失败出口 |
| `loop` | 有界重复一段节点 | 集合或继续条件、游标、上限和终止依据 |
| `invoke` | 调用已保存的另一条链路 | 链路身份、版本、单次或逐项模式、输入与输出绑定 |
| `llm` | 显式单次调用模型完成语义判断 | 编译时保存的 prompt、一个输入绑定、一个类型化 `result` 和调用审计 |
| `terminal` | 结束本次链路调用并绑定输出 | 完成、部分完成、阻断、失败或取消及可验证原因 |

人工等待、检查点和输出发布属于运行生命周期，不是可无限扩张的业务节点类型。具体浏览器操作集合由 `browser.perform` 等能力合同提供，至少覆盖导航、观察、点击、输入、按键、选择、滚动、拖拽、标签页、上传、下载和等待。Chain IR 通过当前 browser-use capability adapter 调用这些能力，不维护一套与浏览器提供者分叉的站点操作系统。

## 6. 值绑定与运行上下文

节点参数只能来自以下来源：

- 本次链路输入；
- 已完成节点的输出；
- 当前运行变量；
- 明确常量。

运行上下文只保存通用事实：输入、节点输出、变量、浏览器观察、产物引用、循环游标、检查点和最终输出。业务名称可以作为任务动态数据中的键出现，但运行时不得据此选择网站专用代码路径。

节点不能依赖探索时生成的临时元素引用。可持久化目标必须使用复跑时能够重新解析的语义描述或浏览器适配器认可的稳定定位描述。

## 7. 链路组合与重复执行

已确认准备计划草案中的业务步骤经内部合同投影后，通过输入输出连接。一个步骤产生集合、后续步骤逐项处理时，后续只保存一条参数化链路，并对集合中的每个输入创建一次链路调用；不得为每个输入复制一张同构节点图。

链路调用必须固定被调用链路的身份和版本，保存每个输入的稳定键、结果、检查点与失败状态。单个输入失败时的停止、暂停或继续策略由已确认草案明确决定，不能由执行器临时猜测。

## 8. 模型与首次编译边界

2026-09-19 用户收敛了 LLM 边界：复跑只支持一种显式 `llm` 节点。该节点必须来源于用户明确要求或已经确认的准备计划草案中的语义步骤；prompt 在编译时生成并随 TaskChain 版本保存，运行时不能临时拼 prompt 或因普通节点失败而插入模型。节点读取普通能力已经形成的一个输入值，最多调用模型一次，只返回一个类型化 `result`；它不拥有 Browser、Tools 或 Agent loop，也不返回节点 ID、连线、动作或技术预算。当前页面需要语义理解时，先由普通观察节点生成页面数据或截图产物，再交给 LLM；后续动作仍由 Function/Branch/Capability 明确承接。

同日明确：弹窗、DOM 遮挡、滚动锁定和 selector/等待失败不属于 LLM 需求。预执行已证明的关闭动作可以编译为由下游消费就绪控制的可选准备动作；运行时新出现且没有安全处理证据的干扰必须失败并保存 native dialog、目标、命中和滚动事实，由后续修复产生新链路版本。完整实现见 [D 阶段方案](replay-repair/D_RUNTIME_RESILIENCE_AND_EXPLICIT_NODES.md)。


2026-09-16 用户明确：需求对话只负责聊透需求并产出详细精准的自然语言执行任务列表，直接交给 browser-use。不得另加必须确认的规则 JSON，也不得把它作为探索或编译的第二份需求权威。编译以已确认任务与实际执行证据为来源，内部数据合同不成为给 b-u 的新任务语言。

产品中的模型只通过 AI Connect 选择的账号和模型运行。当前新路径的首次代表探索复用 browser-use Agent/Browser；AI Connect 通过薄 bridge 提供模型，API 宿主不得手写第二套模型/工具循环。Pi/BrowserSkill 的既有实现只作为历史或其他已隔离路径保留，不能参与同一次新链 authoring/replay。Codex 只用于开发，不是产品运行时、账号入口或额度来源。

模型可以参与：

- 需求理解与访谈；
- 在同一需求对话中形成并修订准备计划草案；
- 首次代表路径探索；
- 对编译器提交的单个有界区段补充开放语义注解；
- 用户明确发起的链路修复；
- 链路中声明的 LLM 节点。

模型不得直接拥有完整节点图、边、节点标识、错误出口、检查点或技术预算。B-A-T 必须先记录经校验的全部动作、动作前后观察、真实业务结果和字段来源，再由受管 fork 按 [ADR 0005](../adr/0005-workflow-use-fork-hybrid-compiler.md) 完成动作覆盖、需求对齐、值绑定和区段分类，最后由宿主确定性物化唯一 Chain IR。轨迹和注解只作为编译证据，不得成为第二套可执行 DSL 或运行旁路。

普通能力、函数、分支、循环、调用和终点不得隐式调用模型。每个输出字段必须能追溯到可复现的能力结果；只能由模型推断的值必须成为显式 `llm` 节点，否则链路不可冻结。每次复跑必须从实际调用审计得出模型调用数，不能因链路声明“普通”就推断为零调用。

## 9. 浏览器与人工边界

browser-use Browser 或后续等价实现是当前新路径的浏览器能力提供者，不拥有任务需求、计划、链路版本、批量复跑或业务完成结论。B-A-T 的浏览器适配层负责把 `browser.perform` 能力映射为经过准入的公开动作，并返回类型化结果。

页面结构化读取必须复用 browser-use 的公开页面、元素和观察能力及经过准入的成熟解析组件。平台不得让模型执行任意页面脚本，也不得把网站选择器或业务字段写进公共源码；定位和字段映射随任务版本保存。

登录、验证码、一次性口令、授权确认、支付确认和访问限制形成类型化运行等待点。自动化必须停止并保存现场；用户交还控制权后重新观察并检查恢复条件。超时、取消或仍受限是明确结果，不是自动重试信号。

登录态由用户浏览器 Profile 持有。B-A-T 只保存非秘密的 Profile 引用或状态摘要，运行前以同一 Profile 做只读核验；Cookie、密码、令牌和验证码不得写入 Git、测试快照或普通日志。browser-use Browser 会话在 `finally` 中关闭，关闭会话不清除 Profile。

链路运行结论与资源清理结论分别保存。TaskRun 已经到达合法 completed terminal 而 runner、浏览器树或临时资源清理尚未确认时，
不得改写节点和输出事实，也不得产生链路修复授权；正式 execution 进入 `cleanup_required`，阻止资源冲突的新运行并只允许核验清理。
清理确认后执行生命周期闭合；业务执行和清理同时失败时，业务错误保持主因，清理作为附加生命周期事实。

## 10. 验证与复用边界

第一次代表输入得到业务结果只证明预执行成功。输出字段拥有可重现来源、样本常量已参数化、临时引用已转换为稳定定位且循环有界后，才是可编译候选。候选生成后立即由正式执行器复跑样本；本地失败进入有界修复并产生新版本，外部访问限制则暂停。最终还要在至少一个不同输入上证明绑定生效、合法完成终点可达、输出合同成立且模型调用符合声明，才能标记为已验证并冻结。

正式运行的 `completed` 只表示链路沿合法控制流到达完成终点，所有已执行节点及输出合同没有未处理错误。节点定位、动作派发、输入、读取、输出校验、浏览器断开和预算错误仍然必须失败；但不得在图已经正常结束后追加一个链外的来源 judge、完成态 judge 或通用证明引擎，仅因缺少额外语义证据把运行改判为失败。用户是否认为实际结果符合需求是独立验收事实。

TaskRun 的 completed 与正式 execution 生命周期闭合必须区分：前者只由图执行决定；后者还要求本 execution 所有运行资源的清理已确认。
清理未确认不是节点失败，也不是用户不满意；它是可持久恢复的 `cleanup_required`。只有类型化清理报告可以驱动该状态，新运行不得依赖错误字符串推断。

需求、计划和链路可继续保存用户可读的完成预期，供准备验证、版本审阅和画布编辑使用；运行时完成事实只来自实际到达的 terminal、节点结果和输出合同。`chain.completion`、`step.completion`、`plan.completion` 等历史 predicate 不得在合法终点后成为第二套全局运行门，旧来源 trace 的 judge 元数据也不得参与新编译或复跑判定。

页面结构变化超出已声明复用边界时，运行暂停受影响输入并保留进度。修复产生新链路版本；不得修改旧运行历史，也不得为继续批量执行而让模型逐项临时接管浏览器。

用户声明的是业务数量和授权范围。图迁移、底层浏览器命令、活动时间、显式 LLM、调用次数和深度等技术预算由编译器根据图、节点能力成本、超时、显式循环上限和子链计算；模型不得猜这些预算。运行错误必须指出耗尽的具体技术预算，账号或供应商用量另归模型提供方错误，不能统一显示为“额度耗尽”。

## 11. 分层职责

LangGraph `StateGraph` 是正式运行路径唯一的图执行引擎，负责重复异步推进、循环调度、取消传播和递归上限。`TaskChainRuntime` 把版本化 Chain IR 映射为一次图运行，并在每个产品节点边界应用值校验、预算、幂等和审计；不得再用手写 `while`、自建 scheduler 或另一套状态机替代这些引擎能力。

独立 `TaskRun` 仍是用户可查询、可恢复和可审计的产品事实，由 API host 使用现有 SQLite/Drizzle 仓储持久化。LangGraph 内部快照不能替代任务版本、授权、浏览器现场摘要和未决副作用合同；同时也不应另建一份引擎数据库，使同一次运行出现两个权威状态。

| 层 | 允许拥有 | 不得拥有 |
| --- | --- | --- |
| contracts | 通用 Chain IR、动态数据契约、事件和运行状态 | 网站或任务类别的固定业务类型 |
| runtime | 将 IR 映射到 LangGraph、值绑定、控制流、子链调用、产品检查点和审计 | 手写通用调度器、浏览器、数据库、模型供应商或站点知识 |
| browser adapter | 浏览器能力映射、会话和安全边界 | 任务计划、批量语义或业务完成结论 |
| API host | 需求、计划、链路编译、版本、授权、运行编排和持久化 | 重复实现浏览器驱动或通用图解释器 |
| Workbench | 通用任务、计划、节点、运行、清理、人工等待和链路展示投影 | 按网站或业务字段分叉的状态机、第二份可执行图 |

## 12. 链路运行台与展示边界

- 已发布链路的运行/再次运行主操作位于链路工作台；左侧任务或 session 列表只选择和导航。选择与运行都必须立即显示 pressed、busy、accepted 或 error，不允许无反馈点击。
- 服务端运行命令以 requestId 幂等并返回明确 `TaskExecution` 引用。画布一次只绑定该 execution 及其 TaskRun 事件；历史运行必须显式切换，禁止逐节点混合不同运行的最后事件。
- 实时传输只负责把持久化运行事件送到 UI。无论轮询还是事件流，都必须按 execution 与单调序列续接，不能成为第二个 runtime 或状态事实源。
- 链路阶段与实现它的动作节点是同一 `TaskChain` 的层级投影。总览解释任务顺序，临时摘要解释关键动作，聚焦态显示真实节点、端口、分支及异常出口；三者不得维护可漂移的节点或连线副本。
- 链路阶段只能来自已确认草案的内部投影、编译证据或显式版本化事实，不得按网站、文案、CSS class、节点 label 或坐标猜测。旧链没有可靠阶段事实时显示“未分组动作”，不得伪造业务含义。
- 节点编辑必须由 capability descriptor 提供类型化表单、上下文摘要和兼容替换规则。缺少 descriptor 的节点只读；不得以递归 JSON 编辑器作为通用回退。
- 画布基础设施优先复用成熟开源工作流编辑器；B-A-T 只拥有 TaskChain/revision/run-event 到编辑器模型的适配、产品运行命令和审计，不自研已有的通用画布能力。
- 动画只增强可感知性。节点和边状态必须同时以文字、图标或线型表达；reduced-motion 不影响信息完整性。

## 13. 架构验收门

任何链路公共能力只有同时满足以下条件才能宣称完成：

1. 至少能表达两类结果不同的浏览器任务，而不是只通过一个数据采集样例；
2. 任务特定输入输出只存在于版本化任务数据中；
3. 一次探索生成一条参数化链路，换输入验证后可以由普通执行器复跑；
4. 每个步骤的代表探索先返回真实业务结果，所有输出字段有可重现来源；模型只给紧凑编译语义，宿主确定性生成唯一 Chain IR；
5. 节点状态、人工等待、模型调用、字段来源、检查点、具体技术消费和终止原因均可审计；
6. 至少再以一类非数据采集任务证明公共能力没有被首个抓取样例绑死；
7. 用户可以从已发布链路画布直接启动运行并观察本次 execution 的节点与连线流，再修订局部节点并发布新版本，或携带运行记录返回需求访谈形成新需求版本；
8. 链路画布以“阶段总览—临时动作摘要—同画布聚焦子图”满足可读与可审计；技术路径不常驻、不形成第二份图，列表选择不产生运行副作用，任何异步操作都有即时反馈；
9. 未通过真实浏览器闭环时，自动化测试和结构样例不能替代完成结论。

首次探索、轨迹和编译的详细决策见 [ADR 0002](../adr/0002-pi-agent-exploration-trace-compilation.md)，稳定节点和当前实施顺序见[稳定通用任务链节点迭代说明](STABLE_TASK_CHAIN_ITERATION.md)。
