# 自然语言浏览器任务链路架构基准

日期：2026-09-12；2026-09-13 修订首次探索与编译边界
状态：已确认；首次探索采用 Pi AgentSession，链路由真实轨迹确定性编译
适用范围：B-A-T 的需求、计划、链路协议、浏览器适配、执行器、持久化、UI 与验收。

## 1. 最高产品目标

B-A-T 将自然语言描述的浏览器任务编译为参数化、版本化、可验证、可复跑的任务链路。首次运行可以由模型借助浏览器能力探索实际路径；链路形成并验证后，普通执行器直接复跑，只有到达显式 LLM 节点时才允许调用模型。

B-A-T 不以任何网站、业务实体或任务类别作为平台边界。数据采集、内容播放、表单填写、后台配置、文件上传下载和跨页面操作都由同一套任务链路表达。具体网站名称、页面文案、业务字段和任务数量是版本化任务数据，不是平台源码中的固定规则。

## 2. 产品闭环

```text
自然语言任务
  -> 需求访谈：确认目标、输入、约束和可观察完成标准
  -> 任务计划：拆分步骤并声明链路间输入输出
  -> 探索运行：Pi AgentSession 借助 BrowserSkill 完成代表输入并返回真实业务结果
  -> 轨迹编译：记录工具轨迹与字段来源，宿主确定性形成参数化节点图
  -> 链路验证：正式执行器复跑样本并换输入证明复用边界
  -> 复跑运行：普通执行器执行已保存链路
  -> 漂移修复：受影响链路暂停，经用户授权形成并验证新版本
```

需求草稿、任务计划、任务链路和任务运行分别拥有版本与事实源。计划描述“需要哪些可组合步骤”；链路描述“一个步骤如何执行”；运行记录“本次使用哪些输入实际发生了什么”。

## 3. 单一事实源

| 事实 | 权威归属 |
| --- | --- |
| 用户目标、参数、约束和完成标准 | 已确认需求版本 |
| 步骤、依赖、链路组合、业务数量限制和授权范围 | 任务计划版本 |
| 参数化节点、连接、输入输出契约、复用边界和推导出的技术预算 | 任务链路版本 |
| 当前输入、节点游标、变量、检查点、结果和审计 | 独立任务运行 |
| 当前页面、标签页及人工等待现场 | 浏览器会话 |

模型消息、UI 临时状态、任务样例和测试夹具都不是上述事实的替代来源。

## 4. 通用 Chain IR

任务链路是平台级中间表示，不是浏览器录像，也不是某次模型工具调用的原始转录。每个链路版本至少声明：

- 动态输入契约与动态输出契约；
- 入口节点和有向连接；
- 节点读取与写入的值绑定；
- 成功、缺失、超时、阻断、人工等待和失败等明确出口；
- 完成条件、执行预算和复用边界；
- 版本、验证证据和实现摘要。

任务输入和节点结果使用通用结构化值或产物引用。平台不得为网站、商品、评论、剧集、表单或其他任务实例新增固定公共类型。任务需要的字段结构由需求与计划动态生成，随链路版本保存并由运行时校验。

## 5. 节点族

| 节点族 | 职责 | 必要语义 |
| --- | --- | --- |
| `browser` | 执行受控浏览器原子操作 | 操作、参数绑定、目标描述、结果绑定及明确失败出口 |
| `observe` | 获取当前浏览器可观察状态 | 观察范围、稳定条件、结果绑定 |
| `data` | 对通用结构化值执行确定性处理 | 提取、赋值、转换、过滤、映射、去重、排序、合并或计数 |
| `condition` | 根据值或浏览器状态选择分支 | 类型化条件及各结果出口 |
| `loop` | 有界重复一段节点 | 集合或继续条件、游标、上限和终止依据 |
| `invoke` | 调用已保存的另一条链路 | 链路身份、版本、单次或逐项模式、输入与输出绑定 |
| `human` | 等待用户完成不可由程序代办的动作 | 原因、提示、恢复条件、超时及取消结果 |
| `llm` | 显式调用模型完成语义工作 | 指令、输入绑定、结构化输出契约和调用审计 |
| `checkpoint` | 保存可恢复执行状态 | 节点游标、变量、循环状态和浏览器状态摘要 |
| `emit` | 发布链路输出或产物 | 输出名称、值或产物引用及动态契约校验 |
| `terminal` | 结束本次链路调用 | 完成、部分完成、阻断、失败或取消及可验证原因 |

具体浏览器操作集合由浏览器能力合同提供，至少覆盖导航、观察、点击、输入、按键、选择、滚动、拖拽、标签页、上传、下载和等待。Chain IR 通过浏览器适配器调用这些能力，不维护一套与 BrowserSkill 分叉的站点操作系统。

## 6. 值绑定与运行上下文

节点参数只能来自以下来源：

- 本次链路输入；
- 已完成节点的输出；
- 当前运行变量；
- 明确常量。

运行上下文只保存通用事实：输入、节点输出、变量、浏览器观察、产物引用、循环游标、检查点和最终输出。业务名称可以作为任务动态数据中的键出现，但运行时不得据此选择网站专用代码路径。

节点不能依赖探索时生成的临时元素引用。可持久化目标必须使用复跑时能够重新解析的语义描述或浏览器适配器认可的稳定定位描述。

## 7. 链路组合与重复执行

任务计划通过输入输出连接多个步骤。一个步骤产生集合、后续步骤逐项处理时，后续只保存一条参数化链路，并对集合中的每个输入创建一次链路调用；不得为每个输入复制一张同构节点图。

链路调用必须固定被调用链路的身份和版本，保存每个输入的稳定键、结果、检查点与失败状态。单个输入失败时的停止、暂停或继续策略由计划授权明确决定，不能由执行器临时猜测。

## 8. 模型与首次编译边界

产品中的模型只通过 AI Connect 选择的账号和模型运行。首次代表路径探索由 Pi AgentSession 负责多轮推理和 BrowserSkill 工具调用；API 宿主不得手写第二套模型/工具循环。Codex 只用于开发，不是产品运行时、账号入口或额度来源。

模型可以参与：

- 需求理解与访谈；
- 任务计划形成；
- 首次代表路径探索；
- 为探索证据补充输入参数、循环、输出来源、完成条件和复用边界等紧凑语义注解；
- 用户明确发起的链路修复；
- 链路中声明的 LLM 节点。

模型不得直接拥有完整节点图、边、节点标识、错误出口、检查点或技术预算。B-A-T 必须先记录经校验的工具调用、动作后观察、真实业务结果和字段来源，再由宿主编译器把轨迹与紧凑注解转换为本文件定义的唯一 Chain IR。轨迹和注解只作为编译证据，不得成为第二套可执行 DSL 或运行旁路。

普通浏览器、观察、数据、条件、循环、调用、检查点和输出节点不得隐式调用模型。每个输出字段必须能追溯到可复现的浏览器观察或工具结果；只能由模型推断的字段必须成为显式 `llm` 节点，否则链路不可冻结。每次复跑必须从实际调用审计得出模型调用数，不能因链路声明“普通”就推断为零调用。

## 9. 浏览器与人工边界

BrowserSkill 或后续等价实现是浏览器能力提供者，不拥有任务需求、计划、链路版本、批量复跑或业务完成结论。B-A-T 的浏览器适配层负责把 `browser` 与 `observe` 节点映射为受支持命令，并返回类型化结果。

页面结构化读取必须复用 BrowserSkill 已有的 page、target、HTML 或语义快照能力及成熟解析组件。平台不得让模型执行任意页面脚本，也不得把网站选择器或业务字段写进公共源码；定位和字段映射随任务版本保存。

登录、验证码、一次性口令、授权确认、支付确认和访问限制使用 `human` 节点或等价类型化等待点。自动化必须停止并保存现场；用户交还控制权后重新观察并检查恢复条件。超时、取消或仍受限是明确结果，不是自动重试信号。

登录态由用户浏览器 Profile 持有。B-A-T 只保存非秘密的 Profile 引用或状态摘要，运行前以同一 Profile 做只读核验；Cookie、密码、令牌和验证码不得写入 Git、测试快照或普通日志。BrowserSkill 控制会话在 `finally` 中关闭，关闭会话不清除 Profile。

## 10. 验证与复用边界

第一次代表输入得到业务结果只证明探索成功。输出字段拥有可重现来源、样本常量已参数化、临时引用已转换为稳定定位且循环有界后，才是可编译候选。编译后的链路还要由正式执行器复跑样本，并至少在一个不同输入上证明绑定生效、完成条件可达且模型调用符合声明，才能标记为已验证并冻结。

页面结构变化超出已声明复用边界时，运行暂停受影响输入并保留进度。修复产生新链路版本；不得修改旧运行历史，也不得为继续批量执行而让模型逐项临时接管浏览器。

用户声明的是业务数量和授权范围。图迁移、底层浏览器命令、活动时间、显式 LLM、调用次数和深度等技术预算由编译器根据图、节点能力成本、超时、显式循环上限和子链计算；模型不得猜这些预算。运行错误必须指出耗尽的具体技术预算，账号或供应商用量另归模型提供方错误，不能统一显示为“额度耗尽”。

## 11. 分层职责

LangGraph `StateGraph` 是正式运行路径唯一的图执行引擎，负责重复异步推进、循环调度、取消传播和递归上限。`TaskChainRuntime` 把版本化 Chain IR 映射为一次图运行，并在每个产品节点边界应用值校验、预算、幂等和审计；不得再用手写 `while`、自建 scheduler 或另一套状态机替代这些引擎能力。

独立 `TaskRun` 仍是用户可查询、可恢复和可审计的产品事实，由 API host 使用现有 SQLite/Drizzle 仓储持久化。LangGraph 内部快照不能替代任务版本、授权、浏览器现场摘要和未决副作用合同；同时也不应另建一份引擎数据库，使同一次运行出现两个权威状态。

| 层 | 允许拥有 | 不得拥有 |
| --- | --- | --- |
| contracts | 通用 Chain IR、动态数据契约、事件和运行状态 | 网站或任务类别的固定业务类型 |
| runtime | 将 IR 映射到 LangGraph、值绑定、控制流、子链调用、产品检查点和审计 | 手写通用调度器、浏览器、数据库、模型供应商或站点知识 |
| browser adapter | 浏览器能力映射、会话和安全边界 | 任务计划、批量语义或业务完成结论 |
| API host | 需求、计划、链路编译、版本、授权、运行编排和持久化 | 重复实现浏览器驱动或通用图解释器 |
| Workbench | 通用任务、计划、节点、运行和人工等待投影 | 按网站或业务字段分叉的状态机 |

## 12. 架构验收门

任何链路公共能力只有同时满足以下条件才能宣称完成：

1. 至少能表达两类结果不同的浏览器任务，而不是只通过一个数据采集样例；
2. 任务特定输入输出只存在于版本化任务数据中；
3. 一次探索生成一条参数化链路，换输入验证后可以由普通执行器复跑；
4. 探索先返回真实业务结果，所有输出字段有可重现来源；模型只给紧凑编译语义，宿主确定性生成唯一 Chain IR；
5. 节点状态、人工等待、模型调用、字段来源、检查点、具体技术消费和终止原因均可审计；
6. 至少再以一类非数据采集任务证明公共能力没有被首个抓取样例绑死；
7. 未通过真实浏览器闭环时，自动化测试和结构样例不能替代完成结论。
