# 需求对话：机制、层级与实现边界

日期：2026-09-06。范围：持续需求对话与多任务归属；全工作台信息清单和承载方式见 [工作台布局](WORKBENCH_LAYOUT.md)。产品后续来源与浏览器执行阶段不因本次 UI 修改被标记完成。

## 判断依据

参考 domain-analysis 现行 `InterviewThread.tsx`、`codexCategoryInterviewRuntime.ts`、`categoryInterviewModule.ts` 与私有 `interview-product-category/SKILL.md`。借鉴的是持续对话、逐轮决策、草稿版本及独立规划机制，不是它的商品品类、品牌策略或 ZOL 限定。

本工具的基础产物是基于 BrowserSkill 的浏览器操作链：输入、动作、条件、循环、检查点和可验证结果。数据抓取是当前首个场景；未来浏览器自动化需要独立定义读写权限、人工确认、幂等性和恢复规则，不能从本轮讨论推断已经允许支付、发布、提交等动作。

## 信息价值与展示层级

减负的判断标准是“用户现在是否需要它作出判断”，而不是屏幕元素数量。

| 信息 | 主界面保留什么 | 二级内容 | 原因 |
| --- | --- | --- | --- |
| 对话 | 按到达顺序的用户原文、助手回复、当前问题及建议 | 不折叠整条时间线；旧消息通过滚动回看 | 对话上下文是当前任务本身 |
| 草稿 | 消息中的文档卡、当前版本入口、确认状态 | 完整 Markdown、版本选择、明确确认按钮 | 长文档需要专门阅读，但不能失去入口和状态 |
| 决策 | 当前必要问题；开放回答或 2–3 个真正业务选项及代价 | 历史问题保留在对应消息，不能再次提交旧选项 | 提问形式取决于缺少什么信息 |
| 来源 | 被采用的来源、可行性、影响范围的缺口 | 查询记录、URL/时间、代表页证据、字段详情 | 主层帮助判断能否继续，详情支持审查依据 |
| 计划 | 步骤目标、依赖、输入输出摘要和授权状态 | 完成标准、预算、来源引用、风险细节 | 操作链依赖必须可见，技术字段不必全部平铺 |
| 链路 | 独立完整画布、步骤切换、节点/分支/循环 | 选中节点的配置与验证依据 | 画布本身是核心价值，不降成弹窗附件 |
| 结果 | 完成/部分完成、结果与关键缺口 | 原始来源关联、运行和模型审计 | 有结果才能谈完成，诊断不能淹没成果 |
| 设计系统 | 无业务入口 | 工程文档、组件规则、自动检查 | 设计规范约束实现，不是用户业务任务 |

## 当前访谈实现

### 业务目标驱动的访谈（2026-09-06 修订）

访谈负责得到足以开展来源调研和制定计划的业务要求。用户可以只给品牌、品类或目标，系统负责发现可核验的入口和对象集合；用户提供链接是可选线索。先判断信息属于哪一类，再决定是否追问：

| 信息类别 | 处理方式 |
| --- | --- |
| 会改变结果的关键业务取舍 | 结合完整历史，只问当前最必要的一项；已明确或已委托系统决定的不重复问 |
| 品牌候选、官方店铺、分类入口、商品链接、页面字段、分页及访问情况 | 形成系统调查事项与核验标准；缺少具体 URL 不阻塞草稿 |
| 可合理建议的处理方式 | 写入草稿的建议默认值，随草稿一起确认；不能静默缩减用户的全部覆盖要求 |

必要名称或自由描述使用开放问题（options=[]），用户直接在原输入框回复；有真正互斥的业务选择才提供 2–3 个点击即可提交的答案。不要把“我粘贴链接/在输入框填写”等操作方式包装为选项。历史问题只读。初始页面提示业务目标和范围，链接明确可选。

结束门：目标/对象可辨认，来源范围已明确或委托发现，交付数据与覆盖/数量/终止要求足以判定结果，关键业务歧义已解决。满足就本轮直接生成草稿，不限定轮数。真实数量、页面可得性、店铺身份和分类路径留待来源调研，不要求用户替系统调查。

“前 N 条”需明确关联对象、排序与不足处理；可建议页面默认排序，随草稿确认。委托系统确定“知名/主流”范围时，建议应包含证据类型、纳入条件和适用时间，而实际名单待调查。用户纠正品牌、数量或范围后，要按语义重写整份草稿并核对所有字段，不残留旧对象或引入未要求的地区限制。

新草稿包含结构化 brief：目标、对象范围、来源策略、数据实体/字段/覆盖/数量与终止、系统调查目标/期望输出/采纳标准、完成标准、约束、建议默认值。完整 Markdown 由该结构确定性生成，用户看到的内容与后续读取的需求一致。确认仍绑定 taskId、draftVersion 与 revision；新输入立即使当前交接失效。旧草稿原文与确认记录保留，brief=null 不凭空补成新结构需求；后续阶段需重新整理该历史需求后才能取得结构交接。

例如指定品牌时，后续可发现店铺→枚举商品集合→逐商品采集详情/评价；整个品类可先发现符合范围口径的品牌和店铺集合。该发现关系不固定成两条或三条链路。正式调研先核验入口、代表样本及可行性；批量枚举和逐项采集的执行由计划组织，上游实际输出传入下游。访谈不提前要求全量链接，也不让用户决定链路拆分。

1. assistant-ui ExternalStoreRuntime 负责对话、滚动、输入、发送与停止。工作台服务持有业务消息，不让 UI 或模型线程成为事实源。
2. 用户原文完整送入当前轮次；建议点击也作为普通用户消息提交。已回答的问题在历史消息中保留，但禁用重复提交。
3. 每轮从工作台模型设置读取并冻结同一账号与模型，通过 ai-connect 结构调用执行；未保存选择时明确提示先完成设置，不自动选择或回退模型。
4. 访谈协议区分负责人取舍、系统可调查事实及可审阅建议；一轮最多一个必要问题，没有未决取舍可直接形成草稿。开放问题无选项，业务选择题一键回答，无固定题库、轮数或京东默认答案。
5. 中文 commentary 与最终助手回复进入时间线，问题和草稿卡附属于对应助手消息。机器 JSON 不进入聊天正文；不显示内部推理或原始诊断。
6. 完整成功且 Zod 校验通过才提交结构草稿。问题和可确认草稿互斥，选择题推荐项唯一。单轮串行；旧 revision 请求拒绝。新模型不再单独输出 Markdown；用户未提供的 URL 不能写入 providedUrls。
7. 需求确认绑定草稿版本及会话 revision。任意新输入立即使旧确认失效；历史草稿保留、只读。确认操作不调用模型，不产生浏览器授权。
8. 失败/中断保留对话并允许重试最近一次用户原文，不重复追加同一条用户消息。刷新恢复已保存历史；恢复时若服务仍在运行则持续读取快照直到终态。

## 来源调研与真正计划的交接

访谈输出是需求范围，不是抓取计划。以下仍是后续实施门：

1. 从已确认版本创建独立来源调研；检索候选入口并保存实际搜索事件。
2. 通过受控 BrowserSkill 打开代表页面，检查字段、枚举/分页依据、访问状态和终止信号。搜索命中不能被标记为页面已观察。
3. 对照需求建立覆盖与缺口；需要改变业务范围时带证据回到对话，新需求版本使旧计划待复核。
4. 生成绑定需求和来源证据的计划：步骤目标、依赖、输入输出、预算、停止条件、风险。此时仍不是可执行节点图。
5. 用户确认计划并授权启动后，逐步探索、固化链路、换输入验证，再继续剩余范围。普通节点不得隐式调用模型。

不得把本地已存在的冰箱步骤/节点结构样例冒充当前任意需求的正式计划。现有计划和链路仍标记样例，执行按钮受门控制。

## 当前技术与验收边界

F1 已接入独立 Fastify 服务（默认 4175），构建页面与 API 可在同一服务访问，Vite 开发页面代理相同 API。共享 Zod 契约由 packages/contracts 持有；任务创建和访谈命令携带幂等键，取消指定 turnId，命令响应与观察流分别处理。NDJSON 快照绑定 taskId 和单调 sequence，迟到响应不能回退状态；断开观察不停止服务端轮次。初始加载、读取失败、正在停止、失败重试及响应丢失重发均有界面入口。

左侧列表支持新建、搜索、重命名、归档和恢复。切换任务保留各自输入、页签、阅读位置、节点及详情选择；刷新只恢复服务端业务记录与选中任务，不承诺恢复全部视图状态。草稿始终用右侧覆盖抽屉，左边缘可拖拽调宽，支持键盘微调和窄屏限宽；同一任务关闭重开保留宽度。版本记录使用 Radix Select；归档任务只读，历史版本不能再次确认。访谈提示词由正式协议模块持有，不再复制私有 skill 或创建旧 App Server 会话目录。浏览器不直接持有登录凭证。

SQLite/Drizzle 是事实源：任务、消息、轮次、未决问题、明确选项决策、版本草稿、确认、审计及操作去重在本地事务保存。建议没有被点击就不产生 option 决策；自由追问保留原文与问题上下文，草稿确认单独记录。模型调用在事务外执行，仅完整成功且本地验证后提交产物；取消事实优先于迟到成功。新输入清除当前确认，保留历史确认与草稿。

旧 JSON 在首次启动事务导入，原件保留；损坏文件、冲突与重复导入通过隔离测试。相同目录有独占锁，异常退出后新进程在约 10 秒锁过期后恢复未完成轮次为 interrupted；这不会恢复或自动重启模型请求。旧 Vite 私有 server 原型及其专属测试已删除；正式 Fastify API 是唯一服务入口，历史持久化数据仍由现有 schema 兼容读取。

当前访谈不声明原生网页搜索能力，也不接收宿主 shell、插件、Hook 或 Memory；来源事实由独立调研和受控 BrowserSkill 执行产生。模型实际成功/中断返回的调用审计保存于服务；失败时未返回审计则未知，不补造零。
