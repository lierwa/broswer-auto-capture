# 全工作台布局与信息承载规则

日期：2026-09-06。依据：负责人要求同时落实完整信息分层与多个需求任务列表。

负责人已表示原型先保留，转入功能开发。本文件是布局承载基线，不是全部状态的最终画面签核；各状态的最低展示和操作要求见 [UI_STATES](UI_STATES.md)，整体开发入口见 [DEVELOPMENT_BASELINE](DEVELOPMENT_BASELINE.md)。后续随真实功能补齐界面，不要求负责人提前穷举所有画面。

## 1. 层级和归属

左侧任务侧栏 → 当前任务 → 需求对话／来源调研／抓取计划／抓取链路／运行结果。

任务从一次需求对话开始，持续拥有后续产物；不是五个彼此无关的全局页面。切换任务必须同时切换五个视图的上下文。尚未接入的来源/计划/运行保持当前任务的真实空态，不展示别的任务或全局冰箱样例作为其成果。

任务列表固定显示新建、搜索、名称和一个关键状态；不平铺每项的步骤、字段、计数与日志。重命名、归档在更多菜单，已归档列表按需打开且可恢复。新建不调用模型、不弹需求表单，直接进入空白对话。

## 3. 承载规则

- 常驻：完成当前判断必需的信息。状态、阻塞原因与关键风险不能因减负而藏入折叠。
- 折叠：属于原对象的补充，展开后仍适合在原处阅读；不是把整个主流程藏起来。
- 需求草稿：始终使用右侧覆盖抽屉，左边缘可拖拽调宽并支持方向键调整；宽度随视口收缩，同一任务关闭重开保留宽度。版本选择使用 Radix Select，历史版本只读。确认按钮说明当前仅保存需求版本，后续调研和规划另行实施。
- 其他详情侧栏：节点、来源、结果详情在宽屏与主内容并排，关闭不删除数据。
- 窄屏抽屉：空间不足以并排时，使用具有焦点管理、Esc 关闭和返回焦点的右侧覆盖抽屉，不压缩画布到不可读。
- 弹窗：短暂且聚焦的操作，不承载持续聊天或整页长文档。不因为所有内容都属“二级”就使用同一种弹窗。
- 同一视图只展示一个对象详情，切换对象原位替换；不叠加多个详情面板。不同视图保留各自选择，任务切换时不得显示上个任务的详情。

## 4. 状态与交互

- 未开始：显示真实空态、下一步条件和一个主要入口；不把协议字段清单铺成仪表盘。
- 进行中：显示实际进度和停止入口；可以切换任务继续查看或编辑，不因离开页面取消后台轮次。
- 受阻/失败：问题和可用恢复动作在主层；日志与技术诊断放详情。另一任务正在用模型时显示任务归属，不把“发送不可用”做成无解释的灰按钮。
- 待确认：文档卡和状态在主层，全文与版本在侧栏；确认绑定当前任务和版本。
- 完成/部分完成：主层显示成果及关键缺口；审计按需查看，不能以计数或动画代替业务结论。

任务切换保存各自未发送输入、对话阅读位置、页签、样例开关、步骤、节点选择和详情状态。正在生成的响应仍写回发起任务，不得串入后来选中的任务。归档不删除产物，恢复后仍归原任务；执行中的任务不能归档。

## 5. 响应式布局与本轮能力边界

- 宽屏：约 232px 任务侧栏 + 弹性主区；详情打开时提供约 380px 侧栏，对话保持可读。
- 中屏：任务侧栏默认收起，可手动展开；详情空间不足时转右侧抽屉。
- 小屏：任务列表通过左侧抽屉打开；业务 Tabs 可横向滚动，输入保留视口内，节点画布保持主视图。

本轮实现多任务元数据与独立访谈持久化、任务切换和现有五视图的信息分层。来源调研、正式计划与 BrowserSkill 执行仍未接通，其未来有数据/失败/完成态按上表约束，不能声称真实执行交付完成。当前文件存储仍是本地开发切片，不替代后续 Fastify/Drizzle 与队列事务迁移。
