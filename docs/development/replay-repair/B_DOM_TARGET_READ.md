# B · DOM 定位与数据读取

## 目标与接口

输入：当前页面、任务要求、原生查询或 A 提供的局部上下文。

输出：可重新解析的目标描述，以及按记录范围读取的字段值和来源。探索和复跑使用同一套定位/读取能力。

## 当前入口与修改位置

现有 `FieldReadToolParams` 使用 `outputPath/container/fields`。模型负责选择所需范围和字段，程序提供输出 schema、身份、基数和审计信息。

Python 路径前缀：`vendor/workflow-use/workflows/workflow_use/hybrid/`。

| 文件 | 修改职责 |
| --- | --- |
| `targets.py`、`natural_target_compile.py` | 稳定目标描述、当前页面唯一解析 |
| `dom_evidence.py`、`author.py` | 给既有工具提供真实局部结构 |
| `field_read_params.py`、`field_read_tool.py` | 少字段模型接口、准确错误反馈 |
| `read.py`、`rendered_field_text.py` | 记录范围、相对字段、渲染文字读取 |
| `natural_reads.py`、`field_read_evidence.py` | 读取一致性、结果来源与编译输入 |

## 实现

1. 使用真实 DOM 父子结构生成并验证定位描述。原生 index/backend id/坐标仅用于当前观察；保存的描述必须在节点重建后重新解析。
2. 目标必须唯一。按记录身份选择与按集合第 N 项选择由任务含义决定；歧义返回候选及范围，不默认取首项。
3. 使用原生选择器与元素查询。缺少上下文时补查所需局部；现有 selector 无法表达原生目标时，最小扩展现有目标表达，不新增平行的多套 LLM 字段。
4. 先定位记录集合，再执行任务要求的筛选/前 N 条选择，逐项相对读取。数量上限用于校验；不能用隐藏截断代替选择操作。
5. 区分零命中、多命中、可选字段、空字符串和合法空集合。返回具体字段、范围和命中问题，不把读取错误转为空成功。
6. 使用实际渲染文字或任务要求的属性。shadow、slot、frame 通过已核验的原生能力读取；保留时间、标签等字段的完整语义。
7. 读取前后核对 document、记录集合及相关数据状态。发生更新时丢弃混读结果，按预算重读该范围；不重发翻页、提交等业务动作。
8. 结果由成功读取记录装配。需要语义推断的字段显式交给 D，并区分读取值与推断值。

## 替换或删除

删除猜 CSS 层级、整页 HTML、歧义首项兜底、隐式 slice、跨记录读取、样本值冻结及读取失败后的模型手抄兜底。统一到正式字段工具和原生查询通路，移除无消费者的重复包装。

## 独立验收

| 场景 | 通过条件 |
| --- | --- |
| 同名目标、节点重建、行顺序变化 | 按任务含义选择正确记录，歧义/缺失不误操作 |
| 多列表、嵌套子项、前 N 条 | 集合、顺序、数量和逐字段归属正确 |
| 单值/多值/可选字段/空集合 | 返回值与页面一致，错误有准确字段和基数 |
| shadow/slot/时间字段 | 可见内容完整、顺序正确，Updated/Created 含义不混淆 |
| 同 URL 读取过程中刷新 | 输出来自一致状态，或明确未就绪；无新旧混合结果 |

先用真实浏览器核对底层读取，再让 b-u 通过正常工具信息自行完成实际任务页面的读取。开发者提供正确 selector 只算底层验证。改变数据、记录位置和布局后，复验同一接口。

交付目标与字段来源对照、真实工具调用、变化数据结果和支持范围。完成后供 [C](C_INTERACTION_ORDER.md) 使用。
