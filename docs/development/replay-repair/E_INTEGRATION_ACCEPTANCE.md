## 验证顺序

| 阶段 | 使用方式 | 通过条件 |
| --- | --- | --- |
| 小链保存加载 | 正式入口生成含点击、等待、读取的候选，重新加载后运行 | 同一版本执行正确，结果来自当前页面 |
| 普通与 LLM 组合 | 同一链设置可选干扰分支 | 未触发时无额外模型调用；触发时 b-u 局部处理后正确返回 |
| 同链换输入 | 更换合法入口/记录输入及页面数据 | 复用同一候选版本，输出随实际输入变化，不重新生成整链 |
| 取消恢复 | 在动作完成但结果等待中取消，再恢复 | 继续同一 run，无重复业务副作用 |
| 完整业务 | 当前已确认需求、计划和输出格式 | 所有要求、输出来源及运行审计通过 |

受控页面用于复现延迟、布局和弹窗竞态；实际任务页面用于验证产品可用性。两者均使用正式能力入口。手填正确 selector、mock 返回值、native judge 或退出码不能单独构成通过证据。
