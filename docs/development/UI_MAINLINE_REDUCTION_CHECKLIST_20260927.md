## 1. 删减判据

默认界面只需要说明：现在在做什么、用户需要做什么、结果或失败原因是什么。不能帮助理解这三件事的重复说明、技术教材、冗余状态和专属退役入口删除。

- **删除：** 重复标题/状态/按钮、空闲口号、实现机制解释、无消费者的 UI 分支、D1 智能修复与 D2/D3 编辑拾取入口、D4 旧兼容展示。不是添加隐藏开关保留整套逻辑。
- **合并：** 同一工作区的阶段进度和当前动作有一个主要显示位置；侧栏导航摘要与工作区详细进度有不同职责，可以同时存在。
- **按需：** 完整搜索词/来源依据、历史、运行事件、原始诊断等仍有用途，默认收起或进入已有详情。信息不因折叠而从持久化删除。
- **保留：** 用户原话、业务结果、来源身份与必要选择、操作风险、永久删除确认、真实失败和合法下一步、忙碌/取消反馈、人工等待、清理及原窗口操作、可访问性名称。
- **状态去重不等于删事实：** 草稿/发布/运行归属、版本摘要、原错误、清理/交付结论继续保留。先删重复投影和无消费者字段；不能把多个真实结果压成一个“完成”。

| 尚无链路 / 准备 | 一个阶段进度、必要输入或失败处理；无假节点 | 空态编号、多个生成入口、头部/中央/侧栏重复的进度和说明 |
| 链路画布 / 节点说明 | 业务步骤、真实连线、必要运行状态、只读说明、缩放/定位 | 编辑表单、代码输入、增删/改路由、元素拾取、重复展开按钮和教学文字 |
| 样本 / 独立复验 | 当前验证动作、必要参数、不同输入要求、实际结果 | 常驻多段验证口号、底层冻结机制解释；两次验证事实不得删除 |
| 手动发布 | 一个明确发布操作及必要后果说明 | 关于计划/步骤/布局/证据冻结的技术清单、后置修复流程的承诺 |
| 正式运行 | 本次必要参数、开始、忙碌反馈；单次运行设置按需 | execution 术语、无参占位输入、同义状态堆叠 |
| 等待 / 失败 / 清理 | 具体原因、对应继续/取消/清理操作 | 无条件“请重试”、工程排障教材、错误的“动作已完成”前缀 |
| 结果 / 原窗口 | 业务值、一次运行结论、必要原窗口入口 | 每次自动展开的评价表单、无数据时无意义占位卡、所有权教学段落 |
| 历史 / 诊断 | 所选运行的版本/时间/结果，必要故障证据 | “按需读取”眉标、能力计数、旧兼容数量、默认内部 ID/核验次数 |
| 登录 / 模型设置 | 可用连接、明确错误、在网站登录/结束操作 | 重复原则宣传卡、实现说明；不改共享设置组件的内部实现 |
| 归档 / 删除 | 当前只读原因、恢复/永久删除及不可撤销说明 | 重复归档说明；不得以删文案取消删除确认 |

## 5. 跨层删除要求

1. 每项先确认所属生产者/消费者。删除专属 JSX 后，同时清理 callbacks、hooks、连接方法、提示、样式及无消费者字段；不能仅加 CSS 隐藏。
2. D1–D4 的 API 命令、任务投影和仓储读取由各自功能卡一并退役。共享取消、准备原阶段恢复、来源保存、验证、发布和删除任务继续工作。
3. 文案与派生状态只保留一个映射来源；不为每张卡新增布尔字段或主操作枚举。身份、revision/checksum、来源引用、requestId 和 execution 仍由宿主持有。
4. 节点可编辑性与可读性拆开：删完整编辑器后，草稿也要有只读动作说明；不能删掉写表单后留空侧栏，或让普通用户靠 JSON 自行排错。
5. 布局与图执行分开：阅读图、缩放和聚焦不能保存节点修改。保留既有 React Flow 和自动布局，不另造画布或 graph runtime。
6. 复用现有 Radix、共享 Timeline/Question Panel 和已有组件。通过公开能力解决显示问题，不读 node_modules、不复制第三方组件；题板真实重复展示尚待验证，不能仅凭相同参数名删合同。
7. D5 现有观察节奏已折叠在运行设置，暂不额外建设调试器；不能把观察延迟当页面就绪条件。D6 的复杂创作扩展与此次 UI 清单分开，不因此删除单链分页/循环及稳定输入输出能力。

## 6. 实施顺序与退出条件

本轮只交付文档。后续代码阶段按所属功能完成一组再推进：

1. **功能退出：** D1 智能修复、D2 手工编辑、D3 人工拾取、D4 旧兼容；连同 U20/U31/U32 等专属界面同步收敛。
2. **统一状态：** 处理 U02/U05/U13–U16/U23/U27 和第 4 节，去掉重复及误导含义，保留原始事实与即时反馈。
3. **逐环节删文案/入口：** 按 U01–U35 的实际范围处理；U28/U33/U35 只核验保留能力，其余条件性项先验证实际问题。不因已经处理其中一页而宣称全部 UI 已清理。
4. **最小所属验证：** 纯文案用定点检查；跨包字段/命令删除才做所需类型检查和边界验证；保护真实回归才补测试。不跑未经授权的根级/全量测试，也不为每句短文案新写测试。
5. **正式 UI 验收：** 随既定新任务主线观察实际出现的各阶段，核对同次 API/SQLite 事实；等待/失败等未自然触发的分支用已授权的所属验证分别证明，明确未测范围，不注入草稿或旧任务凑截图。

逐项关闭应记录：编号、删改文件、消失的冗余内容、保留入口、验证证据、未测项。最终至少满足：

- 默认界面没有面向普通用户的 execution/digest/内部合同教材；必要诊断仍可访问。
- 同一工作区不堆同义状态、同动作按钮和多个上下文抽屉；确认/运行/发布请求即时有反馈。
- 无链路、草稿、已发布三个情境均有正确下一步；失败不能被“精简”成完成。
- 搜索、题板、确认草案和历史版本引用没有被删错；用户结果及来源可完整读取。
- 运行事件只属于所选 execution，等待/清理/交付保留可理解原因与正确操作。
- 原窗口操作、永久删除确认、键盘操作、图标可访问名称以及亮暗主题不退化。
- 代码、状态/协议、文档中的退役入口一致；不能 UI 已消失但后台仍继续生成智能修复任务。

## 7. 本轮证据边界与维护

本轮检查了导航/访谈/搜索/草案/链路/编辑/运行/结果/历史/账号设置等直接组件，以及 `task.ts` 标签和 `workspace-projection.ts` 的派生关系；**仅完成源码审查和文档登记，没有运行态逐页验收，没有改生产代码或测试。** U11/U12 的共享组件实际重复展示须在实施时定点核验，不能算本轮已复现。
