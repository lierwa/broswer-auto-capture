# 边执行边生成节点：最小开发方案

日期：2026-09-28；源码基线：`1e9d635d7e86`。本版替换此前同名文档，不沿用旧版“生成节点永不更新”的要求。

**用户后续已授权实施；共用编译、串行保存、在线结果消费和最小画布已接通，受控集成通过，真实新任务首次验收未完成。** 当前证据及首次失败以 [PROGRESS](PROGRESS.md) 顶部为准；第 9 节保留设计阶段探针，不以其替代实施或真实验收。实际服务与网站验收已启动，最新结果见 PROGRESS；未提交推送。

## 1. 目标和唯一实现路线

B-U 执行动作时，及时采集现场并生成真实节点。每步保存当前生成结果；结束时已有节点和证据可以形成完整链路。主逻辑完成后，现有画布显示节点，原状态位置显示一句话。

**首版选择：每一步用现有编译规则重新计算当前有限的来源前缀，替换同一个生成快照。** 这是读取已保存证据的确定性计算，不重新执行浏览器动作，不重新让模型生成一条链，不做“冻结前缀”缓存、依赖更新引擎或后台编译队列。

三个边界：

- 原始动作及现场事实不可改：做过什么、作用于什么、结果是什么必须保留。
- 生成中的节点允许按新证据确定性补全：例如后续读取使前一点击有了更准确的等待条件。每次更新都重新校验，不能改原始动作来迎合节点。
- 保存为正式草稿/链路版本后，遵守现有 revision/checksum 和历史不可变规则；已发布版本不得原地改写。

“稳定”指节点的定位、操作、参数来源和检查有证据、可由普通执行器执行，**不是探索未结束就承诺节点所有字段永不变化**。缺少必要信息的动作保留为待补全，不把占位框算作节点。生成校验通过不等于已复跑验证；后者仍由完整候选进入现有普通执行器后提供证据。

本期不做：回退识别、探索树、新剪枝算法、A/B/C 页面子链推导、全输入泛化、新恢复状态机、模型重试循环、时间线/统计/百分比/额外模型播报。已成功的绕路动作照常记录；后续沿用已有合法的读取裁剪和重复方法装配，但不新增路径优劣判断。

本文服从 [任务链架构基准](TASK_CHAIN_ARCHITECTURE.md)，不替换 B-U Agent、浏览器适配、LangGraph、TaskChainRuntime 或既有发布/清理流程。[ADR 0012 的本日补充](../adr/0012-mainline-single-source-and-phase-boundaries.md#2026-09-28-在线生成的限定修订)同步修订“只能关闭后编译”的时序限制；不取消完整来源留档、身份校验及关闭确认后才进入样本验证的门。

```text
Product Alignment:
- natural-language task: 用户确认的受支持浏览器任务，如数据读取或表单操作。
- reusable chain boundary: 既有 PlanStep 的参数化链路，不新增任务/网站专用边界。
- runtime inputs: 同一确认版本的输入合同与代表输入。
- dynamic task outputs: 沿用既有结果合同与真实数据来源。
- generic platform capability used: 原生采集、受管 hybrid 编译/物化、准备 job、现有画布。
- replay model calls: 普通节点为 0；仅保留合法的显式 llm 节点。
- site/task-specific code added: no
```

## 2. 对旧设计的实质修正

| 旧要求 | 为什么不成立 | 本版决定 |
| --- | --- | --- |
| 节点生成后不能改完成条件 | `rebind_consumer_readiness` 会根据最终保留的读取重绑条件和证据 | 同一来源动作保持稳定 ID；生成快照中的配置可以重新推导并校验 |
| 结束只能接边，不能再计算节点 | 读取裁剪、重复折叠、可选准备动作会影响节点/运行 scope | 最后再执行一次同一编译规则；不重新探索，不走另一套模型生成 |
| 所有待补全都阻止下一个改变页面的动作 | 输出选择、重复方法依赖后续证据，不一定缺当前现场 | 区分“现场证据缺失”与“已有证据等待组合”，按第 4 节处理 |
| 必须只转换新增动作并永久缓存旧节点 | 需自行维护依赖失效和回写，增加第二套编译状态 | 首版重算受预算限制的前缀；不实现增量缓存优化 |
| 发现终态冲突再回 G0 想办法 | 把架构决策留给了实施者 | 本节已选定可更新生成快照；验收只验证明确行为，不再决定路线 |

原始来源不可变与派生节点可更新不是两套执行图：来源是证据，生成快照是当前唯一未发布投影；最终仍只有现有 TaskChain 交给执行器。

## 3. 精确调用顺序

```text
原生 before_action：采集目标/输入/前态，执行已有派发前检查
→ 原生动作执行
→ 现有 after_step：对齐实际结果、采集后态
→ 必要选择函数生成一次（只返回 source）；以真实候选与实际点击序号/导航目的地校验
→ 快照当前来源；共用编译逻辑生成当前片段
→ 宿主校验、物化、保存快照并确认
→ B-U 继续下一步
```

### 3.1 采集时机

保留 `max_actions_per_step=1` 和现有 `AuthorCaptureCallbacks`。不自己调用 `Agent.step`，不另写 Agent loop。

- 动作前：复制需要保留的目标结构、参数来源、页面/document/标签身份；不能把临时 `click.index` 或活 DOM 对象当作复跑定位。
- 动作后：先按原生 `step_number/actionIndex` 对齐历史并完成 rebase，再生成快照。动作 ID 不能按回调次数或参数相同匹配。
- 模型失败而未产生动作：维持原生错误处理，不制造动作/节点，不因此阻止原生模型重试。
- 采集到的页面/目标身份不一致：复用当前有界观察/刷新机制；无法取得一致证据就终止准备，不让已派发动作重做。

失败尝试只按现有 coverage 证据过滤：已证明未派发或符合现有纯读取失败排除规则的动作可不进入执行节点，但保留原记录与排除原因。已派发且可能改变页面的失败不能因为后面成功就删除，更不能跨过它借用后态；无法闭合其影响时返回缺口。成功但走错方向的动作照常转换，本期不判断方向。

从 `EvidenceCollector.finish` 抽出不结束采集的快照步骤。它不得清空 pending、伪造 finalResultRef、把完成标记改成 true，或声称浏览器已关闭。`historyRef` 在一次 author 请求开始时固定，不每步随机生成。

`attach_prior_read_bindings` 与 `PreparedSelections.attach` 的派生事实按事实身份幂等附加；不能改写原生动作或重复叠加。唯一控件沿用已证明的确定性唯一性保护；动态选择函数在成功动作后用既有 annotation 生成一次，只返回源码或 null。代码提供真实候选、实际 ordinal 和 schema，并在原 QuickJS 中核对。成功事实进入原 collector；失败记 gap 和已尝试动作键，后续快照与最终结束不得自动再问模型。B-U 不再注册 `bat_validate_selection`，不要求它写函数、样例或节点字段。父子结构只用于 B-A-T 内部采集编译，不注入模型反馈。

同一选择能力覆盖两种输出：点击消费当前候选 ordinal，动态导航消费当前候选 attribute_href。导航已经具备输入/授权常量/唯一读取绑定时不增加模型调用；混合目的地查询中存在等价链接时不能随便固定某一数组位置，必要函数按需求选择 href，由原 navigate 消费。原继续查询全部等价 href 的情况仍由 repeat 绑定处理。输出类型/真实样例/连接均由代码决定，模型仍只写源码；同一来源键成功或失败均最多生成一次。

### 3.2 保存先于下一步

回调等待本批宿主确认，确认成功才返回 B-U。只保持一个待确认批次，不后台追赶、不并发编译、不让 UI 是否连接影响运行。

有编译缺口或未来依赖时，先保存来源、已有节点及缺口再继续探索；不得把普通编译缺口变为 Agent.stop 或让 B-U 改函数。来源身份、协议、保存/ACK 失败则停止并留证，不能把它们反馈成模型重做浏览器动作的指令。

## 4. 什么必须当场解决，什么可以等后续证据

决策由现有分类/证据校验代码产生。只增加准备期内部的依赖分类，不向执行节点添加新状态；不得靠 UI 文案、模型自报或统一过滤 gap 字符串作决定。

| 当前缺项 | 处理与结束条件 |
| --- | --- |
| 前态/目标结构/实际结果/页面身份缺失或不一致 | 必须当前采集阶段解决；超过已有预算即失败，不能离开现场后补造 |
| 参数缺可靠输入或先前读取来源 | 复用现有绑定；缺口当步留证，继续探索但不产生假节点，不用样本常量顶替。最终未解则拒绝发布 |
| 操作已有直接后态证据 | 当步生成节点；不为未知将来读取阻塞 B-U。后续可按真实消费者证据补强条件 |
| 操作只缺后续读取证明后态 | 留为编译依赖，不拦截原生下一动作；现有因果规则仍禁止跨已派发的状态变更借用证明，越界未解时记缺口，最终拒绝发布 |
| 固定 wait 尚未出现所属动作 | 先用现有 unchanged 等直接条件分类；仅缺归属时等待下一目标，沿用 `supporting_wait/waits_owned_by_next_target`，不新增特殊等待节点 |
| 当前读取最终是否被结果/后续动作使用 | 读取方法先生成，不因暂时没有消费者就裁掉；等最终装配决定保留，不需要重取现场 |
| 现有重复方法尚未形成 | 保存已验证读取和实际操作。方法未确定不装配循环、不把代表页数固化为循环次数；证据齐全后复用现有 repeat 注解/验证/折叠 |
| 其他编译缺口 | 保存缺口、继续原生探索，最终拒绝不完整链路 |
| 来源摘要/身份错误、保存失败、越权或业务歧义 | 停止并保留原因；业务歧义回需求对话，不让准备模型替用户决定 |

重复导航的窄例外：`derived_repeat_navigation_binding` 可能需要稍后才产生的 repeat_method。只有已保存、同一上下文的完整验证读取能够覆盖实际导航值，且缺项确实仅为该方法关系时，才能记为“等待方法”；不生成带假绑定的 navigate 节点。只有值碰巧相同、读取截断或来源不明，不适用这个例外。最终已有方法验证不通过则准备失败，不能改成固定 URL。

未来依赖的识别放在对应分类函数内：消费者就绪、wait 归属、重复方法分别返回自己的结构化依赖及动作引用。不要在外层写“所有 missing_binding/missing_effect_proof 都可忽略”的总开关。依赖记录仅含现有动作引用、缺项类别和证据引用，不成为可执行指令。

**采集安全边界与编译准入分开。** 已保存的证据是否能组成节点不能限制 B-U 正常探索；最终仍未解的依赖不能发布。身份失配、越权与无法可靠保存来源仍由原安全边界停止。

after_step 保存依赖和缺口；before_action 不再按编译依赖拒绝下一动作。因果边界由编译器检查，跨边界不能产生错误连接。不得新增模型指令、自动插入动作或补证重试循环。编译缺口与来源/保存错误分别保留归属，不能统一包装成 capture_failed 或交给 Agent 重试。

## 5. 编译器与物化器怎么拆

### 5.1 两个入口，共用规则

新增准备期内部入口 `compile_natural_prefix`；保留现有 `compile_request` 的完整来源入口及严格默认行为。不得让正式运行或外部请求用 prefix 模式绕过完整准入。

| 处理 | 每步 prefix | 最终完整编译 |
| --- | --- | --- |
| 来源/registry/动作参数、目标和实际效果校验 | 执行 | 执行 |
| 现有动作分类、读取、选择函数、值绑定 | 执行；所有当前前缀按同一规则重算 | 执行同一规则 |
| 直接后态、已有消费者就绪、辅助 wait 归属 | 执行；未知依赖明确返回 | 执行；未解依赖拒绝 |
| 根据“暂时没消费者”裁掉读取 | 不执行；未来还可能消费它 | 执行既有 liveness 规则 |
| 原始证据已确认的未派发/失败尝试过滤 | 执行既有 coverage 规则 | 执行相同规则 |
| 完成来源、最终输出/结果绑定、重复签名与整体图准入 | 不提前要求；不伪造通过 | 全部执行，不放宽 |
| 语义函数 | 只对新成功选择动作生成一次；普通重算不调用模型 | 复用已保存函数，不再补问；现有重复方法注解仅在有重复读取时调用一次 |
| 产物 | 真实局部 segments、coverage、依赖/缺口；不具备运行入口 | 完整既有 HybridCompilation/TaskChain |

从 `natural_compile.py` 抽出当前动作分类循环；完成来源检查与 `finalize_natural_compilation` 的整体准入留在完整入口。prefix 的读活性策略是“当前未使用不代表无用”，不能直接把当前完整编译器的结果删掉几个 gaps 就当 prefix。

每步重算只读快照，零浏览器调用、零模型调用。同步遍历受现有来源和读取上限约束；不做跨步失效缓存。性能必须用最大受支持前缀测量；不合格时记录为实施未完成，不能用异步追赶隐藏，也不因此改变本方案的数据/执行所有权。

### 5.2 TS 物化

从 `hybrid-materializer.ts` 抽出“校验来源、局部依赖、生成节点”的共用函数，prefix 和完整入口均使用它。保留现有 canonical 数字字节、事实摘要、选择函数 QuickJS、消费者后态和 scope 检查，不能只做 Zod 形状校验。

prefix 只物化当前依赖齐全的节点集合；不完整项保留证据/缺口，不能临时填 null、假目标或假成功终点。节点配置要用现有严格节点 schema；部分图不调用完整 `taskChainSchema`，也不作为 TaskChain 对外返回。

若下游的值绑定或 runtime scope 依赖待补全节点，下游也暂不物化；不能删掉依赖或改成样本常量来让它通过。每次前缀重算后用现有绑定/scope 规则检查依赖闭合，不维护另一张跨步依赖图或永久阻塞状态；证据齐全后自然一起生成。

最后的完整物化继续执行：已有读取裁剪/重绑、重复方法与 scope、可选准备动作、结果节点、预算、完整图校验。它们可以更新生成快照；无需为了“只追加”删除现有能力。原始动作/来源不变，节点身份和去向由现有 segment ID/ActionCoverage 关联，不新建血缘系统。

### 5.3 必须成立的具体例子

1. 导航后先读宽集合，再读用于点击的窄集合：早期节点可关联宽读取；最终宽读取若合法裁掉，导航节点以同一 ID 重绑到窄读取。不能保留悬空 consumerRef，也不能为保护“冻结节点”禁止这种合法更新。
2. 一个读取后来被 done 选为输出：prefix 必须保留它；最终不能因之前无人消费而丢失。
3. 两次代表迭代后来形成已证明循环：生成时已保存每次读取/动作，最终复用既有折叠及 coverage。正式链只保留一个参数化循环体，不复制 N 份，也不抹掉探索事实。
4. 失败动作可能已经改变页面：不得跨它把后续读取强接成之前动作的完成证明；沿用现有拒绝规则。
5. 同一个当前前缀计算两次：节点/缺口相同，来源不变；模型调用和浏览器派发均为 0。

这些是开发必须实现的确定行为，不是留给开发者选择的备选路线。

## 6. 最小交接与保存

只扩展现有 fd3/stdin 协议与 job 仓储，不增加事件库、数据库表、消息队列、订阅框架或第二个状态机。

### 6.1 一个当前生成快照

在现有 authoring 合同增加可选字段 `job.authoring.build`，旧 job 缺省为 undefined。需要的内容只有：

- authorRequestId、PlanStep、批次 sequence、整包摘要：限定来源与重复确认。
- 当前 canonical 来源及 prefix 编译结果：复用已有动作/观察/segment/coverage 类型。
- 校验后的 nodes/edges、当前依赖与缺口：节点是上述编译结果的投影，不拥有独立业务逻辑。

内部字段复用已有同义合同，不新造第二套来源类型。来源中不复制原始模型 history、截图或整页 DOM，敏感资料沿用现有本地受控边界。公开工作区只投影节点与必要状态，不投影原始现场或模型思考。

采用当前快照整体替换，不设计增量 patch 协议。已有动作/结果/观察原始事实只增不改；派生编译结果允许变化，但每一版必须重新通过共用验证，不能由前端或模型随意改节点。

PlanStep 结束时先保存该步骤的最终编译产物及引用，再切换当前 build；禁止覆盖前一步成果。本条只保护已有顺序处理，不扩展 D6/each 自动创作。

### 6.2 一个保存确认往返

Python 在当前回调里发送 `authoring_compilation` 类别的检查点，宿主在现有 stdin 返回匹配的保存确认。事件具体字段由 Zod/Pydantic 同步定义并测试；包含请求、批次和摘要，不只返回 success。

- `RunnerProcess.accept` 按事件种类分派，不再把所有 event 当人工等待。
- `AuthorRequestLoop` 在 author 活跃时只多接这一种确认，不接受任意并发浏览器命令。
- 宿主校验、物化并通过现有 `saveJob` 原子保存成功后才确认。Python 收到准确确认才继续。
- 写入前再次核对当前 job 的请求/步骤/活动状态；不能用耗时校验开始时的旧 job 副本覆盖后来发生的取消或人工等待。新增 build 仍经现有仓储保存，不另建状态写入通道。
- 同请求/批次/摘要的重复包直接确认；同序号不同内容、乱序、错误 owner、取消后的迟到包拒绝。
- 来源或协议非法时保留上次有效快照和固定原因，按现有原始回执方式留证，不用非法数据覆盖有效节点。
- 保存成功但确认丢失：停止本次准备，保留数据；不重放动作、不自动重开 author。刷新只恢复展示，不承诺崩溃后的浏览器自动续跑。
- 等待必须可取消、有界；B-U 0.13.8 的 on_step_end 在 step_timeout 之外，不能依赖原生 step timeout 收尾。
- 确认预算涵盖宿主实际校验：以本批既有 Function 校验执行次数（只计算实际提供的样例，不追加逆序输入）× 原 1000ms 沙箱上限，加 10 秒本地解析/IPC/保存余量计算；不是旧版固定 10 秒截断一切校验。两端从同一受校验批次确定次数，上限来源于受限前缀及 FunctionDraft 合同，禁止无限续时。10 秒余量是首版预算，不是已测性能结论；第 8 节上界验收未过则不能交付。
- 管道关闭、取消或宿主拒绝必须释放当前等待。诊断 fd4、前端轮询都不参与成功确认。

人工登录/验证码继续使用原 `HumanWaitControl`；只有用户继续及身份检查完成后才采集人工作用后态，再生成节点。保存 ACK 不是人工授权。清理沿用现有 finally/owner 路径，清理失败不覆盖原业务/编译错误。

## 7. 结束阶段不能另起一条生成路线

1. 每个普通步骤执行 prefix 编译与保存。原生正常 done 加既有输出合同决定探索是否完成；删除 B-A-T 完成 judge 及其追加任务/重跑逻辑。
2. author 最终完成时，`finish_author_source` 复用已保存选择函数；只保留确有重复读取时的现有 repeat 注解。不得重复请求选择程序，也不得以最终补问掩盖在线缺口。
3. **在当前 author 返回最终来源、关闭浏览器前**，对最后快照调用一次完整编译与完整物化；未解现场依赖、非法目标/绑定、输出或控制缺口均失败，不降级为“先发布再修”。
4. 完整结果通过同一个保存确认通道保存；最终来源回执必须与它的请求、来源摘要、registry 和输入版本一致。保留现有 onSource 原始回执存档与真实关闭结论。
5. `TaskChainAuthoringService.taskWithModel` 的新在线分支消费这个已核验结果，替代现在 explorePlan 后默认再启动 `recompile` 的过程。不要追加第二条在线编译路径，也不允许“缺最终结果就偷偷调用旧路径”。
6. 现有用户显式发起的离线重新编译仍保留，只用于该明确操作；不是本次首次准备失败的自动后备。当前 `recompileHybridSource` 中“编译缺 selection/repeat 注解后再调用模型”的分支留在显式离线操作内，不接到在线终态兜底；在线只用第 2 步已有 author 注解，仍缺就保留首次失败，不新增注解重试。
7. 浏览器/runner 关闭结论仍单列。在线完整产物此时只保存在 job：只有最终 `source/v3` 已留档、同版身份及摘要通过、原 owner 关闭确认，才按现有路径保存正式候选并进入样本/独立验证/手动发布。失败或关闭未确认时保留在线结果但不能提前运行；发布后由原 LangGraph 路线运行。

这里允许最后一次纯编译更新草稿，是必要的最终归一化；禁止的是最后才第一次转换全部动作、重新开浏览器补现场、重新让模型设计整条链。最终缺口只能使本次准备失败并留下原始记录，不能通过修补重试改写“首次通过”。

## 9. 设计阶段可行性证据与边界

已对照本地源码核实：B-U 步骤末回调可等待；已有单动作分类、消费者就绪、完整编译/物化、双向进程协议和 job 仓储均有现成接入点。[官方 hooks](https://docs.browser-use.com/open-source/customize/hooks)说明扩展方式，具体时序以锁定版本为准。

本轮执行了两个不启动浏览器或模型的定点探针，均有 exit_code=0：

1. 使用现有 liveness 夹具：同一来源经现有裁剪/重绑得到相同节点 ID，consumerRef 从 `s-a-0002` 改为 `s-a-0004`；重复纯计算结果相同，原始来源和旧草稿副本不变。这证明“来源不变、派生草稿允许更新”与现有规则相容。
2. 使用现有真实方法合同夹具，去掉 done/最终结果并保持 `completed=false`：现有单动作分类仍产生同一 read-fields 方法；旧完整编译入口正确拒绝该不完整来源。这证明可以复用局部分类，但必须分开 prefix 与 final 准入，不能伪造完成。

第二项首次因测试 PYTHONPATH 缺少 `apps/api/python` 在导入阶段失败；修正测试入口后通过，未修改生产代码。另一次八项既有测试批次未取到终态回执，不计入通过数量、未重复运行该批次。完整证据与复现方式见 [RESEARCH](RESEARCH.md#2026-09-28-在线生成文档修订来源不变生成快照可更新)。

这些设计阶段证据解决了旧版的不变性矛盾，并验证了复用接点；**它们本身不证明 prefix 包装、IPC 接线、最大规模性能或真实复跑通过。** 后续实施的 prefix/IPC/受控普通执行及有界 500 动作样本回执见 [PROGRESS](PROGRESS.md) 与 [RESEARCH](RESEARCH.md)，真实首次验收仍未完成。不再把“是否允许改草稿”“最终是否可以重算”留为待决项。
