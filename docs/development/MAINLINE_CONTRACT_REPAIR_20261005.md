4. 接通 Python 来源、TypeScript 准入/物化、在线生成、代表输出与正式输出；同一操作不额外重派，缺证据停止发布。

## 实际实现与首败补充

- 列表输出包含宿主生成的内部稳定键，按真实链接优先建立身份；最终交付不含该键。数组页预算 300、业务 `take`、代表样本 3 和计划逐项预算分别保存。未声明最终上限的计划采用 10,000 次逐项技术上界，超出明确阻塞，不静默截断。
- 明确缺失使用可选对象字段，值缺失时省略；兼容已确认稿中“；缺失时/无法确认时标记缺失”的明确声明。新稿支持 `（数字，可缺失）` 与 `- 结果数量：最多 N 条`，宿主只解析声明语法。
- 对象读取复用原 ReadSpec 和 input ValueBinding：宿主登记同名同类型的 inheritFields，真实运行绑定完整单项输入，读取器只复制声明的本次字段，保持可选缺省，再校验完整结果。原有 output assembly 与 data.merge/assemble 仍承担其他结果组合；未增加控制器或通用合并引擎。
- 消费者就绪检查与正式字段读取必须接收同一运行输入；导航按本条输入入口参数化，不能依赖上一条详情页或样本列表下标。
- 原生 Pydantic 输出使用 JSON 别名，保护下划线/方法同名字段；嵌套对象缺省不会序列化成非法 null，真实 null 字段保留。
- 启动前源码前检失败明确记录“未创建本次资源”，不能留下虚假 cleanup_required；已有 runner 的未知清理仍严格保留独立事实。
- 首次原生样本 eBW2sf：读成功但内部字段名被 Pydantic 拒绝，done 失败；xlhQC7：草案形成，第二条的页面入口/可缺失标量读取不成立；GBKvsC：开发中修改源码清单产生前检失败，未创建运行资源却被原逻辑挂清理占用。分别修复后 xvOoHZ 的正式 prepare_task → 在线编译 → 自动代表试跑/独立复验 → 变更到 2 项现场试跑全部完成；原首败保留。

## 对抗审查后的补充修复

- R1：最终结果不要求链接时，中间合同仍必须允许真实导航入口。增加仅中间使用的 `__batRecordEntry`；入口优先建立身份。无链接记录按页面与原始位置建立本运行身份，不能把两条空记录摘要去重为一条。
- R2：代表输入拥有字段不等于输入合同保证所有条目都有。直接继承必填结果必须有 input.required 保证；否则对象读取要登记真实 DOM fallback。准备阶段验证 fallback 的投影和类型，正式阶段本项已有字段直接使用，缺失才读取 fallback。纯输入 completion、静态绑定、TS 来源准入同时限制路径存在性，防止绕过。
- 补验仅覆盖上述两个审查反例及发布后从持久化链路复跑；不重跑全量验证。
- R2 复审反向项：继承候选来自输入 schema，不能来自代表输入实际存在的键；代表缺字段时验证 DOM fallback，后续已有输入优先使用。
- 实际京东验证：集合发现完成，详情导航 `https://item.jd.com/100409670464.html` 实际落到同路径追加 `?purchasetab=gfgm`，原精确相等误判。修正物理导航合同：同协议/域名/端口/路径/fragment，保留所有已指定查询键及多值，仅允许服务器新增查询键；显式 equals URL 检查仍严格。采集、编译和正式后置检查复用同一固定匹配，消费者作用域绑定本次实际文档，不重派导航。数值投影失败返回固定字段错误，禁止裸 ValueError 隐藏首因。
- 实际京东第二次验证：商品读取成功，但固定排序控件被整个页面同 class 布局祖先当作业务集合而拒绝。保留动态记录守卫；复用原 Browser-Use accessible-name/history identity 与现有“常量必须来自确认需求”的授权边界：仅当目标完整名称是已确认需求里的字面常量、同文档同标签唯一、与原生 axNameDigest 相符时，记录固定目标证据。正式复跑按该名称唯一定位，不能用旧 XPath/弱 hash 绕过名称变化或重复。未提供此证据的业务条目仍必须完整读取与绑定。没有网站类名/关键词表或新控制器。
