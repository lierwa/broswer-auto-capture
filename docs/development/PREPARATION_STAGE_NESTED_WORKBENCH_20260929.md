## 0. 本轮唯一结论

当前准备画布把每个在线编译节点作为顶层 React Flow 动作卡并使用 LR 布局；节点增长到二三十个时会形成无法阅读的横向长链。完整编译完成后，系统才创建 `ChainPresentation`，画布随后切换为阶段视图。只修改最终阶段卡不能解决准备期长链。

本轮替换路线固定为：

1. 每个有效 prefix build 都由 API 尝试生成**可变的阶段展示内容**，Workbench 从准备开始就显示“阶段父节点 + 子动作列表”。若该次 prefix 投影失败，仍必须保存已校验的 nodes/edges 并完成原 ACK，由服务端投影为单个“未分组动作”父节点；不得因展示错误中断 B-U 或编译。
2. prefix 展示只表达当前已校验、已闭合的节点和真实边，不伪造入口、终点、成功状态或可运行权限。
3. final 编译使用完整 TaskChain 生成并校验正式阶段内容；正式内容在样本复跑开始前封存。
4. 同一 candidate/version 的草稿、样本复跑、独立复验、发布和正式运行复用同一份 final 阶段内容，只更新节点与阶段运行状态，不自动重新分组或重新布局。用户显式发起 revision 时形成新 candidate 和新 presentation/checksum；旧版本、旧运行和旧布局不改写。
5. 阶段父节点是 React Flow 节点；子动作是父节点内部的语义化列表行，不是总览里的第二批 React Flow 节点。按 2026-09-30 最新要求，条件、分支、循环范围及本次走向直接在对应子节点说明，不再增加“展开路径”、重复路由列表或内部子图。说明必须引用真实 nodeId、条件、边和运行事实，不按列表顺序编造路线。
6. 所有阶段，包括只有一个动作的阶段，使用同一父节点结构。废止“单动作阶段扁平化为动作卡”的现行投影。

如果 final build 的阶段内容不能通过完整 `validateChainPresentation`，准备必须在创建草稿和样本复跑之前失败并保留原因；不得静默重新分组、回退平铺长链或修改 TaskChain 使展示通过。

## 4. 准备到运行的唯一展示时序

```text
B-U 已派发动作与现场证据
  -> prefix checkpoint
  -> materializeHybridPrefix：已闭合 nodes/edges
  -> createPreparationPresentation：可变 stages/layout
     投影失败 -> 保留 nodes/edges，服务端投影单个“未分组动作”阶段
  -> 保存同一个 job.authoring.build
  -> Workbench：阶段父节点 + 当前子动作，状态为“生成中”

B-U 完成当前 PlanStep
  -> final checkpoint
  -> materializeHybridChain：完整 TaskChain
  -> createStepChainPresentation：完整、可校验的 final stages/layout
  -> 保存 final build presentation
  -> 后续候选链再次物化并核对 chain digest + presentation content 完全一致
  -> createTaskDraft
  -> 样本复跑 / 独立复验 / 发布 / 正式运行
  -> 同一 candidate/version 只更新该 presentation 上的运行状态和结果，不重组结构
  -> 显式 revision 创建新 candidate 与新 presentation/checksum，不改写旧版本
```

这里存在两个不同事实，不能混写：

- `build.presentation`：准备 job 当前可变快照的一部分，没有 chain reference、presentation digest、运行入口或发布权限。
- `ChainPresentation`：绑定精确 chain id/version/digest 的正式展示事实，进入草稿 checksum，发布后不可变。

Workbench 可以复用同一渲染 Module，但必须依据 `build.phase` 和是否存在正式 chain reference，分别显示“生成中”和正式运行状态。

## 5. presentation Module 与合同修改

### 5.1 Seam 与 Interface

阶段分组的唯一 Seam 保持在 `apps/api/src/task-chain/presentation.ts`。Workbench 不实现第二套分组算法。

建议的内部 Interface：

```ts
type PreparationPresentationInput = {
  step: Pick<TaskPlanStep, "id" | "title" | "goal">
  nodes: StableChainNodeV2[]
  edges: ChainEdgeV2[]
  previous?: ChainPresentationContent
}

function createPreparationPresentation(
  input: PreparationPresentationInput,
): ChainPresentationContent

function createStepChainPresentation(
  chain: TaskChain,
  step: Pick<TaskPlanStep, "id" | "title" | "goal">,
): ChainPresentation
```

两个入口共用私有的阶段候选、节点标题、连通性、稳定身份和布局实现；prefix 入口不接受 completion、terminal 或发布引用，final 入口继续执行完整校验。不要新增 `StageCompiler`、新数据库表、前端分组器或额外模型接口。

### 5.2 build 合同

复用现有 `ChainPresentationContent`，只在当前 build 增加一个字段：

```ts
build: {
  stepId: string
  sequence: number
  digest: string
  phase: "prefix" | "final"
  nodes: StableChainNodeV2[]
  edges: ChainEdgeV2[]
  presentation?: ChainPresentationContent
}
```

持久化字段保持 optional，同时兼容旧 job 和 prefix 投影异常。新 prefix 正常路径写入 presentation；但投影异常不得拒绝已合法的编译快照，必须先保存 nodes/edges 并完成原 ACK。`projectActivity` 对旧 build 或该次缺失 presentation 时，在服务端统一投影一个“未分组动作”阶段父节点，不能回退为几十个顶层动作卡。公开 `TaskAuthoringActivity.build` 在归一化后始终带 presentation。final build 则必须写入并通过完整校验，否则不得创建草稿。

不增加新的阶段 schema、阶段状态枚举、节点字段、运行事件或数据库表。

### 5.3 prefix 分组规则

prefix 只对当前已物化 nodes/edges 分组，满足以下顺序：

1. 每个节点必须且只能出现一次；缺少合法归属时单独形成一个阶段父节点，不能隐藏。
2. 已有值绑定证明“读取/确定性选择只为当前浏览器动作提供输入”时，将这些支持节点与该动作放在一个阶段。
3. 已有控制边和原生合同证明 `input -> send_keys` 延续同一输入动作时可以合并。
4. 动作 postcondition 的 `consumerRef` 明确指向 readiness read 时，可以附在同一阶段。
5. 共享读取、跨阶段值依赖、分支或循环保持真实跨阶段关系，不复制节点，不为了列表好看强行合并。
6. output tail、completion 和 terminal 相关合并只在 final 执行；prefix 不生成“最终输出”阶段。
7. 标题只使用现有冻结动作、目标摘要、绑定和 Step goal；不得根据 URL、网站名、CSS class、Function 源码或坐标猜业务阶段。

准备阶段的分组允许在新证据到达后变化，但必须保持以下稳定性：

- 阶段 ID 由阶段锚点 nodeId 的安全短摘要生成，不使用 `stage-1/stage-2` 位置序号。
- previous 中仍合法的节点归属、阶段 ID 和坐标保持不变；新节点只加入有真实归属的阶段或形成新阶段。
- 新边使旧阶段违反单入口或连通性时，只重算受影响阶段并保留其它阶段位置；禁止整张画布 remount。
- 当前 `canvasKey` 继续绑定 authoring job + step，不包含 build sequence。
- prefix 阶段状态统一为“生成中/已生成”，不得显示运行成功、跳过或完成终点。

### 5.4 final 封存和一致性门

final checkpoint 已经物化完整 TaskChain。此时：

1. 使用完整入口、completion、terminal、全部绑定消费者和真实边生成 final `ChainPresentation`。
2. 将其 content 保存进 final build，并在 Workbench 显示；这一步发生在样本复跑之前。
3. `AuthoringBuild.finish` 将 final presentation content 随已验证编译结果交给后续候选链创建。
4. 后续生成的 chain 必须与 final build 的 chain digest 一致；`createChainPresentation(chain, savedContent)` 必须通过现有完整校验。
5. 任何 digest、阶段覆盖、入口、出口或布局身份不一致都在创建草稿前失败。不得调用模型修复，不得重新执行 B-U，不得静默使用另一份分组。
6. 同一 candidate/version 的样本、复验、发布和正式运行只能读取该 presentation；运行事件不得触发 regroup 或自动布局。用户显式修订链路时，新 revision draft 以当前 presentation 为基线，只对新 candidate 生成新 checksum/presentation 并重新验证；不得把“final 封存”解释为禁止现有 revision 能力。

这个门保证准备期 final 画面与复跑画面是同一个结构，不出现“复跑开始后节点突然换组”。

## 6. 画布结构和布局

### 6.1 React Flow 节点层级

final/草稿/发布/运行总览有三类 React Flow 节点：开始、阶段、结束。prefix 没有完整入口和 terminal，只显示当前阶段父节点及已证明的阶段间边，不生成开始/结束辅助节点。阶段卡内部的子动作是 DOM 列表行，不注册 React Flow Handle，也不参与 Dagre 节点数量。

```text
                阶段父节点
        target ●────────────────────● source
               │ 04 进入目标仓库   │  <- 标题区；端口位于该区垂直中心
               ├────────────────────┤
               │ 读取搜索候选       │
               │ 选择目标仓库       │
               │ 点击选中的仓库     │
               └────────────────────┘
```

必须满足：

- 父节点 target/source Handle 位于标题区垂直中心，不是整张动态高度卡片的中心。
- 阶段间连线只连接阶段父节点；内部子动作不生成总览连线。
- 所有阶段，包括一个子动作的阶段，都使用相同父节点外壳。
- 阶段宽度由 Workbench 密度 token 固定在可读范围；高度为标题区加动作行实际高度。
- 子动作行显示动作类型/标题、必要的条件或循环释义、状态与可用耗时；耗时位于行右侧。已选中行持续高亮。不显示编辑输入框、原始 schema、内部 ID 或 JSON。
- 不通过增大画布、缩小字体或降低 minZoom 来容纳长链。

首版密度预算使用当前主题字号和间距，不沿用现有 300×148 阶段卡里的空摘要区：阶段父节点桌面宽度以 240px 为旧基准，标题区 42–46px，普通动作行 30–34px，水平阶段间距 44–56px。条件/循环行可按释义自然增高，不能强行套单行高度裁掉条件。不得保留固定最小高度制造空白，也不得靠缩小字体容纳信息；具体密度属于待确认的视觉方案。

### 6.2 布局

Dagre 仍只布局父阶段节点及阶段间真实边。节点高度使用实际测量值或与动作行数一致的确定值；方向仍可沿当前 LR，但屏效比由父节点数量而不是动作数量决定。

准备快照更新时：

- 相同 stageId 保持当前位置；高度增加只推动必要的下游节点。
- 新阶段追加到真实控制流位置。
- 只在阶段身份/真实边改变时重新布局；运行状态、耗时和选中变化不布局。
- 不因 build sequence 改变重新 fitView；首次载入和用户主动“适应视图”才 fitView。
- MiniMap、缩放、平移、亮暗主题继续复用 React Flow。

## 7. 点击与节点详情

阶段父节点和子动作有不同点击结果：

- 点击标题区：选择阶段，详情显示阶段目的、准备/final 状态、动作数量、已知入口和真实出口摘要。
- 点击子动作行：选择真实 nodeId，详情显示该动作；不得同时选择父阶段。
- 不再提供“展开路径”操作；必要的控制关系直接显示在对应子动作行，点击该行仍只选择并查看真实节点。

动作详情首屏只展示用户判断需要的事实：

1. 动作：具体执行什么；
2. 目标：作用于什么页面/控件/数据范围；
3. 输入来自：任务输入、常量、前一节点还是变量；
4. 条件和出口：成功条件、业务分支、人工等待或失败路由；
5. 本次运行：排队、运行、成功、失败、跳过或等待人工；
6. 本次节点输出：完成态事件没有持久化节点值时明确显示“本次节点输出未记录”；不得把 `outputContract`、schema 或节点配置当成实际结果。只有当前 checkpoint 确实保留该 nodeId 的 `nodeOutputs` 时，才可标明它是未完成运行的检查点值；
耗时只显示在对应画布阶段/子节点右侧，不再列在详情面板。时间从同 invocation 的 started/finished 事件计算；缺事件不显示假 `0 秒`。

Function 详情应具名展示参数及绑定来源、返回值要求，并提供独立可展开的“函数代码”区，不再要求从整份 JSON 找源码。真实运行参数/返回值与定义分开，有缺失时明确说明。原始节点 JSON、原始 schema、prompt、内部 ID、digest 和完整事件仍放在折叠的高级信息。取消的是额外路径展开，不是源码/JSON 的折叠查看。父节点已经包含动作列表后，阶段详情不再重复渲染相同列表。

准备阶段没有 execution：详情显示“生成中的节点”、真实输入来源和当前已知下一动作；不显示“本次运行成功”或虚构耗时。

## 8. 最终输出展示

结果区域独立于画布选择，不放进最后一个阶段节点。唯一事实源是所选 `TaskExecution.result` 与该 execution 精确绑定的 `TaskPlan.outputContract`。Step 的 `resultSpec` 只有在现有 plan output binding 能证明字段路径映射时才补充字段说明；多步骤聚合不能按同名字段猜归属。

当前实现主要覆盖完成回执、单条记录和记录列表，标量与 artifact 存在兼容分支。这是能力现状，不是产品输出只能有这些形式。按最新需求，输出表示用户约定的成果交付：可为浏览器现场、值、文件或组合，不按网站/业务分类写死。任务完成条件、交付内容与形式、浏览器结束后处置须分开约定。Excel/Markdown 是格式例子，不是本次已选定格式；正式产物生成、打开或下载未验证时不得声称已接通。

“去哪里看结果”固定为已有 execution 上下文，不再发明结果节点：

- 所选 execution 已有 `result` 时，链路工具栏显示“查看最终输出”；点击现有结束 terminal 也打开同一个结果上下文。
- 现有右侧 `WorkbenchContext` 可作为预览入口；多记录或长内容不能全挤进窄栏。宽结果区、记录详情、分页及下载是待确认交互提案，不能写成已冻结方案或现有能力。
- 面板标题明确写“本次结果”，同时显示 execution 状态；数据任务紧接着展示业务结果，操作任务展示完成回执。用户无需选择 `output-assemble`、打开节点 JSON 或猜哪个节点是结果。
- 切换历史 execution 时，面板必须随选择重新绑定；不得显示其它运行的最新结果。

| 结果事实 | 展示 |
| --- | --- |
| `payload.mode = execution` | 完成步骤、总步骤和证据产物摘要；不伪造数据报告 |
| `payload.mode = data` 且 `output = null` | 明确显示“本次运行没有结构化结果”；失败时同时展示失败原因和已完成步骤 |
| `payload.mode = data` 且 `TaskOutput.kind = artifact` | 合同兼容态只展示现有 `mediaType`、`artifactId` 和 digest；当前正式 Plan 执行器尚不产出该结果，只有已有读取/打开能力时才显示对应操作，不伪造文件名、预览或下载 |
| `payload.mode = data` 且 `TaskOutput.kind = value`、schema 为 object | 记录详情；字段顺序按 schema/resultSpec，长字符串使用可阅读正文块，不显示 JSON 花括号 |
| `payload.mode = data` 且 `TaskOutput.kind = value`、schema 为 array | 记录列表；同构 object 可使用表格/列表切换，长正文留在单项详情，不把整批 JSON 塞进页面 |
| `payload.mode = data` 且 `TaskOutput.kind = value`、schema 为 string/number/boolean | 历史/导入兼容的文本或单值结果卡；不增加新的正式需求形状 |

字段标题在绑定路径可证明时使用对应 `resultSpec.fields[].description`；否则使用输出合同字段名。不得按网站、商品、Issue、文章等业务键写 renderer special case，也不得为决定展示类型增加模型调用。

当前“标题 + 正文”的单记录任务应表现为可直接阅读的一条记录：标题字段与正文内容在结果区展开，原始值只在高级信息中查看。

## 12. 验收标准

以下全部满足才可称本次改造完成：

1. 准备期第一个有效 build 起就显示阶段父节点和子动作列表。
2. prefix 顶层 React Flow 节点数等于当前阶段数；final/草稿/发布/运行总览才等于阶段数加开始/结束辅助节点，二者都不等于动作数。
3. 每个动作恰好出现一次，点击子动作定位真实 nodeId。
4. 每个阶段，包括单动作阶段，具有相同父节点结构。
5. 阶段输入/输出 Handle 位于标题区垂直中心，阶段间边来自真实 TaskChain/build edge。
6. prefix 不出现假成功、假终点、运行耗时或发布权限。
7. final build 与草稿 presentation 的阶段 ID、节点归属、入口、出口和布局一致。
8. 样本、复验、发布和正式运行不会触发重新分组或全图自动布局。
9. TaskChain executable digest、运行节点/边、模型调用和浏览器命令不因展示改动变化。
10. 节点详情首屏只显示动作、目标、输入绑定、条件/路由以及当前确实持久化的运行事实；没有节点实际输出时明确写“未记录”，JSON 只在高级信息。
11. 完成回执、单记录和记录列表有正式可读展示；标量与 artifact 有不夸大能力的兼容展示；当前标题/正文任务无需查看 JSON。
12. 亮暗主题、键盘、触屏/窄屏、reduced-motion 和 React Flow 控件保持可用。
13. 所属聚焦测试、受影响 workspace typecheck 和 `git diff --check` 通过；未授权的全量测试不运行。
14. 正式 Workbench 新任务证明准备期嵌套、final 一致、普通复跑和结果展示；旧成功与旧失败记录均未改写。
15. 条件、分支和循环在子节点中直接可读；没有额外“展开路径”按钮、第二份路由列表、内部子图或整图切换。
16. 显式 revision 产生新 candidate/presentation/checksum 并重验；旧 candidate、发布版本和历史运行展示不变。

## 13. 停止条件与补救责任

### 15.3 子节点直接表达什么

保留阶段父卡 + 子节点行，不增加路径展开按钮、重复路由列表、内部子图或另一张画布。不是给每行机械加三句文字，而是按真实节点类型安排操作、规则和本次事实。完整行结构、取值来源、选中反馈、重复执行口径及无法表示的边界见第 16.2、16.3、16.7 节。

没有节点事件不能直接写“已跳过”；没有循环进度不能写“3/5”；只有分支出口不能声称保存了判断输入。当前发布 V5 没有独立条件、分支或循环节点，不能把之前的示例当成这条任务需要新增的节点。

### 15.4 输出/交付的统一边界

输出不是必然生成一张表，也不要求每个任务都有组装节点。结束负责结束链路，交付负责把已约定成果给用户；两者可以在结束节点的结果入口统一查看，但语义与事实分开。

1. 需求对话确认任务要做到哪里、交付什么、需要什么形式，以及浏览器结束后如何处置。只有影响结果的重要歧义才继续问；不能把需求确认变成填写 URL、selector 或 JSON。
2. 活页面交付：结束自动化后保留原标签页和约定状态，交还控制；不因释放自动化资源而关闭用户 Chrome、页面或停止播放。“回到原页面”必须指向同一现场，不是重新打开一个 URL。
3. 数据/文件交付：字段与数量属于任务版本数据；如果用户要求 Excel、Markdown 或其它产物，必须有真实生成、校验、保存和可取用入口。现有 artifact 引用或表格预览不能冒充已生成文件。
4. 未指定格式时不能机械给每个任务添加文件输出；需要文件但格式会影响使用时，在需求对话确认支持的交付方式。支持方式尚未实现应如实说明，不能先承诺再用 JSON 代替。
5. 单条、集合、文本、文件与现场可能组合；查看方式据实际交付安排。宽结果区、列表分页、文件预览等是本轮助手提案，尚待用户确认，不作为固定交付类别。
6. 合法完成、用户满意、页面交付、资源清理分别记账；不增加结尾全局模型 judge，不因清理失败抹掉业务结果，也不将“有 keep_open 字段”称为真实留页验收通过。

### 16.2 子节点的固定结构与查看行为

**每行只有一个实际动作节点身份。** 外层阶段仍是 React Flow 节点，子节点是引用该 nodeId 的列表行；没有独立 Handle，不伪装为已经画出的内部流程图。

```text
阶段：完成这个业务步骤                          状态    阶段用时
┌─────────────────────────────────────────────────────────┐
│ 状态图标  类型  动作名称                         状态  用时 │  主行
│                 与该类型有关的关键定义                    │  有需要才显示
│                 本次事实或具体异常                        │  有证据才显示
└─────────────────────────────────────────────────────────┘
```

1. 主行从左到右是状态图标、类型、名称、短状态、耗时。名称承担“干什么”，类型承担“通过什么机制干”；不能只靠绿点区分完成与未执行。耗时固定在右侧，等宽数字，不能被长名称挤掉。

3. 定义摘要用次级文字；本次失败、等待或所选出口单独标识。运行事实与定义并存时分别标“规则”“本次”，不能把“要求可见”写成“已可见”。无实际值不填样例值，`null`、空串、`false`、`0` 都不是“未记录”。

5. 点击整行只选择和查看；同一渲染周期立即高亮，详情读取中显示读取状态，失败显示读取错误。不会启动、重试、修改、发布或跳转浏览器。再点同一行不关闭面板；点另一行切换；关闭详情清除选中，点击空白清除选中。
6. 父卡标题点击选择阶段而非某个子节点；子行点击不冒泡把它改选成父卡。Tab 可到达行，Enter/Space 查看，焦点轮廓与持续选中区分。拖动画布不应误触查看。

9. 默认全部子行可见。规则过长时画布给可追溯摘要，完整规则在该节点的正常详情中查看；这不是另加路径面板或“展开”操作。不得把阶段外出口全部重列一遍冒充流程。

| 子链 Invoke | 被调用链的名称和精确版本；一次或逐项；逐项失败策略 | 当前调用、成功/失败项数仅据已有进度 | 输入绑定、集合/每项参数、被调用版本、确切子运行、返回及恢复状态；不复制 N 份链路 |
| 数据处理/输出发布 | 真正执行的变换和去向，例如“把来源 A/B 映射到约定字段”，不一律叫组装 | 保存的产出摘要；无记录就说明 | 具名来源到目标的对应关系、计算/映射规则、产物或值的可取用入口 |
| 显式 LLM | 调用目的和模型；不是普通节点异常兜底 | 真实调用状态及已保存返回 | 固定 prompt 独立折叠、输入绑定、输出要求和实际审计；不新增模型解释/重试 |
| 人工/检查点（含历史节点） | 为什么停、用户要做什么、已有恢复条件 | 等待/恢复事实；不能显示“继续必成功” | 当前等待说明、停止现场、继续条件及核验结论；恢复走原运行，不新开一份任务 |

**条件行不是“小型流程图”。** 一个二路判断可在行里写“存在 → 处理下一项；不存在 → 收尾”，本次行写“已选：不存在 → 收尾”。多路 Branch 按保存的顺序解释，默认仅给短规则/出口摘要，完整有序 case 放正常详情；不能按字母排序改变判断优先级。出口为 `failed` 是求值出错，不是“条件不满足”。没有真实边就不画/写虚构去向。

**循环行不是“把同一个动作复制很多遍”。** 它说明哪一个循环体被重复、为什么继续、何时停。普通循环体动作可以附“属于 ×× 循环”的可点击定位引用；仅当归属能由真实 body/控制结构可靠确定时显示，不按列表相邻推断。嵌套循环分别指明所属范围，当前轮次无法唯一归属时不混成一个总进度。

### 16.4 开始：看这次怎么进入，不是假装又执行一步

**语义**：画布“开始”是链路入口投影，连接 `chain.entry`，不是 TaskChain 中新增的 start 节点。它解释采用哪个版本、什么输入、需要什么运行环境、从哪里进入。检查由现有服务端和浏览器能力承担，UI 只展示，不自己再执行一次。

**画布卡提案**：扩大现有只有绿点的胶囊为可点击紧凑入口卡；两行摘要即可，细节在右侧。开始没有独立 started/finished 事件，因此不显示 0 毫秒或虚拟耗时。

```text
开始                                           待运行
版本 Vx · 输入 2 项 · 入口：第一阶段名称
```

数字是该合同的真实输入项摘要，不是固定参数数量；无参数写“无需参数”。复杂输入只概述，不能用对象顶层键数宣称所有必填参数均齐全。

| 场景 | 卡上显示 | 点击后显示 / 禁止行为 |
| --- | --- | --- |
| prefix 正在生成、没有完整入口 | 不生成正式开始卡；保留“生成中”状态 | 没有启动权限，不补默认入口或假输入 |
| 完整候选/草稿，尚无本次运行 | “开始 · 未运行”及入口；候选身份明确 | 输入要求、草稿试跑预设及未提供项；只能叫预设，不叫实际输入 |
| 已发布版本，尚未选运行 | “开始 · 待运行”及版本/入口 | 当前运行预设、进入约束；浏览器连接未验证就写“运行时检查”，不预先亮绿 |
| 点击运行、请求尚未接受 | 运行主按钮 immediate busy；开始仅表示提交中 | 不创建本地假 run；失败展示请求错误，没有 node 事件不能写入口已执行 |
| 已接受 execution，当前步骤未开始 | “开始 · 已排队”或“待上游输入” | 有该调用已保存的 TaskRun.input 就可展示实际输入；否则 execution 输入与该步骤待绑定输入分开，未产生的上游数据不能冒充已知实参 |
| 选定 TaskRun 已开始/结束 | “开始 · 已进入”；版本和入口稳定 | 该 run.input 是本次链路实际输入；不可用后来改过的 preset、草稿或别次执行输入代替 |
| 启动检查拒绝、尚无 TaskRun | “开始 · 未进入”，旁示已有原因 | 显示版本/合同/连接等确切失败归属；不会把第一动作标成失败或生成一条虚构已执行边 |
| 历史记录不足 | “开始 · 输入记录不完整”或实际可得摘要 | 展示能确认的输入层级及缺口，不能反算历史实际参数 |

**开始详情的固定顺序**：

1. **这次使用什么**：所选发布/候选版本、所选运行用途与身份摘要，入口阶段/真实动作定位；不把候选称为正式发布版本。
2. **输入**：有 run 时按输入合同展示实际具名值；没有 run 时展示定义/预设/缺项。动态字段来自合同，敏感值按授权遮蔽。显示输入来自用户、上游结果或保存预设的事实来源，不把常量称为用户填写。
3. **进入要求**：已确认来源范围、`reuseBoundary.assumptions/invalidationConditions`、所用浏览器要求、链路/计划身份与输入校验。业务约束是声明，只有实际检查回执才能标“已核验”。不把所有 assumptions 都自动变成新增可执行检查。
4. **本次进入检查**：服务端已经保存的成功/拒绝信息及问题归属；未逐项保存时明确“仅保存整体接单/输入校验事实，未保存逐项检查回执”。显示无法连接时的具体问题，不再次创建权限问题、私有 profile 或重启 Chrome。
5. **高级信息**：精确版本引用/digest、原始合同与安全诊断。面板不放耗时、不创建第二个“运行”按钮；正式运行主操作仍在工作台工具栏。

链路在某步骤逐项调用时，开始面板指向所选调用的输入。整次计划输入不能冒充每项链路输入；上游未产生的输入不能在运行前显示为已提供。

提交新运行请求失败时，保留原来所选历史运行的输入、状态和结果，在运行操作处显示本次请求错误；只有收到新 execution 引用才切换画布绑定。不得把请求失败的临时状态刷到上一次成功运行的开始卡上。

### 16.5 结束：看为什么停、停到哪里、交付什么

**语义**：每个结束卡对应实际 terminal 的精确身份和声明状态，不能把 failed/partial/blocked/cancelled 合并成“完成”。终点绑定并校验约定返回值，结束当前链路调用；它不是再次抓页面、再次调用模型验收，或每个任务强制生成文件的动作。

**画布卡提案**：首行保留终态名称和到达状态，右侧耗时仅用该 terminal 的真实事件配对；第二行在可确认时给本终点结果摘要与可点击“查看结果”。终点处理时间不冒充整个任务总用时。

```text
完成                                           已到达   0 毫秒
本步骤结果：集合，共 N 项                         查看结果
```

此处是结构示意，N、耗时和结果形状不得写死；没有真实数量就不显示数字。无业务数据的操作任务可以写“自动化已结束 · 原页面交付已确认”，仅限确有页面交付回执；只有合法终点事实时只写“链路已完成”。

| 场景 | 卡上/面板显示 | 结果入口行为 |
| --- | --- | --- |
| 未运行 | 终点声明“完成/部分完成/受阻…”及“未到达” | 点击看结束定义：上游来源、输出约定和浏览器处置；不展示样例当结果 |
| 运行中，终点未到达 | “未到达”，无完成耗时 | 查看已保存进度，结果未形成说明未形成；不能先染绿色 |
| 已到达 completed，当前链路无输出错误 | “完成 · 已到达” | 看本次实际步骤结果；整次任务尚有后续步骤时明确“本步骤完成，任务仍在运行” |
| 多个声明终点，只经过一个 | 到达的终点按事实标识，其它“未到达” | 每个终点详情保持各自规则，不能给所有终点套同一个成功结果 |
| 在终点前发生节点/合同/运行时失败 | 声明的 completed 卡仍“未到达”；运行状态区突出实际停止节点/原因 | 点击也能查看本次停止原因及已保存部分成果，但标题明确“运行提前停止，此终点未执行”；不伪造 failed terminal |
| 到达 partial/failed/blocked/cancelled terminal | 按真实声明和到达事实显示，不写完成 | 展示真实原因、剩余范围和可确认的部分成果；未保存部分成果则明确没有记录 |
| waiting_for_human / paused | 终点仍未到达，突出实际等待节点 | 给已有人工等待/同运行恢复入口；不宣称任务结束、不无条件重派动作 |
| completed，但现场交付 unavailable/pending | 完成事实保留，附“页面交付未确认” | 结果与交付异常并列；不再开页面假装交付、不覆盖 TaskRun，不偷偷补浏览器操作 |
| completed，但 cleanup_required | 完成事实保留，附“运行资源释放待确认” | 已得结果仍能查看，清理问题单列；不改成链路失败、不丢结果、不用模型修复清理 |
| 历史结果/合同身份不匹配 | 明确“该结果无法按所选版本解释” | 不拿最新 schema 套旧结果、不借别次成功结果填空；保留安全诊断 |

**结束详情/结果视图的固定顺序**：

1. **本次停在哪里**：所选 execution/步骤调用、该终点声明和是否到达；实际到达终点或提前停止位置及原因。合法完成、人工等待、失败都用准确中文，不只给一行 `completed`。
2. **约定做到什么**：已确认结果要求与浏览器处置、terminal 的结果来源/合同。旧 `chain/step/plan.completion` 只作为准备验证/期望定义展示，不能写成“结束前逐条再次核验”。
3. **实际交付**：当前调用 output 或整次 execution 最终 result，按层级分开。数据的字段来自精确合同，文件必须真实存在可取用，现场必须有原目标交付事实；可组合，不按任务网站分支。
4. **交付/生命周期异常**：仅有异常或未确认时提示，不在正常结果底部堆英文码。页面交付、清理与链路结论独立；保存的部分输出明确“部分”，不能冒充全量覆盖。
5. **高级信息**：原始 terminal、所选事件、精确版本/输出合同引用及安全错误码。耗时只在画布节点右侧；不要在详情加另一张耗时表。

**进入结果的具体操作提案**：结束卡整体点击打开终点详情；“查看结果”和工作台已有结果入口打开同一份、绑定当前 execution/call 的结果视图，不创建第二份结果状态。单步骤任务可以直接定位最终交付；多步骤/逐项时先展示本步骤/本项结果，并提供“整次任务结果”明确导航，不能混淆层级。

终点的 finished 事件不能单独证明 completed：必须与该调用的终态结论及终点引用一致。终点返回/必要引用处理发生错误时显示实际错误，不仅凭名称或一条 success 事件判完成；证据残缺则明确残缺，不填造到达事实。

- 活页面：若确有同一现场定位/聚焦能力才给“回到原页面”；它只能选中原目标，不 navigate、不新建 tab、不结束播放。当前仅 lease/targetDigest 并不证明已有可用聚焦入口，能力不足先显示已保存的交付事实和缺口。
- 数据：普通值/文本完整可读；集合用独立宽结果区呈现记录与记录详情，不把全部长正文塞在终点卡或窄侧栏。列来自合同而非标题/正文固定字段；分页/窗口化只是查看已有数据，不自动追加抓取。具体布局与批量加载范围仍是此次待对齐提案。
- 文件：展示真实产物的名称、格式和可取用动作；没有产物生成/取用链路就标能力缺口，不显示假下载按钮、不把 JSON 改后缀冒充 Excel。
- 无数据/文件、也没约定现场交付：展示实际动作完成回执，明确本任务没有另产出数据文件，不添加“组装输出”凑步骤。

### 16.6 前置、后置、就绪、分支、结束：分别归哪里

“都有条件”不意味着它们都是 Condition 节点。展示的条件必须按作用和执行所有者归属，不能从界面排版生成一套新检查系统。

| 条件/约束 | 所在位置 | 谁负责、何时判断 | 没满足如何显示 |
| --- | --- | --- | --- |
| 运行准入：身份、当前版本、输入合同、授权范围及资源冲突 | 开始详情/运行主操作 | 现有服务端接单与运行入口；不是画布点击 | 未进入及具体拒绝原因；若无 run，不画第一节点执行失败 |
| 声明复用假设：允许的来源/页面范围、失效边界 | 开始详情的进入要求 | 随链路保存；仅有对应真实检查时才是运行检查 | “声明要求”或实际核验事实；不能直接全部标通过 |
| 动作前目标/页面作用域核验 | 所属动作的条件区；画布有关键约束才写“执行前：…” | 已有浏览器能力与 runtime scope；在该动作派发前 | 未派发、目标缺失/不唯一、身份失配等；不能自动换页或让模型救场 |
| 动作后要求/下游消费就绪 | 生产动作说明“执行后：…”；真实 consumer 引用可定位 | 已有 postcondition/readiness 与有界观察；动作只派发一次 | 已派发但完成/就绪未确认；与“尚未派发”分开，不靠重试重做动作 |
| Condition/Branch 的业务路径规则 | 它自己的子节点行和详情 | 读取已绑定值，选择实际 port；不额外观察页面 | 正常 false/default 是另一条路径；求值失败才是错误 |
| Loop 的继续、停止、最大次数 | Loop 自己的行和详情 | 既有循环节点/LangGraph；每轮按版本定义推进 | done、limit、failed 分开；不能把技术上限到达当业务全部完成 |
| 人工处理后的恢复条件 | 实际等待节点/检查点详情 | 用户发起恢复后，现有恢复核验继续同一运行 | 尚未满足就保留等待/暂停；不重复已确认的外部副作用 |
| terminal 的返回绑定/合同/必要 evidence 引用 | 结束详情的结束定义 | 既有 runtime 进入 terminal 时解析绑定、校验输出/引用 | 绑定或合同错属于实际运行错误，不能因卡名“完成”染绿 |
| 用户要求的停止点/交付形式 | 结束详情的约定与实际交付 | 准备时已编入真实动作与终点，运行沿合法图结束 | 展示真实事实和用户独立意见；不追加全局语义 judge |

**同一个条件不执行两遍**：生产动作后置的“下游已经可读”可以成为下游动作的消费前提；详情分别说清“谁验证、谁消费”，通过引用表达同一个证明，不为两个面板各生成一个等待节点。UI 点击、选择或打开详情绝不触发 fresh browser check。

**当前 V5 的定点核查**（只读发布记录，不是新运行验收）：入口 `s-a-0001` 是 `browser.workflow-step`；终点 `completed` 通过 `output-assemble` 返回结果；没有独立 branch/condition/loop，capability 配置没有 `preconditions` 字段。浏览器动作保有 postconditions，多个读取通过 `runtimeScopeFrom` 关联上游，部分 postcondition 使用 `read_fields.ready + consumerRef`。因此正确方案是读其真实配置与关系，不凭空插入“开始前检查”“结束前检查”两个执行节点。

混合编译来源中的 `preconditions` 当前是自由记录数组，不是任意页面检查的统一 UI 协议。未经具体能力合同/descriptor 解释，不能遍历后就翻译成“通过”；无法解释则高级区只读并说明缺少结构化释义。结构化规则用既有 operator/绑定确定性描述；缺少业务标签时显示清楚的字段路径关系，不新增 LLM 造自然语言。

### 16.7 重复执行、耗时、未经过和缺失事件

1. **选择粒度**：页面绑定一个 execution；每个步骤/逐项调用绑定精确 runId + invocationId。切换调用时，开始输入、子节点事实、结束结果一起切换，不继续显示上一个调用的值。一个节点定义不因重复执行复制成多份。
2. **同一调用内多次执行**：按 nodeId、invocationId、stableKey 和事件 sequence 区分每次 started/finished；重复事件传输不重复累计。同一 idempotencyKey 可能再次出现，不能只按该 key 合并所有轮次；必须保持事件顺序与不重叠配对。
3. **计时提案口径**：单次节点用该次 started→finished 墙钟跨度；同一所选调用重复执行，右侧标“累计 ×× · N 次”，仅汇总完整配对。阶段右侧标“阶段跨度”，取该范围已有首/末边界，可能含等待，不能把它解释成 CPU 时间或把平行调用叠加。运行中写运行中，有 finished 缺 started 等情况写“耗时未记录/不完整”，不记 0；真实 0 合法。所有耗时只在对应画布节点右侧，详情不再重复。
4. **进度不同于耗时**：循环已完成项只据已持久完成稳定键/调用进度；重试不算完成新项。总数来自实际完整集合/已保存调用清单，未知时写“已完成 N 项，总数未记录”，不能把 `maxItems/maxIterations` 当分母。
5. **本次规则结果**：重复节点画布默认说明最近一次有记录的出口并标“最近一次”；详情按次序查看保存的出口/输入/输出，不把最后一次冒充全部迭代结论。所有调用均完成的综合事实只有独立聚合证据成立时才显示。
6. **未到达/未选择/跳过/缺记录**：未结束运行中的未来动作写待执行；终态且该节点没有执行记录只能写“无执行记录”。有确切分支控制事实可说“本次未进入此分支”，有明确 skip 回执才说“已跳过”；事件数据不完整时说记录不完整，不仅凭数组没找到事件断言业务跳过。
7. **缺失与值为空**：未执行、未记录、记录被脱敏/截断、真实空值分开。读到空列表是实际结果，不能当没有记录；只保存出口但没参数时可显示出口，参与值仍写未记录。
8. **恢复**：沿原 execution/run 接续。外部副作用不确定时只说明不确定，不用假 finished 事件补齐计时/结果，不让查看详情触发自动恢复。

### 16.8 详情面板的信息顺序与 Function 示例

普通节点详情统一四层：**动作/规则定义 → 输入和返回要求 → 本次已保存事实 → 高级信息**。实际等待或失败原因放在本次事实首部，不让用户翻整份 JSON 找原因。不同类型有不同字段，不渲染“目标：绑定的输入数据”这类空话。

Function 的方法、参数、输出按以下结构呈现；以下 `candidates/ordinal` 是当前选择函数的说明例子，不成为平台字段：

```text
按任务规则选择当前候选                 Function
所属阶段：……

输入定义
参数 candidates ← “读取候选”节点的完整输出集合
来源路径/类型/约束；常量参数应直接说明是常量

返回要求
整数；取值范围按这个节点保存的合同解释
下一动作的 ordinal 参数读取这个返回值

函数代码                                  [折叠/查看]
显示该版本保存的完整 JavaScript，等宽、可选择复制

本次执行
状态：已完成 / 失败 / 未执行
实际 candidates：有记录则查看；无记录明确“未记录”
实际返回：有记录则显示；不能用 schema 的示例整数代替

高级信息                                [折叠/查看]
版本引用、原始安全配置、对应事件
```

方法区不从高级 JSON 中让用户自行找 `source`；具名参数保留每个参数自己的来源、路径和常量，不因来源节点相同就去重丢掉参数名。返回要求与真实返回分区。普通 Function 不能读取浏览器/网络/文件，也不调用模型；如果实际节点是数据 capability，就按真实类型展示，不能为改善文案把它改称 Function。

两个现有“组合任务输出”的说明也按这个规则：一个把多个来源放入 value0/value1 临时对象，一个映射到最终合同；当前同结构读结果的这一条可提出恒等消除，但是否删由新候选的绑定/消费者验证决定，不在 UI 隐藏一行冒充编译已修复。

### 16.9 字段事实源与需要单独补齐的留存

| 显示内容 | 已有事实源 | 当前缺口 / 不允许的替代 |
| --- | --- | --- |
| 节点定义/入口/边/终点 | 所选不可变 TaskChain 与其 ChainPresentation | 不按列表顺序/DOM/标题重新推理图，不混用最新版本 |
| 操作释义与可编辑结构 | 精确 capability name/version 的 descriptor 和类型化配置 | 不扫描未知 JSON 造检查项，不加模型解释，不创造业务专用 UI 分支 |
| 本次链路输入 | 所选 TaskRun.input；计划输入为 TaskExecution.input | 以该调用是否已保存确定 input 为准，非首节点是否已执行；只有 execution 输入、默认值或未解析绑定时标对应层级，不能替代该调用实际输入 |
| 节点状态/出口/耗时 | 所选 run 内有序 events 与 invocation/stableKey | 节点 finished 的 success 只说明能力结果成功；不等于每条条件参与值已保存 |
| 终点是否到达 | 同一 run 的终点事件及 outcome/completionEvidence | 运行提前失败不能生成假 terminal 事件；cleanup_required 看保留的业务结论，不抹掉到达事实 |
| 最终步骤/任务输出 | 同版本绑定的 TaskRun.outputs / TaskExecution.output/result | 不从当前页面重读，不把最新 schema 或别次运行结果套进来 |
| 交付与清理 | TaskExecution.browserHandoff、cleanup/cleanupResume 及安全审计 | active 租约不是当前页面语义再次验证；没有聚焦原目标能力就不摆假入口 |
| 节点实际实参/返回/条件参与值 | 活动 checkpoint 只保存部分输出/变量；完成态没有完整逐次 I/O | 独立持久化缺口，必须单独设计，不称 UI 即可解决、不重算历史 |
| 精确循环进度/每次路径 | 已保存 invocations/checkpoint.loops 和有序事件可覆盖部分 | checkpoint 完成后释放，历史完整进度未必可得；不在前端建第二进度事实源 |

留存设计的**最低要求**是以真实消费者倒推：能查某次 Function 实参/返回、某次条件参与值/出口、某个实际动作的安全检查和效果回执。保存可引用的必要业务值或产物，不复制整页 DOM、浏览器 Profile、Cookie、验证码或所有供应商日志。日志不是节点 I/O 仓库；不能用“加字段以后可能有用”扩公共合同。

本稿没有冻结新 schema。实施前要写清生产者、记录发生点、唯一身份、脱敏/授权、大小限制、缺失/截断语义、读取消费者、旧记录兼容及最小验证；复用现有产品仓储/事件链，不加第二个 runtime、调度器或检查点数据库。实际源码/技术方案审核通过前，带实际值的 UI 只显示能证明的部分。

### 16.11 最小验收矩阵（获得实施授权后执行）

| 场景 | 必须观察到的不变量 |
| --- | --- |
| 未运行候选、已发布预设、prefix 未闭合 | 输入定义与实际输入不混淆；prefix 不伪造起止/运行权限 |
| 接单失败/版本失效/缺参数/浏览器未连接 | 请求即时有反馈；开始显示未进入及准确原因；不会误标第一动作已失败/创建假 run |
| 普通一条线、同名两动作 | 无路径展开/重复路由区；点击持续高亮且详情对应实际 ID；没有运行/修改副作用 |
| 有真实二路/多路分支 | 规则顺序、default、failed 区分；已选出口与去向正确；无参与值不填假值 |
| 有界 each/while、重复调用/恢复 | 一套节点，多次事实；重试不增完成数；不会把上限写成总数、混 run 或重复累计事件 |
| 已完成但缺节点 I/O 的旧运行 | 最终结果仍可看；节点实际值明确未记录；不重跑/重读/重算补历史 |
| 节点提前失败，没有 failed terminal | completed 卡未到达；能查看真实停止位置和部分成果；不造终点执行事件 |
| completed + 交付未确认 / 清理未确认 | 完成事实和输出保留；两个异常独立可读；不以模型修复清理、不关闭用户页面 |
| 步骤先完成、计划仍运行；逐项选历史调用 | 看步骤/项结果不冒充最终任务结果；开始输入、所有子行、终点结果同步到同一调用 |
| 不同动态合同：对象、集合、标量/文本、现场、真实文件及组合 | 无 issue/字段/网站硬编码；大结果不挤窄栏；文件可真实取用，现场保持原目标和约定状态 |
| 耗时 0、多轮、缺时间、等待 | 节点右侧口径明确；详情不重复；未记录不当 0；等待跨度不冒充 CPU 时间 |
| 点击/键盘/关闭详情/事件到来/主题 | 状态不只靠颜色；焦点、持续选中可区分；Handle 不截断；同版本运行不 regroup/remount/fitView |

结构测试只保护绑定、投影与缺失语义；真实浏览器现场交付、播放不中断、真实文件取用、批量完整覆盖必须各有正式路径证据。不能让一个 GitHub 单记录成功样本替这些场景签字。测试范围在实施阶段再按风险批准，不因这张矩阵自动跑全量测试或新建产品任务。
