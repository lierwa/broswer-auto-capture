# 工作台与任务生命周期减法基准

初稿：2026-09-22；交互修订：2026-09-24。  
状态：方向已确认，已部分实施；新建任务闭环未通过。正常路径、无链路失败恢复及自然语言调整的现行细则见 [能力对齐与恢复基准](PRODUCT_LOOP_CAPABILITY_AUDIT.md)，本文不代表代码已经完成。

## 结论

产品只保留两个主入口：**需求对话**和**链路画布**。

准备是生成草稿的后台过程，结果是某次执行的上下文信息。两者都不再拥有独立页面、独立导航和一套重复状态。生成前的计划或浏览器试做失败在准备阶段恢复，此时尚无可编辑链路；链路生成后的调整、保存和试跑作用于同一份工作草稿。只有用户明确点击发布，才形成不可变发布记录。

减法必须同时发生在 UI、协议、状态投影、服务端生命周期和持久化读取上。只隐藏页面、不删除对应逻辑，不算完成。

## 一、只保留四个产品事实

| 产品事实 | 职责 | 生命周期 |
| --- | --- | --- |
| Requirement | 用户确认要做什么 | 新的目标、来源、范围或结果理解才形成新需求记录 |
| TaskDraft | 当前正在生成、编辑和试跑的任务草稿，包含计划、链路和画布展示 | 每个任务最多一份活动草稿；保存时增加草稿 revision，不产生发布版本 |
| Release | 用户明确发布的固定任务 | 发布时冻结；旧发布记录只读保留 |
| Execution | 一次试跑或正式运行及其事件、结果、清理事实 | 每次独立保存，必须绑定准确的草稿 revision/digest 或 release |

`TaskPlan`、`TaskChain` 和 `ChainPresentation` 仍是编译与运行所需的内部结构，但不再作为三个并列、可由普通用户切换和管理的产品资产。它们归属于当前 `TaskDraft` 或某个 `Release`。

当前 `ChainRevisionDraft` 只拥有单条链，并强制依赖 `baseRelease/baseChain`，不能直接充当这个 `TaskDraft`。目标草稿是支持多步骤的任务级聚合，最小权威内容为：草稿 identity、task identity、revision/checksum、需求引用、可选的基线 Release 引用、一个包含 TaskPlan + 全部 TaskChain + 对应 ChainPresentation 的 content、当前有效试跑引用和更新时间。生成中/等待/可发布状态从当前 job 与试跑事实推导，不再复制一套产品状态字段。实现后迁移并删除“首次生成直接发布 + 发布后逐链修订”的双轨生命周期。

准备 job、修复 job、验证记录、能力描述和浏览器目标选择是内部支撑事实，不再扩张为主页面、用户版本或重复的“产品状态”。

## 二、唯一正常流程

```text
需求对话确认
    ↓
形成方案 → Browser-Use 代表试做 → 编成当前草稿
    ↓
用固定链路试跑，必要时换输入验证可复用
    ↓
用户点击发布
    ↓
固定发布内容 → 日常运行 → 画布显示同次执行状态与结果

异常分支：计划／试做／编译失败 → 在原阶段定点恢复；链路已有且结果不符 → 说明问题 → 查看建议并确认 → 更新草稿 → 重新试跑 → 用户手动发布
```

规则：

1. 首次生成和后续调整使用同一种 `TaskDraft`，不能先自动发布再创建“修订草稿”。
2. 准备阶段的有界技术纠正要保留候选与真实来源；链路形成后，系统提出的修改须由用户确认才写入草稿。验证通过也只使草稿可发布，不能调用发布。
3. 草稿保存只更新当前草稿；不得制造需要用户管理的计划版本、链路版本或发布版本。
4. 试跑绑定草稿 revision 和 digest。草稿变化后，旧试跑状态立即失效，不得染色新图。
   试跑开始时必须冻结一份 execution-owned candidate snapshot（或严格等价的不可变引用）；后续草稿修改不能改写该 execution 的输入图。它不是用户版本，但 execution 保留期间不能回收。
5. 发布是单独的显式命令。发布必须按 draft identity + revision/checksum 精确冻结该草稿中的计划、每个步骤的链路、每份 ChainPresentation 及已满足的验证证据；不能从仓库中临时挑 `latestChain`。
6. 正式运行只绑定一个 `Release`，不在运行时选择“最新计划”或临时切换链路。
7. 调整已发布内容时继续进入工作草稿；旧发布内容和历史执行不改写。
8. 目标、来源、范围或结果理解错误回需求对话；动作、输入绑定或路线错误在已有链路的草稿中调整。没有链路时先恢复计划、试做或编译，不提供节点编辑。正常验证通过不经过调整环节。

| “运行 1…运行 20”长下拉 | 删除；默认显示当前或最近执行，历史使用时间、状态和结果摘要的按需列表 |
| 永久展示的复跑节奏滑块 | 移入运行设置 |
| 完整连线表、节点 ID 编辑、原始 JSON 编辑 | 删除；普通用户选中步骤或结果说明问题，系统提出有依据的修改与前后差异，确认后才作用于唯一草稿；底层受控编辑能力保留 |
| “代表输入 / 独立复验 / 发布”等多组常驻按钮 | 普通调试只显示“试跑”；发布动作内部说明并完成必要检查 |
| 无参数任务的空输入框 | 删除；只有真实运行参数存在时才显示输入 |
| 画布前多层标题、说明、状态条和画布底部教程 | 删除或压成一条工具栏 |
| 重复通用异常出口 | 不生成业务分支；错误显示在发生的动作上，只有真实业务路线才画分叉 |
| 每次完成后的常驻满意度大卡 | 删除；保留轻量主动反馈入口 |

删除页面不等于删除业务结果和历史。结果、失败原因、人工等待、资源清理和用户验收仍须保存，只在需要时出现。

## 四、协议和状态投影必须同步瘦身

当前 `TaskChainState` 每次读取会携带完整的 `requirements[]`、`plans[]`、`chains[]`、`runs[]`、`executions[]`、`jobs[]`、`releases[]`、`revisionDrafts[]`、`presentations[]`、`staleIds`、`staleVersions`、`legacy` 和能力描述。画布轮询不应反复获取整个任务历史。

目标普通工作区只读取四类当前事实：

```text
当前确认需求
当前工作草稿（没有则为空）
当前发布记录（没有则为空）
当前或最近一次执行摘要（没有则为空）
```

约束：

- 不为每张 UI 卡新增状态字段、布尔开关或 `primaryAction` 枚举。
- 操作能否执行由当前四个事实和并发令牌推导；服务端仍在命令边界校验。
- 当前图数据按草稿优先、否则当前发布记录读取，不再把全部计划和链路发给前端后自行挑“最新版”。
- 执行事件继续按 execution 增量读取，不能混合多次运行。
- 历史发布、历史执行、技术审计和能力描述改为按需读取；打开历史或编辑器时才请求。
- 普通轮询不返回旧 requirements、旧 plans、旧 chains、旧 jobs、旧 runs、旧 presentations、legacy 摘要和全部 executions。
- `requestId`、草稿 revision/checksum、release 引用和 execution identity 属于并发与审计边界，必须保留；它们不默认展示给用户。
- 不增加网站名、动漫名、业务字段或任务类别的公共协议字段。
- `ready-to-publish` 由当前草稿存在有效候选和发布检查事实推导，不新增一套持久化产品状态。
- 删除独立 `TaskRunPreset` 生命周期、`saveAsDefault` 和运行中修改节奏命令。execution 已保存实际输入和 pacing；再次运行可显式沿用最近一次与当前 Release 匹配的输入，不再维护第二份“当前运行配置资产”。
- 发布不保存代表输入或 pacing；它们属于具体 Execution，不是 Release 内容。

最终协议以最少字段表达事实，不再同时返回“事实 + 派生产品状态 + 主操作 + 多套历史数组”。旧字段只允许作为迁移读取，所有调用方迁移后删除。

这里删除的是独立计划／链路技术版本管理和普通工作区的全量历史投影，**不是删除已发布版本管理**。顶部可读当前发布版本，历史发布按需读取；已发布内容和 execution-owned candidate 仍必须保留 plan/chain/release identity、version 和 digest，供运行、恢复、事件归属和历史审计使用；草稿自身只使用 revision/checksum 管理并发修改。

不能为了“文件少”把准备、验证、编译或执行器揉进一个巨型类。瘦身的判断是：一个产品事实只有一个所有者、一条写入路径和一个读取入口；不是机械合并文件。

`TaskExecution` 与 `TaskRun` 也不能粗暴合并：Execution 负责任务级步骤编排、最终结果、清理和用户反馈；TaskRun 负责单条链调用、节点事件、检查点与恢复。二者是必要的上下层事实，但不再同时整批发送给普通工作区。

`ChainPresentation` 的阶段、节点归属、布局、descriptor registry version 和 digest 必须保留，并随草稿/发布内容冻结；`readOnly/source` 等可从归属推导的兼容字段在调用方迁移后删除。

## 六、命令收敛

普通产品流最终只需要以下意图：

```text
生成/更新草稿
说明问题并请求修改建议
确认／拒绝建议；确认后保存至唯一草稿
保存草稿修改
试跑草稿
发布草稿
运行已发布任务
处理人工等待或清理
记录用户反馈
```

当前公开契约还包含 `generate_plan`、`author_task`、`generate_chain`、`generate_task_chains`、`validate_chain`、`validate_plan`、`authorize_plan` 等细粒度命令。实施时先用 CodeGraph 和调用测试逐一核验调用方；属于准备编排内部步骤的改为私有方法，属于历史兼容的迁移调用方后删除。`create_chain_revision + update_chain_revision` 收敛为首次编辑即可使用的草稿保存；独立 presentation 校验命令并入保存或试跑边界。不得一边保留整套旧命令，一边再增加一套“简化命令”。

`authorize_repair` 不再启动另一套修复 job/发布流程；它收敛为从准确版本和运行证据进入同一画布的建议交互。确认建议时复用草稿 revision/checksum 边界，拒绝、取消或过期不改草稿；尚无链路时归准备恢复。`set_execution_pacing`、preset 保存和第二套运行入口在调用方迁移后删除。恢复、取消、资源清理和用户结果反馈仍是独立业务意图，不能因页面合并而删除。

试跑和发布检查可以复用同一个 execution 机制及 mode，不再建设另一套验证运行系统。发布校验是发布命令的前置事实，不是独立页面或资产。

## 七、持久化保留与清理

必须永久或按现有审计策略保留：

- 用户确认的需求记录；
- 用户手动产生的发布记录及其冻结计划、链路和展示；
- 正式运行、试跑、结果、错误、人工等待、资源清理和用户反馈；
- execution 状态、节点事件、输出、失败证据、cleanup audit、artifact、requestId 幂等和 sequence 并发保护；
- 仍被草稿、发布或执行引用的证据。

不再作为长期产品资产保留：

- 每次草稿保存产生的独立 plan/chain 版本；
- 已被后续草稿 revision 覆盖且无 execution 引用的候选快照；被 execution 引用的不可变 candidate 必须随 execution 保留；
- 已完成 job 在普通工作区的完整投影；
- 重复派生的产品状态、主操作和 stale 列表；
- 独立 preset、默认值和运行节奏资产；实际输入和 pacing 只随 execution 保存；
- 无调用方的 legacy 命令、兼容适配和第二套运行入口。

删除存量数据前必须先提供迁移：旧 Release 和 Execution 仍能解析其引用；活跃草稿能恢复；不可识别记录进入只读兼容，不得静默丢失用户历史。

## 八、画布布局

```text
任务名称                                             任务级操作
需求对话 | 链路画布
草稿·基于 Vn／已发布 Vn    当前状态         试跑/运行  发布  更多
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│                        链 路 画 布                           │
│                                                             │
│      阶段  →  阶段  →  阶段  →  阶段                       │
│                                                             │
│ 缩放 / 适应视图                          按需打开上下文详情   │
└─────────────────────────────────────────────────────────────┘
```

- 画布填满窗口剩余空间，节点数量不能撑高页面。
- 工作区不依靠页面滚动寻找画布或后半段链路；长图使用平移、缩放和适应视图。
- 适应视图负责看全局关系，放大后阅读动作；不强求任意规模图同时显示全部文字。
- 右侧只有一个上下文区：调整说明与建议、当前结果、错误处理互斥显示；关闭后空间归还画布。
- 尚无链路时中央显示方案／Browser-Use 试做的真实进展，不画假节点；技术阻碍先有界排查，只在登录、业务选择或超出授权时请用户处理。
- 已有链路出错时右侧依次显示用户说明、系统候选修改的前后对照、确认与验证结果；不要求普通用户直接拖线写节点。
- 交互原型只决定状态和操作关系，不决定正式视觉。实现沿用工作台现有 Radix Theme（暗／亮、amber／sand）、集中语义 token 和组件变体；对话沿用 AI Connect，链路沿用现有 React Flow 节点与单一右侧上下文区，不复制原型配色、控件或另建主题体系。
- 详情内部允许滚动，画布所在主页面不产生纵向文档流。
- 任务列表可收起；小地图、缩放和布局只作为画布控件，不各占一行。

## 九、实施顺序

1. **事实源收敛**：冻结四对象模型，建立首次生成也使用 `TaskDraft`、准备/修复不自动发布、显式发布的服务端闭环。
2. **协议瘦身**：替换全量 `TaskChainState` 普通读取；拆出按需历史和诊断读取；迁移调用方。
3. **命令清退**：把细粒度生成命令收回准备编排内部，删除第二套公开流程及兼容分支。
4. **两页工作台**：删除 Plan/Results/ChainView，链路画布接入生成、当前结果和必要处理。
5. **全屏画布与按需调整**：固定容器、适应视图、单一上下文区，删除旧页面和 CSS；无图恢复、已有图的问题反馈／修改确认及版本入口使用同一工作台。
6. **存储清理**：在旧数据可迁移、旧发布/执行可读取之后，删除不再写入的表、列和孤儿快照。
7. **正式产品验收**：从新建需求、方案、Browser-Use 试做、链路生成、复跑验证、手动发布、正式运行，到无图失败恢复和已有图调整，全部经正式页面、API 与持久化验证；重启后事实保持一致。

每一步先删除旧调用，再删除旧字段和文件；不能只添加新适配层并把旧体系留在旁边。

## 十、完成证据

以下条件全部满足才能称为完成：

1. 主导航只有需求对话和链路画布。
2. 普通窗口打开链路即看到完整画布容器，工具栏在屏内，主页面没有画布纵向滚动。
3. `Plan.tsx`、`Results.tsx`、`ChainView.tsx` 及其专用逻辑和样式已删除，不是隐藏。
4. 首次生成直接得到活动草稿；准备和修复不会自动新增 Release。
5. 保存和试跑不新增发布记录；只有用户明确发布才新增 Release。
6. 普通工作区协议不再返回全部计划、链路、运行、job、发布和兼容历史。
7. 旧细粒度公开命令、重复运行入口和无调用兼容分支完成调用方迁移后已删除。
8. 当前执行的阶段、动作和结果来自同一个 execution；修改草稿后旧事件不再显示。
9. 旧发布和历史执行仍能按需读取，旧数据迁移后没有丢失。
10. 《凡人修仙传》任务在画布中只需看到四阶段，展开才看 11 个动作，普通流程不出现计划/链路/发布多套版本、内部 ID、digest 或空输入框。
11. 没有新增网站或任务特例，没有依靠修改 prompt 或盲目复跑掩盖系统问题。
12. 计划、Browser-Use 或编译失败时，保留已有候选和真实观察；画布没有假链路，也不把用户送去改节点。技术阻碍先由系统有界排查。
13. Browser-Use 完成只标代表试做通过；真正的草稿须编译成功并通过固定执行器验证。正常通过可手动发布，无必经修复流程。
14. 已有链路出错时，经正式页面完成说明问题、查看真实候选差异、接受／拒绝、独立试跑和手动发布新版；旧版本、原运行和历史不改写。
15. 正式页面的需求对话、无链路进展、草稿、发布运行和调整侧栏在暗／亮主题下与现有工作台组件、状态样式和画布布局一致；窄窗口可用，原型截图不充当验收证据。

本文是下一阶段唯一的减法基准。现有历史文档只作为已经发生过的证据，若与本文的工作台信息架构和手动发布方向冲突，以本文为准。
