# 功能状态与界面验收清单

日期：2026-09-06。性质：功能开发约束，不是已完成截图集，也不是负责人逐状态视觉签核。

布局承载遵循 [WORKBENCH_LAYOUT](WORKBENCH_LAYOUT.md)，业务语义遵循 [PRODUCT_FLOW](PRODUCT_FLOW.md)。下表是最低状态覆盖，具体功能遇到新的真实状态时补入，不把所有状态挤在一个页面同时显示。

## 1. 跨页面共同要求

- 顶部始终能辨认当前任务；左侧只保留一个最重要状态，主区解释当前需要用户处理的事项。
- Loading 表示正在读取已有事实，empty 表示确实没有产物，failed 表示读取/运行失败，三者不能混用。
- 业务状态由服务端事实投影；页签、节点选择、抽屉开关不改变业务阶段。任务状态不是用四个页签索引推出来的线性进度。
- 失败原因、关键风险及影响范围在主层；技术日志、原始字段、重复事件进详情或折叠。必须提供恢复动作，无法恢复时解释缺少什么。
- 历史产物可查，但必须标记版本与有效性；浏览历史不改变当前确认和执行授权。
- 所有请求与流绑定任务/轮次/版本，忽略迟到的过期响应；切走后返回仍能知道真实终态。
- 宽屏详情与主内容对照，窄屏转抽屉；验收键盘、Esc、焦点返回、输入可见和无横向溢出。

## 2. 状态、主层和动作

| 区域 | 状态或触发条件 | 主层必须可见 | 可用操作与保护 |
| --- | --- | --- | --- |
| 任务列表 | 首次加载 / 读取失败 / 无任务 | 加载、错误或新建入口分别显示 | 失败可重试；不得把读取失败当无任务新建替代 |
| 任务列表 | 多任务 / 另一个任务运行中 | 名称、选中态、实际正在处理的任务 | 搜索、查看和编辑未发送内容；不把结果转移到当前任务 |
| 任务列表 | 已归档 | 只读归档提示 | 恢复后继续，保留所有产物；活动执行不能直接归档 |
| 需求对话 | 新任务 / 正在恢复 | 空白对话入口或恢复提示 | 新建不调用模型；恢复期间避免重复发送 |
| 需求对话 | 生成中 | 用户原文、助手到达顺序、真实忙碌状态 | 停止本轮；输入保留；无成功草稿前不能确认 |
| 需求对话 | 待回答 | 当前问题、2–3 个同轴专业方向及必要解释 | 互斥方向单选、同轴可并存条件复选；同面板可自由补充，Composer 可补充/纠正/拒绝；历史问题只读 |
| 需求对话 | 草稿可确认 / 历史版本 | 当前文档卡、版本与确认状态 | 侧栏审阅全文；只确认最新有效版本；历史可查 |
| 需求对话 | 已确认后补充或纠正 | 新输入及旧确认失效 | 回到需求讨论；旧计划待复核，不静默覆盖活动运行版本 |
| 需求对话 | 失败 / 取消 / 连接或进程退出 | 保留已有消息，区分失败与用户取消 | 明确重试/恢复；不重复用户消息、不接收过期结果、不卡永久生成中 |
| 任务计划 | 尚无确认需求 / 待开始 | 缺少条件或已确认范围 | 返回对话或显式生成计划；查看页面不自动启动浏览器 |
| 任务计划 | assessing / source_evidence / drafting | 当前阶段、来源证据摘要、访问条件、任务步骤和业务限制 | 停止整次计划生成；阶段来自 PlanState，不由 UI 猜测 |
| 任务计划 | waiting_human / manual_required / cleanup_required | 真实 BrowserRecord waitpoint、人工提示和恢复条件 | 已有 Profile 可访问时不请求人工；实际阻断才在同 session/tab 请求；Done 后 fresh observe 验证；超时不自动重试；恢复同一 PlanRecord |
| 任务计划 | blocked / failed / interrupted | 证据或业务条件、影响和恢复条件 | 带证据回访谈、恢复或重新生成；不能擅自缩减范围 |
| 任务计划 | 生成失败 | 绑定的需求版本、实际状态 | 失败可重试，不能出现可启动的伪成功计划 |
| 任务计划 | 待确认 / 待复核 | 步骤依赖、输入输出、执行性核验项、业务数量、按需证据和版本 | 详情审阅并确认范围与授权；失效或未满足计划声明前置条件的计划不可启动 |
| 计划与运行 | 授权启动 / 排队 | 授权版本、队列状态、当前占用任务 | 防重复启动；单实际浏览器任务；确认需求不代替执行授权 |
| 任务链路 | E1 探索中 / 探索成功 / 等待人工 / 探索失败 | Pi AgentSession 的实际阶段、业务结果、BrowserRun、字段来源或具体失败层 | 登录或验证码处理后恢复；探索成功不显示为已有链路 |
| 任务链路 | E2 可编译 / 不可编译 | 输入参数、稳定目标、循环和每个输出字段的可重现来源 | 无来源、临时 ref、隐藏模型推断或不支持能力必须停止，不能碰候选 |
| 任务链路 | E3 样本执行中 / 成功 / 失败 | 编译图、代表输入的正式 TaskRun、输出、具体技术消费和模型审计 | 样本成功仍不能标记为 verified；失败回到对应编译证据 |
| 任务链路 | E4 换输入验证中 / 已验证 / 失败 | 不同输入、复用边界、差异结果和调用审计 | 只有已验证版本可冻结和批量授权；失败不重置已保存探索事实 |
| 任务链路 | drift_paused / 浏览器访问命令失败 | 已完成步骤、当前输入、剩余输入和明确暂停原因 | 同一来源不自动重试；页面恢复后从系统恢复，先 fresh observe 再继续 |
| 任务链路与运行 | 技术预算 / Provider 用量或账号错误 | 明确显示图迁移、浏览器命令、活动时间、显式 LLM，或账号/模型错误类别 | 业务数量单独显示；不得统一写“额度耗尽”或自动换供应商 |
| 运行结果 | 运行中 / 等待人工 / 中断 | 实际进度、已有结果与阻塞点 | 停止/人工处理/恢复；恢复同运行并核验浏览器状态 |
| 运行结果 | 完成 / 部分完成 / 失败 | 成果、真实覆盖、关键缺口与终止原因 | 查记录/来源/审计；部分成功不能被总失败遮蔽，也不能标为全量完成 |
| 运行与链路 | 复跑 / 结构漂移 / 用户修复 | 独立运行或受影响链路及保留进度 | 复跑新运行；漂移暂停；用户授权模型修复后产生新版本并验证 |

## 3. 当前覆盖与后续补验

当前接通多任务访谈、通用 Plan/TaskChain/TaskRun、固定版本授权、运行历史、artifact、技术消费与检查点恢复。上一版受控探索和完整候选生成已经否决；E1–E4 的 Pi 探索、字段来源、确定性编译和新状态投影已经实现，非采集任务已取得真实 E4 与正式复跑证据。京东详情的现场 E1–E4、两个换输入和 10 型号复跑仍未通过；旧 F6 抓取记录只作为历史只读证据，不定义当前状态机。实际完成、失败和未测范围只以 [PROGRESS](PROGRESS.md) 首节及[重构实施说明](TASK_CHAIN_AUTHORING_REDESIGN.md)为准。

每个功能 PR/本地检查点应记录本次覆盖的上表行、数据来源和截图/断言。至少验证：正常完成、一个实际失败回路、刷新或恢复、多任务归属，以及宽窄屏下主操作可达。涉及模型再覆盖取消与过期响应；涉及浏览器再覆盖访问受限、会话 finally 回收、版本授权与真实调用审计。
