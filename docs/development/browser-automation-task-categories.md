# 浏览器自动化任务类别

更新：2026-09-12。

本分类按用户最终要得到的结果划分浏览器自动化任务，用于访谈时选择领域知识和完成标准。用户只需描述目标，不需要先选择类别；混合目标可以组合多个类别，并分别满足各自的完成标准。类别是产品设计语言，不是 contracts 或 runtime 的枚举。

## 类别

| 类别 | 触发边界 | 示例 | 完成标准 | 当前通用链路状态 |
| --- | --- | --- | --- | --- |
| 信息检索与核实 | 最终结果是一个答案、判断或事实核实，而不是一批结构化记录。 | 核实某机构官网是否发布了指定公告，并给出结论与页面证据。 | 回答目标问题，保留来源、观察时间与适用范围；无法核实时明确证据缺口。 | 可形成同一 Markdown 需求、计划和参数化链路；真实浏览器闭环待验收。 |
| 数据采集与整理 | 最终结果是具有明确实体、字段和范围的结构化数据集合。 | 收集指定来源内的职位列表、字段与详情页关联。 | 交付数据集合及来源关联，说明枚举范围、终止依据、字段缺失和未覆盖部分。 | 一条预先明确步骤的公开页面字段提取已跑通运行管道；自然语言编译、批量、登录和复杂组合仍未验收。 |
| 内容访问与媒体控制 | 最终结果是页面或媒体达到指定可观察状态。 | 播放指定内容并移动到指定位置。 | 核实目标内容身份，并证明页面或媒体达到用户指定状态；无法访问时报告原因。 | 使用通用 browser/observe/human 节点；具体动作若超出浏览器能力合同必须阻断。 |
| 表单与事务办理 | 最终结果是表单、预约、申请或订单达到用户指定的提交前状态或被目标系统受理。 | 填写预约表单并在提交前停住，等待用户核对。 | 核对对象与内容；提交只有在独立授权后执行，并保留回执或明确失败状态。 | 使用通用链路、检查点和授权；外部副作用仍需任务版本明确允许。 |
| 站内内容与资源管理 | 最终结果是已有账号内对象的状态发生指定变化。 | 将站内已有收藏移动到指定收藏夹。 | 核对目标对象，并证明变更后的状态；写操作须经过与风险相称的明确授权。 | 使用通用链路、检查点和授权；登录或验证码转 typed human 等待。 |

## 分类规则

- 以最终结果判断类别，而不是以网站、页面控件或中间动作判断。网站、点击、搜索、下载、跨站和定时分别属于对象、动作或执行维度，不另行堆叠成互斥类别。
- 只有用户要求多个可独立验收的最终结果时才组合类别。例如“整理账单数据并提交报销申请”同时要求数据集合与事务受理结果。“播放最新一集”仍以媒体控制为主，核实内容身份是达到该结果的内部步骤。
- 分类只帮助系统选择访谈知识和完成标准，不进入公共 IR。平台只认识通用链路、节点、值绑定、预算、检查点、事件和终止结果。
- 组合任务分别保留各目标的完成证据，不能用一个步骤成功替代整体完成。

## 当前交付边界

所有类别都通过同一个 `interview-markdown` 协议形成可审阅、保存和确认的完整 Markdown。确认后生成版本化 `TaskRequirement`；规划器再形成动态步骤合同，来源发现或现场核实只是任务需要时的一般步骤，不是固定平台阶段。

每个步骤必须先由用户给出代表输入并单独启动受控探索，模型依据真实观察编译候选链路。候选链路经过样本运行和不同输入验证后才能标为 verified；全部步骤 verified 后，用户再冻结计划、总预算和执行授权。普通复跑只有显式 `llm` 节点可以调用模型。

当前代码已完成这些通用合同、运行器、BrowserSkill adapter、持久化、Workbench 投影和离线聚焦验证，并取得一条受控公开页面链路的代表输入、不同输入和普通复跑现场证据。由于其需求预先给出了字段和高层步骤，它不能证明自然语言编译质量；第二类真实浏览器任务及登录/人工返回也没有证据。
