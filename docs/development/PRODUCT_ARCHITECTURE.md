# 产品运行架构方向

日期：2026-09-11；2026-09-13 更新当前浏览器与 authoring 事实
状态：产品形态与职责方向已确认；迁移细节和真实执行闭环仍待验证。

本文记录浏览器自动化工作台的目标产品形态，作为后续方案、拆分与验收的产品依据。当前代码和已验证能力以
[开发进度](PROGRESS.md) 与 [调研登记](RESEARCH.md) 为准；本文描述目标职责，不把目标写成已经实现。

自然语言任务如何形成通用、参数化、可组合、可复跑的任务链路，由[自然语言浏览器任务链路架构基准](TASK_CHAIN_ARCHITECTURE.md)统一定义；首次探索和轨迹编译见[重构实施说明](TASK_CHAIN_AUTHORING_REDESIGN.md)。本文件只定义扩展、Web 与服务端的部署及事实归属，不重复定义链路协议。

## 三部分产品形态

### 浏览器扩展：主前端与本机执行主体

扩展是用户完成主要任务的入口，负责：

- 需求对话、Question 交互、连续 Timeline 与需求草稿审阅；
- 模型账号与模型选择界面；
- 需求版本确认、计划生成进度、计划审阅与独立执行确认；
- 在用户自己的浏览器中执行获授权的浏览器动作；
- 展示运行进度、暂停与恢复入口、部分结果、完成结果及可见审计。

目标安装体验是用户只安装本产品扩展，不再另行安装 `bsk` CLI 或 BrowserSkill daemon。BrowserSkill 中仍有价值的
浏览器控制、定位、观察和通信能力，应由扩展与服务端按最终协议承接；不能因为沿用其源码或协议而保留第二套用户安装步骤。

### Web：辅助管理界面

Web 用于更适合大屏或集中处理的辅助管理，例如任务总览、历史结果和运营管理。Web 不拥有任务主流程，也不是扩展执行
浏览器动作的前置条件。扩展界面（popup 或 side panel）关闭或 Web 未打开时，任务状态仍由持久事实和服务端生命周期决定，
不能依赖某个 React 页面存活；扩展不可用或浏览器关闭时，本机浏览器动作必须暂停，恢复前重新核验权限和浏览器状态。

### Node 服务端：AI Session 与持久事实

Node 服务端继续承担不适合放入扩展的受信能力：

- AI Connect 账号连接、凭据 locator、Key/OAuth 生命周期、模型目录与能力校验；
- Pi AgentSession、结构化模型调用、调用审计和中断恢复；
- 用户、任务、需求版本、计划、授权、运行及结果的服务端持久化与并发控制；
- 扩展与 Web 共享的安全 API、事件流及客户端连接边界。

浏览器动作发生在用户电脑；模型与数据库服务可以在服务端运行。两者通过带用户、任务、版本、授权和幂等标识的协议连接，
不能让服务端模型调用绕过扩展中的浏览器权限，也不能让扩展自行推导服务端权威状态。

## AI Connect 与模型使用形态

模型设置、账号目录、认证进度和调用 Timeline 继续复用 `@agent-platform/ai-connect` 与
`@agent-platform/ai-connect-react`。Provider 认证、API Key、OAuth/token refresh 和 wire 兼容由 AI Connect 与锁定的 Pi
实现负责；本产品只提供宿主组合、业务选择和安全投影，不重新发明认证系统或复制 Timeline 状态机。

用户自带模型账号是已确认形态：用户可以连接受支持的订阅账号、套餐 Key 或 API Key，并为任务选择准确模型。商业类型
`subscription | api` 与技术认证方式 `oauth | api-key` 分开处理，不能把订阅一概解释为不可调用 API。

“产品提供模型”是讨论中的可能形态，尚未冻结为正式产品模式。后续若采用，需要另行确认账号归属、额度、计费、租户隔离和
可用模型；在确认前不得据此改变用户自带账号的现有边界。

## 单一事实源与授权边界

- 扩展拥有当前交互和本机浏览器权限的用户界面，不另建一套需求、计划或运行状态机。
- 服务端数据库拥有持久任务、版本、授权和运行事实；扩展与 Web 只读取、提交命令和投影。
- AI Connect 拥有账号连接、凭据生命周期、模型目录和公共 AI 事件；Pi AgentSession 拥有模型会话执行。
- 需求确认、计划确认和浏览器执行授权是三个独立动作；能够查看计划不等于已经获准或能够执行。
- 凭据、Cookie、Profile、验证码内容和原始敏感页面不得进入普通投影、日志或 Git。

## 当前实现与目标差距

当前产品仍以本地 Fastify + React Workbench + SQLite 运行，并通过 `bsk` 进程接入浏览器。需求草稿、通用 task-chain IR、
LangGraph runtime、版本/运行持久化和通用 Workbench 投影已经存在；上一版由 API 手写模型命令循环并让模型直接生成完整
Chain IR 的 authoring 路径已经否决，新的 Pi AgentSession 探索与真实轨迹编译尚未实现。

2026-09-13 的只读现场检查证明本机 `bsk` 和扩展能够连接，指定京东 Profile 当时显示已登录，检查会话随后关闭。这只证明
当前环境和登录态在该时刻可用，不证明产品链路闭环；登录会过期，真实运行前仍须以同一 Profile 复查。旧的“本机缺少
`bsk`”是 2026-09-11 的历史阻塞，不再是当前事实。

后续迁移至少需要真实验证：

1. 扩展直接承接 BrowserSkill 能力后，无独立 CLI/daemon 安装仍能操作用户浏览器并保持明确权限提示；
2. 扩展、Web 与 Node 服务在用户、任务、版本、幂等请求和断线恢复上的协议；
3. 每用户 credential、AgentSession、数据库和服务端 profile 的隔离，以及各 provider OAuth 的部署回调；
4. 扩展关闭、MV3 后台回收、浏览器重启和服务端重启后的暂停、恢复及审计；
5. 从需求确认、计划生成与确认到真实抓取、结果保存和刷新重开的完整正式入口验收。

## 不再作为后续决策依据的前提

以下前提已经撤回，后续方案和验收不得继续引用：

- “扩展作为主体”等同于产品不再需要服务端；
- 必须把现有 Node、SQLite、AI Session 和全部模型逻辑搬进扩展；
- 因为扩展展示模型设置或 Timeline，就能把当前 Node/Pi 模型执行入口原样打包进扩展；
- 必须新建一套模型网关或认证系统；
- 计划 proposal 已可查看即可证明真实浏览器执行闭环完成。

需求、计划、执行和恢复的产品顺序继续由 [产品流程](PRODUCT_FLOW.md) 定义；目标迁移阶段与真实验收门由
[开发路线](ROADMAP.md) 管理。
