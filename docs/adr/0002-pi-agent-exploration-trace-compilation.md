# 使用 Pi AgentSession 探索，并从真实轨迹编译任务链路

## Context

B-A-T 已有一套通用 `TaskChain` IR、LangGraph 执行器、BrowserSkill 适配器、版本与运行持久化。上一版首次探索却由 API 宿主实现了一套固定轮数的“模型输出一个命令，宿主执行，再把观察发回模型”的循环；探索结束后，又要求一次结构化模型调用直接生成近乎完整的 `TaskChain`。这条路径重复实现了成熟 AgentSession 的工具循环，也让模型同时猜测浏览器路径、节点图、连线、预算和错误出口。

真实运行证明，这种方式会把简单页面任务变成反复修 prompt、堆预算和碰候选的过程。模型偶然完成页面动作，也不能证明生成的链路可复跑，因为临时元素引用、输入参数、循环边界和结果字段来源可能仍然无法重现。

B-A-T 的产品模型入口已经确定为 AI Connect 选择的账号和模型，由 Pi AgentSession 执行。Codex、当前开发会话和 Codex 的额度都不是产品运行依赖。

## Decision

首次代表路径探索由现有 AI Connect → Pi AgentSession 入口负责。Pi AgentSession 在一个受控会话内使用 BrowserSkill 工具，直到获得用户要求的真实业务结果、遇到类型化人工等待或以明确错误结束。API 宿主不再维护第二套手写 Agent 循环。

B-A-T 在工具边界记录类型化探索轨迹：每次工具调用、参数、结果、动作后观察、浏览器状态摘要、业务输出及字段来源。只持久化任务授权范围内的结果和必要证据；Cookie、密码、令牌、验证码和完整敏感页面内容不得进入数据库普通日志、Git 或测试快照。

探索轨迹不是可执行链路，也不成为第二套公共 DSL。模型只补充编译无法单凭轨迹确定的少量语义：

- 哪些样本常量绑定为运行输入；
- 哪段轨迹构成循环，以及集合、继续条件和上限；
- 每个输出字段来自哪条观察或工具结果；
- 完成条件、复用假设和失效条件；
- 哪项结果确实需要语义推理，因此必须成为显式 `llm` 节点。

宿主编译器校验这些注解引用的真实轨迹，再确定性地产生一份现有 `TaskChain` IR：稳定节点标识、值绑定、节点输出合同、成功与错误出口、边、检查点、终止节点和技术预算都由编译器生成。随后继续使用现有 `compileTaskChain`、LangGraph `StateGraph` 和 `TaskChainRuntime`；不得引入第二套运行器或模型生成的可执行旁路。

只有具备可重现来源的输出才能进入可冻结链路。页面观察或工具结果必须带可验证的提取依据；只能由模型推断的字段必须编译为显式 `llm` 节点并进入复跑审计，否则该候选标记为不可冻结，不能宣称零模型复跑。

页面内结构化读取属于通用浏览器能力。实现前先核验 BrowserSkill 已有的 page、target、HTML 或语义快照能力，并复用成熟解析组件。平台源码不得写入京东、商品、评论等固定类型，不得允许模型注入任意页面脚本；选择器、字段映射和数量只保存在任务版本数据中。

用户提供的是业务限制，例如商品数、评论数和允许操作范围。`maxTransitions`、`maxBrowserCommands`、`maxActiveMs`、`maxLlmCalls`、`maxInvocations` 与 `maxDepth` 由编译器根据图、循环上限、节点超时、子链和显式 LLM 节点计算。运行时继续记录实际消耗；错误必须指出具体技术预算，不能统一显示为“额度耗尽”。账号或供应商用量另归 AI Connect/Provider 错误，不与链路预算混称。

登录态继续归浏览器 Profile。B-A-T 只保存非秘密的 Profile 选择或状态摘要。运行前用将要执行任务的同一 Profile 做只读核验；失效时进入类型化人工等待，用户登录后在同一运行中重新观察和恢复。BrowserSkill 控制会话必须在 `finally` 中关闭，关闭控制会话不清除 Profile 登录态。

## Verification states

1. **探索成功**：Pi AgentSession 在真实浏览器中返回了这次代表输入要求的业务结果。
2. **可编译**：所有动态输入、稳定目标、循环和输出字段都有可重现依据，且没有未声明的模型推断。
3. **候选可执行**：编译后的链路能在代表输入上由正式运行器完成。
4. **链路已验证**：同一候选在至少一个不同输入上完成，输入绑定生效，运行期模型调用与声明一致。

只有第 4 级允许冻结为可批量复跑的 `ChainVersion`。任一级失败都保留对应证据和层级原因，不通过重复生成掩盖失败。

## Consequences

- 保留 AI Connect、Pi AgentSession、BrowserSkill、通用 `TaskChain`、LangGraph、SQLite/Drizzle、Zod、React Flow 和 Workbench；它们各自继续承担已有职责。
- 删除固定轮数的手写探索决策循环和让模型直接生成完整 IR 的候选/修复路径，但只在替代路径通过对应聚焦验证后删除。
- 首次探索允许模型调用；冻结后的普通节点复跑不调用模型，只有显式 `llm` 节点可以调用模型并产生审计。
- 一个品牌的十个型号由一条发现链路产生输入集合，再把同一条详情链路逐项调用十次；不得生成十份同构链路，也不得逐项重新探索。
- 如果用户已提供 URL，它是运行输入；如果只给品牌或型号，计划增加通用发现步骤来产生 URL。平台不要求用户预先找 URL。

## Rejected alternatives

- API 宿主手写模型/工具循环：重复 Pi AgentSession 能力，且会产生另一套生命周期和错误处理。
- 让模型直接输出完整 `TaskChain`：把确定性结构、预算和错误出口交给概率生成，失败后只能继续碰候选。
- 把 BrowserSkill 当成批量复跑系统：它只提供浏览器能力，不能拥有任务版本、编排、恢复和审计。
- 为京东或数据采集增加平台 special case：样例知识应进入版本化任务数据，不能污染公共 contracts/runtime。
- 删除成熟库后自行重写相同能力：除非产品明确移除该能力，否则必须继续复用成熟组件或选择另一成熟组件。
