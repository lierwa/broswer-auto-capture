# 需求对话直接产出准备计划草案

## 决定

需求对话只有一份供用户审阅和确认的产物，名称为**准备计划草案**。访谈 Skill 根据完整对话决定何时使用只读联网工具、调查什么、哪些影响结果的选择需要用户确认；搜索证据、用户决定、任务目标和代表试做要求写入同一草案。用户确认该版本后，B-U 直接收到这份草案作为业务指令，再开始真实浏览器试做。确认草案不等于授权启动浏览器，启动仍由工作台的独立操作控制。

不再在确认之后调用另一轮模型生成独立的业务 TaskPlan。若编排、预算、输入输出合同或现有执行器需要内部格式，宿主只能从**同一已确认草案版本**做受校验的技术投影；投影不得新增业务步骤、来源、起始 URL、内容链接、完成标准或授权范围，也不得成为第二份业务权威。编译后的 `TaskDraft` 是后续的**链路草稿**，与访谈中的准备计划草案不是同一产物。

```text
需求对话：Skill 按需联网调查、澄清、修订并确认唯一准备计划草案
  → 用户从工作台启动 B-U 代表试做
  → 按同一草案版本保存真实动作和观察
  → 编译链路草稿 TaskDraft
  → 样本试跑与独立复验
  → 用户手动发布 Release
  → 独立正式复跑
  → 用户验收实际结果
```

## 草案与来源边界

草案用用户可读语言说明目标、来源身份与依据、可用的试做入口、动态选择规则、范围与排除项、必要步骤依赖、完成标准、输入、停止点及仍需 B-U 在现场核查的事实。网站名称、别名或模型记忆中的域名只是线索；当起始入口缺少可追溯依据时，Skill 应结合上下文决定是否搜索和如何核实，宿主记录并校验真实结果引用。有多个合理来源或内容对象时，通过对话或 Question Panel 由用户决定；搜索不可用或没有可靠候选时保留待决，不猜网址。

搜索不是每轮或每个网站名称都强制执行的固定仪式。用户已给出可用 URL 或材料时可直接作为用户提供的来源事实，仍需处理会改变结果的身份歧义。只读搜索能支持来源身份和入口选择，不能证明页面控件、登录状态、剧集排序或播放效果；这些现场事实交给 B-U 观察。动态目标不冻结为调查当时的某个内容页。

示意结构如下，尖括号内容须来自本轮真实证据或用户决定：

```text
准备计划草案 vN
目标：在已确认来源寻找运行时最新可播放的《凡人修仙传》常规正片并确认正在播放。
来源：<已确认的站点或内容来源及决定依据>
试做入口：<已核实或由用户提供的起始 URL；记录来源引用>
选择规则：运行时识别官方内容，排除预告、花絮、特别内容及非官方上传。
B-U 试做：从该入口调查真实页面，确定最新正片、打开播放并观察状态。
停止点：登录、验证码、权限或新业务取舍由用户处理。
现场未知：页面结构、剧集顺序和播放器状态的具体观察方法。
```

B-U 可在已确认的来源范围内自行调查页面路径、标签页、选择器和动态内容链接。若现场发现新的来源、范围、目标或完成含义歧义，暂停试做并回到对话修订草案；技术路径问题留在 B-U 或编译层定点处理。已发布 Release 和历史运行保持不可变，不为旧任务结构加入网站特例。

## 当前实现与验收边界

2026-09-25 已调整访谈 Skill 与确认门：用户确认唯一准备计划草案及入口来源，内部 `TaskRequirement`/`TaskPlan` 从同一确认版本确定性投影，`browserUseTask` 核对版本、摘要与入口后交给 B-U；确认后不再调用模型另写业务计划。本轮正式工作台新任务验证了来源引用、入口、投影、B-U 来源及后续发布版本的交接。当前投影的结构化字段范围有限；多步组合、B-U 现场发现新业务歧义后的对话回流，尚无本轮正式产品证据。

迁移验收须证明：同一草案版本、来源引用与起始入口在用户确认、内部投影、B-U 指令和编译来源之间一致；无证据的深层 URL 被确认门拒绝；模型不会在确认后另作业务规划；B-U 的新业务歧义回到对话；新建任务从正式工作台完成同次试做、编译、验证、发布和独立复跑。本轮只有部分技术路径走通：同任务四个准备 job 中一个在浏览器启动前失败，另两个 B-U 浏览器试做失败，最后一个成功；发布后只做了一次正式运行，未做第二次独立正式运行或服务重启复核。已确认的凡人任务只要求动态选择最新可播放常规正片并观察到播放；B-U 来源曾在目标集观察到 `playing`，正式复跑却没有保存实际集数或播放状态，不能据技术 `completed` 断言该业务结果。结束后持续观看不属于该草案完成条件，应另行报告为未测的体验事实。故不能称迁移或产品闭环验收通过。逐项证据见 [PROGRESS](../development/PROGRESS.md)。
