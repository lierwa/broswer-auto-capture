# 先划分可复用步骤，再做代表探索，并用修复—验证闭环冻结链路

## Context

旧主流程让 Pi AgentSession 先完成整项任务，再从完整工具记录派生计划和图。集合任务因此让模型逐项重新找路，工具事件越多，节点和模型节点越多；94 个节点和 14 个模型节点的产物只能回放当次执行，无法稳定换输入。

连续的探索、样本验证和换输入验证还会叠加同一来源的访问压力。只在收到 `rate_limited` 后熔断当前进程，无法保护下一次运行或服务重启后的来源。

## Decision

产品主流程先根据已确认需求生成版本化 TaskPlan。计划只划分可独立复用的业务步骤和数据依赖，不生成节点图。一个步骤发现集合后，互不影响的项目用 `each` 逐项调用同一条链；需要跨项累计、去重或按真实结果停止时用 `batch`，整份集合只调用一条带显式 `loop` 的链。

Pi 在一个 BrowserSkill 会话中依次探索每个步骤的一条代表路径。发现步骤只取得可见目标集合，不为下游字段逐项进入详情；`each` 和 `batch` 都只探索第一个代表输入。结构化模型只补充紧凑编译注解；宿主确定性生成候选 TaskChain。公共图只包含 `capability`、`llm`、`branch`、`loop`、`invoke`、`terminal`，同构集合项和翻页不会复制图。

本地定位、绑定、循环、来源、完成条件或预算错误进入最多一轮修复—验证。修复复用原代表轨迹，保存新的不可变链路版本并再次复跑，不重新探索。认证、验证码、频控、访问拒绝和不确定网络状态直接暂停，不消耗修复次数。

探索、验证、修复验证和正式复跑共用持久 origin 访问门。公共代码只实现 origin、最小间隔、窗口预算、单并发和冷却；站点参数属于策略数据。

模型正常结束但漏交结果时，宿主先在同一 Pi session 中给出精确缺口并继续。再次失败后，按 AI Connect 目录中可验证的推理档位和容量升级模型，同时复用浏览器现场与已有轨迹。

## Consequences

- TaskPlan 先于浏览器代表探索，用来限定可复用边界；它不猜选择器、页面控件或节点图。
- 一次任务 authoring 只占用一个 BrowserSkill 会话，每个 `each` 或 `batch` 步骤只探索一个代表输入。
- 每条候选链路必须至少完成一次自动样本复跑；失败不能直接结束 authoring。
- 修复版本保留父失败运行和原始轨迹，旧链路与运行历史不改写。
- 搜索发现与逐项详情处理等数据依赖明确的流程拆成组合链路；单一路径任务仍只生成一步。
- 历史端到端轨迹和旧节点模型只读保留，不能直接升级成已验证稳定链。
